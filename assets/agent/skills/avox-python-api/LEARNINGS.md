# avox-python-api 经验日志 (LEARNINGS)

> SKILL.md = 权威 API 参考（仅 API 变化时改）；本文件 = **追加式经验日志**。新经验先落这里，稳定后蒸馏回 SKILL.md。

## 何时记（不是每次跑都记）

仅三种情况：
- **踩坑并解决**：报错/异常 → 绕过或修复，且 SKILL.md 没写过。
- **非显然写法**：SKILL.md 没写但高频有用。
- **新组合闭环**：多步编排出的新模式（截图→识别→动作→重试 等）。

成功跑通的普通脚本**不记**，避免流水账。

## 条目格式

每条一个 `### ` 标题块。**必填**只有「现象 + 解法」两行，其余可省。空模板：

```
### <日期，可省> 一句话标题
- 现象：<报了什么错 / 想做什么做不到>
- 解法：<怎么解决的；多行代码紧接下方用 4 空格缩进块>
- 类型：踩坑 / 写法 / 闭环（可省）
- 来源：<脚本名或场景，可省>
```

样例（**仅示意形状，非真实经验**，照这个形状写）：

```
### 2026-07-23 OCR 在半透明图标上漏字
- 现象：模板匹配找得到图标，但 recognize 该处文字返回空。
- 解法：先按匹配框 crop 出 ROI 再喂 OCR，识别率明显提高。
    roi = buf.crop(r.x, r.y, r.w, r.h)
    rec.recognize(roi)
- 类型：闭环
```

## 维护规则

- 一事一条，正文 1–3 行（代码块另算）。**保留所有已有条目，绝不删除/覆盖**（蒸馏除外）。
- 新条目插在「条目」小节最上方、紧贴下方注释的下面 → 最新在前。
- 软上限 150 / 硬上限 200 行：到 150 做一次蒸馏——稳定条目合并进 SKILL.md 对应小节，从本文件删已吸收的；矛盾以新为准删旧。
