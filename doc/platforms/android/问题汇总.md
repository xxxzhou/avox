# 问题汇总

## 当类中有成员std::function时，编译会报std::__ndk1::__throw_bad_function_call()

搞了很久，是因为-D_LIBCPP_DISABLE_AVAILABILITY -D_LIBCPP_ABI_UNSTABLE这二个编译选项，不要乱加AI给的东东，花了太久时间了。

## 调试一直起不来，报什么端口没启动

- 很可能是初始化时，有机率导致的crash,可以查找JNI_OnLoad相关代码以及窗口初始化调用的native方法。
- 可以尝试关闭手机上的后台应用再试。
- 也可尝试添加如下权限。
``` xml
    <uses-permission android:name="android.permission.SET_DEBUG_APP"/>
    <uses-permission android:name="android.permission.INTERACT_ACROSS_USERS"/>
```

## 安卓手机测试MediaCodec

1. 手机可能不支持B帧，所以直接用ffmpeg推文件流，手机端播放会有花屏现象。
2. 用ffmpeg推流，手机用zlmediakit拉流，相应的PTS时间可能间隔会扩大很多，导致解码不正常。
3. 用OBS推流，手机用ffmpeg拉流，PTS时间还是不正常。主要类似onReleaseOutputBuffer: Render time interval reaches 109ms before pts: 40282000 这种。相比1，2会正常些。
4. 如果Frame队列超过10，可能还是会花屏。
4. 经测试，用OBS推流，zlmediakit拉流，frame队列不超过10，手机端播放正常。

## 奇怪的问题

1. 当二个同PTS帧，一个SEI帧，一个正常帧，正常安卓手机都是二个0，而这个华为手机解出来的是0/-1，注意-1可能造成的问题。
