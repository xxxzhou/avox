### 关键发现 (与 aoce 历史完全互相印证)

1. **弧形(非平面)标定物上 `cv::calibrateCamera` 必然发散** (python/python5.0/C++4.13 三方复现, rms≈169px, fx 飞到 1.5 万+) —— 这正是 aoce 写 `aoce_g2o` 内参 BA 的原因 ("非平面标定场景用 g2o 重写")。**M2 (g2o HandEyeOptimizer/CalibrationOptimizer) 是弧形幕墙可用化的前置**。
2. M1 期弧形幕替代路径: 近似物理焦距 (无畸变) 直接走 PnP+手眼, 多数帧 4-18px; 个别帧 PnP 发散需要 M2 的鲁棒图优化吸收。
3. 棋盘格合成测试的教训: 平面+无噪声是 PnP 二义性病态数据 (4.13 可能收敛到重投影同样好的错误位姿), 测试标定物已加 1.5cm 级微非平面扰动; 3D 点 x/y/z 必须与渲染完全同帧。
4. LED 处理器会把标定图拉伸铺屏 → 格子宽高比可能 ≠1, calibrectest 已留 aspect 参数 (ds1 实测 1.0 即正确)。
5. aoce 原版几处缺陷移植时已修: 棋盘格帧 blur/visibility 恒 0 被默认阈值过滤; `calibMat2Mat4x4` 输出 Mat 未定尺寸的崩溃隐患 (防御性 create)。
6. FBX 侧: ufbx 解析 Mesh1-8.FBX 得 10x12 格/块, 围绕半径 9.56m 圆周 (与 LedCircle 文档参数吻合), markerId=块*120+列+行*10 与现场图 id 分布 (块3=360-479, 块4=480-599) 完全一致。

## 一、aoce 虚拟制片标定技术流程整理

### 1.1 解决什么问题

虚拟制片 (VP/XR) 中,绑定在真实摄像机上的光学追踪器 (Redspy/HTC Vive Tracker) 输出追踪器位姿。**标定**就是把"追踪器位姿"换算成"虚拟空间 (UE4/LED 幕墙坐标系) 下虚拟摄像机的位姿",使得 LED 幕墙上的虚拟画面与真实摄影机拍摄画面透视完全重合。标定输出两个 4x4 矩阵 + 一个尺度:

```
CameraTrack {
    camera2track  — 摄像机相对追踪器的偏移 (手眼矩阵 X)
    base2target   — 幕墙坐标系到追踪器坐标系的变换
    scale         — 追踪器位移缩放 (Redspy 位移与真实尺寸存在未知比例)
}
```

运行时换算链: `摄像机在幕墙系位姿 = base2target(逆) × trackPose × camera2track`,LED 屏上不需要再放标定板即可实时得到虚拟相机位姿。

### 1.3 核心标定算法流程 (五步)

前提: 摄像机与追踪器刚性绑定 (钢体),在 N (≥4, 建议 8) 个不同位置/方向同时拍标定图案 + 记录追踪器位姿,得到 N 组 (画面, trackPose)。

```
① 采集       每帧: 角点图案画面 + 追踪器位姿 (trackPose) + 时间码
              标定物两代: 棋盘格 (张正友) → Aruco LED 幕墙 (推荐,见 1.5)
                  ↓
② 内参标定    N 组角点 2D-3D → cv::calibrateCamera
              → LensModel { imageSize, focalLength(归一化 fx/w, fy/h),
                            focalCenter(0.5,0.5), K1,K2,P1,P2,K3 }
                  ↓
③ 每帧 PNP    内参 + 角点 2D-3D → cv::solvePnP → 每帧 target2camera
              (标定板在摄像机坐标系下的位姿)
              高精度路径: eigen::getCameraPoseDLT 初值 → g2o 单帧图优化精化
                  ↓
④ 手眼标定    AX = XB 问题 (眼在手上):
              cv::calibrateHandEye (Tsai 二步法: 先旋转后位移)
              改进①: 位移方程加 scale 列 → (Rgij-I | -Rcg*Tcij)·[Tcg,S]ᵀ = -Tgij
                     一次 SVD 同时解出平移 + 追踪器位移缩放 (Redspy 必需)
              改进②: SVD 求 base2target:
                     A(摄像机在幕墙系,4N×4) × X(幕墙→追踪器系) = B(摄像机→追踪器系,4N×4)
                     X 为 N 组关系的最小二乘最优解
              输出: CameraTrack { camera2track, base2target, scale }
                  ↓
⑤ 验证与选优  PNP 位姿当真值 → projectPoints 把 3D 角点投回画面
              与实际角点亚像素 UV 比较像素误差 (误差直接体现在屏幕像素上,直观)
              排列组合已有数据,选重投影误差最小的组合 (对每帧数据都不全信)
```

### 1.4 g2o 图优化精度增强 (对标 OpenCV 的高精度替代)

统一约定: 观测 UV 归一化到 0-1 (比像素值收敛更细);**每条边必须 setInformation,否则不收敛**;坐标链 `camera2target = base2target × track2base × scale × camera2track`。

| 优化器 | 顶点 | 边 | 作用 |
|---|---|---|---|
| `CameraPoseOptimizer` | 1 个 VertexSE3Expmap (帧位姿) | 每角点 EdgeSE3ProjectXYZOnlyPose (Huber) | 单帧图优化 PnP,DLT 初值 200+ 像素误差可降到 20+ |
| `CalibrationOptimizer` (在 MeshBuildOptimizer.cpp) | 内参 4 维 + 畸变 5 维 + 每帧 VertexSE3 | BaseMultiEdge<2> 联合 3 顶点 | 重写 calibrateCamera 第三步全局 BA,与 OpenCV 结果差 ~1 像素 |
| `HandEyeOptimizer` (当前主力) | camera2track + base2target + 每帧 target2camera + scale (可固定) | HandEyeEdge (6 维位姿观测, 平移块×0.01) + 每角点 ProjectionHandEdge (2 维 UV) | 参考 st_handeye_graph: 把每帧 target2camera 也作为优化变量吸收追踪器位姿噪声;**对初值不敏感**;scale 顶点天然解决位移缩放 |
| `ZoomLensOptimizer`/`ZoomScaleOptimizer` | fx/k1/k2 三条二次曲线 CurveVertex (ax²+bx+c) + 每帧 scale (固定) | 每角点一条 4 顶点多边 | 变焦镜头标定: 多 zoom 档位联合拟合 fx(zoom)/K1(zoom)/K2(zoom) 曲线,运行时按 zoom 环值生成 LensModel (FIZ 跟焦) |

结论数据 (现场实测): Aruco 标定 + 图优化,在 Redspy 追踪准确时全幕墙误差 ≤5 像素 (可用 XR);两组现场数据 g2o 再优化误差全面小于 OpenCV 手眼结果。

### 1.5 Aruco LED 幕墙标定 (替代实体标定板)

- 动机: 棋盘格只对"拍摄的那一块屏"最优,换一块屏误差就变差;LED 幕墙往往非平面 (弧形/拐角),需非平面 3D 点 + 给定初值内参 (中心 0.5,0.5,fx 按传感器宽高比即可)。
- 原理: 每块 LED 屏按模型放置特定 markerId 的 Aruco,识别 markerId → 查 LED 模型得到该屏在 UE4 中的三维顶点 → 每帧任意位置拍摄都得到 2D UV + 3D 顶点对,反推标定板位姿供手眼求解。**一次标定同时得到 LED 面板/追踪器/摄像机三者关系,且误差直接是屏幕像素误差**。
- 关键契约: `arucoId = (markerId - startArucoId) × 4 + cornerIndex`,是识别结果与 LED 模型顶点对齐的唯一键。
- 幕墙 Mesh 生成: LED 幕墙无法一次拍全时,用 `aoce_slam/led` (Aruco 索引匹配 + 两视图重建 + 逐帧扩展 + 全局 BA) 从有限几张照片重建任意形状幕墙的三维角点 Mesh;路标被观测 ≥3 次保精度。

### 1.7 工程经验与精度坑 (最有价值的部分)

1. **Redspy 欧拉角 Y/Z 分量取负值**才是真实旋转方向 (先壤源码同款处理),不处理则手眼结果完全错误——曾为此排查数月。
2. **追踪器位移缩放**: Redspy 输出位移与真实尺寸有未知比例,Tsai 位移方程改为带 scale 列的 4 元未知量 SVD 求解 (见 1.3④)。
3. **序列化精度**: 标定结果落盘/回读若经 float 轴角或四元数中转,屏幕误差从 3 像素劣化到 10+;**旋转用 3x3 矩阵直接序列化**,中间计算全部 double。
4. **矩阵主序**: aoce 数学库为行主序 (从左向右乘);OpenCV/Eigen/g2o 列主序,互转即转置,必须经显式转换函数 (eigen::toMat),直接 memcpy 得到转置错误。
5. **坐标系约定** (三个都要显式转换): aoce 自定义右手系 X右/Y上/Z朝眼 = avox AvoxMath 同款;OpenCV X右/Y下/Z朝眼;UE4 左手 X前/Y右/Z上。aoce 已实现 `convertOpenCVToUE4/convertUE4ToCommon` 等固定变换。
6. **归一化 UV**: 反投影比较用 0-1 UV 比像素值收敛更精细。
7. **g2o 每条边必须 setInformation**,否则结果不稳定不迭代;g2o 动态库卸载前必须销毁 Factory/OptimizationAlgorithmFactory/HyperGraphActionLibrary 三个单例。
8. **初值很重要** (OpenCV 路径): DLT/g2o 初值 + 亚像素角点;g2o HandEyeOptimizer 例外,对初值不敏感。
9. **结果验证要排列组合选最优**,只信重投影误差最小的数据组合,而不是逐一排除。
10. **FBX 坑**: Scene TimeMode 未设会把 25fps 插值成 30fps;FBX 坐标系选 (X:Right Y:Back Z:Up) 再转 UE 姿态,避开 Yaw≈90° 万向锁。
11. **时间对齐**: 相机帧与追踪器位姿频率不同源,需要延迟对齐线程 (统一时间源 + 帧号对齐),Redspy 同一时码会出现两次需去重。
12. **镜头档案持久化**: 标定结果按镜头存档 (内参+CameraTrack),现场直接加载切换,不需重标。

```cpp

// 归一化内参 + 畸变 (与 aoce LensModel 同构)
struct LensModel { vec2d imageSize; vec2d focalLength; vec2d focalCenter;
                   double k1, k2, p1, p2, k3; };
// 标定产物三要素
struct CameraTrack { Mat4x4d base2target; Mat4x4d camera2track; double scale; };
struct TrackCorners { Mat4x4d cameraPose; Mat4x4d trackPose; PointCorners corners; };
struct CornerPoint { vec2f uv; vec3f point; };   // 角点 2D + 3D
// 手眼参数
struct HandEyeParamet { bool fixScale; bool robustKernel; float robustDelta;
                         bool projectionHand; float projectionDelta; };

class ICameraCalibration {   // 内参
    virtual int32_t saveCornerImage(const ImageFormat& format, uint8_t* data) = 0;
    virtual double calibration(LensModel& lensModel, bool bSave = true) = 0;  // 返回重投影误差
};
class ICameraOffset {        // 手眼
    virtual void setLensModel(const LensModel& lensModel, IImagePoints* points) = 0;
    virtual int32_t saveTrackCornerImage(const Mat4x4d& trackPose,
                                         const ImageFormat& format, uint8_t* data) = 0;
    virtual bool compute(const HandEyeParamet& paramet, CameraTrack& cameraTrack) = 0;
    virtual double getOffset(int32_t frameIndex) = 0;   // 该帧重投影像素误差
};
class IVedioCalibration ...  // 拼写按现有 VideoCalibration 修正
class IPnpCameraPose {       // 运行时验证: 画面 → 反推相机位姿
    virtual bool getCamPose(const ImageFormat& format, uint8_t* data,
                            Mat4x4d& camPose, CameraTrack* offset = nullptr) = 0;
};
class ILedMeshBuild {        // Mesh/FBX 顶点 → Aruco 幕墙布点 + 2D-3D 点集
    virtual bool loadMesh(...) = 0;
    virtual void updateWall(int32_t arucoDict, int32_t blockPixel) = 0;
    virtual void createArucoPoints(IImagePoints* imagePoints) = 0;
    virtual bool saveArucoImage(...) = 0;   // 导出 Aruco 贴图给 LED 播放
};
}
extern "C" {

AVOX_EXPORT ICameraOffset* createCameraOffset();
```

### 2.4 分阶段实施

**M1 — 核心标定插件 (纯 OpenCV,~2 周)**
1. `plugins/avox_calib` 骨架 + AvoxCalib.h 数据结构/接口 + CMake 接线。
2. 移植 M1 清单五个实现 (棋盘格路径先通)。
3. `samples/functest/calibtest.cpp`: 用录制数据集 (PNG + Record.json,可从 aocec 拿现成数据) 跑通 内参→PNP→手眼→重投影误差 输出。
4. 单元测试 `tests/test_calib.cpp`: 随机位姿合成数据生成 → 标定 → 与真值比对 (aocec 开发期同款验证法);纯逻辑不链 OpenCV 的部分 (坐标变换/序列化) 进 doctest。

**M2 — 精度增强 (g2o,~2 周)**
1. Eigen vendor 进 `3rdparty/Eigen` (header-only);g2o 预编译库入 `avc_library/3rdparty/library/windows/g2o` + `cmake/FindG2O.cmake` (参考 aocec 同名文件)。
2. 移植 `HandEyeOptimizer` + `CalibrationOptimizer` + `Aoceg2oHelper` (顶点/边/归一化投影),替换 M1 的 OpenCV 手眼为可选 g2o 路径。
3. 变焦标定 `ZoomLensOptimizer` (跟焦 FIZ 场景需要时)。
4. 注意: g2o 边 setInformation、Eigen 列主序转换函数、卸载销毁三单例。

**M3 — 采集与追踪输入 (~2 周)**
1. `ITrackSource` 接口 (AvoxTrack.h,可放 avox_calib 或核心): FreeD D1 / Redspy UDP 解析 → `trackPose {vec3 pos; vec4 quat}` (AvoxMath 已有该结构) + 时码;**欧拉角 YZ 取负**。
2. 时间对齐: 相机 YUVFrame.pts 与 track 时码的延迟对齐线程 (参考 aoce IDelaySyncThread)。
3. Aruco 检测接 avox_calib (OpenCV 4.13 objdetect::aruco API 与 aoce 时代的 contrib API 有差异,检测器写法按 4.x 新 API 改)。
4. `ILedMeshBuild` 对接真实幕墙模型 (如需 FBX,评估复用 avox 现有资产或引入 ufbx/miniz;aoce 用的官方 FBX SDK 太重不建议)。

**M4 — 结果输出到引擎 (按需)**
1. UDP 位姿发送 (Tab 分隔或二进制,自写 ~200 行)。
2. VRPN LiveLink 通道 (需引 VRPN 库,或首期只做 UE LiveLink FreeD 源对接——UE 官方自带 LiveLinkFreeD,我们只需以 FreeD 协议**发送**,零 UE 侧插件成本,推荐优先)。
3. FBX 轨迹导出 (虚拟制片离线回放需要时再做)。
4. SLAM 幕墙建图 (aoce_slam/led) 仅在"异形幕墙拍不全"场景需要,最后评估。

### 2.6 验证策略

1. **合成数据回归**: 随机生成真值 (内参/手眼/scale) → 合成角点图像数据 + 追踪器轨迹 → 标定 → 与真值比误差 (开发期脱离设备自测,aocec 同款方法)。
2. **真实数据集**: 从 aocec 拿坪山/428 两组现场录制数据 (PNG/avi + Record.json + .raw),标定结果重投影误差应达到同量级 (Aruco 路径 ≤5 像素,棋盘格 ~10 像素内)。
3. **运行时验证**: `IPnpCameraPose` 用当前画面反推位姿,与 `trackPose×cameraTrack` 计算位姿投屏比较,像素误差即验收指标。
