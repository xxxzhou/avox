# 录屏与自动缩放方案

> 状态: 进行中 · 上次核对: 2026-10-30 · 权威源: -

> 目标: 在 avox 引擎内新增"多输入采集会话"原语，配合后期合成链，支撑 avoxkit 的
> 录屏 + 自动缩放产品形态。录制只产生不可再生的原始素材（扁平视频 + 分轨音频 +
> 光标遥测），所有包装（背景/圆角/阴影/比例）与放大（裁切/缩放/平移）都在导出时重画。
>
> 2026-10-29 修订: 并入两路独立评审（技术审查 / Screen Studio 对标）。修正了 5 条
> 承重错误——导出 fps 门未接线、双纹理环与 VK 互操作不兼容、pts 用循环计数会快放、
> 采集参数默认值破坏存量路径、场景层与 resize 层尺寸契约冲突；并补齐时钟/失败恢复/
> 隐私/对标差距四节。本文只定方案，不含代码改动。
>
> 2026-10-30 修订: 场景层生命周期与拒绝路径按实现校正 —— `detachEditorScene` 返回后
> 即可销毁场景（渲染侧求值与 detach 同锁互斥）；X2 尺寸不一致改为**建图时**拒绝并
> 每帧重试（把画布改对即自动恢复，不再把 `bRebuilding` 粘死）。探针见
> `samples/functest/scenetest.cpp` 的 `detach` / `recover` 模式。

## 0. 范围

### 0.1 要做

1. 引擎采集源支持固定帧率（CFR）、关闭系统光标、显示器内固定矩形裁剪。
2. 引擎新增 `ICaptureSession`：多路视频输入各写各的文件，多路音频各写各的 WAV，
   共用一条会话时钟，暴露统计与几何。
3. 引擎修好 option 传递体系（三处缺陷），让 `CaptureSession` 作为配置根、采集源
   作为链尾，为以后加冷门键留扩展口。
4. 引擎新增场景合成层（背景 + 裁切缩放平移 + 圆角 + 阴影 + 光标精灵 + 点击涟漪），
   按帧 pts 求值，预览与导出共用同一份数学。
5. avoxkit 侧：shim 的采集/工程 ABI、光标遥测、素材 finalize、自动缩放生成算法、编辑 UI。

### 0.2 不做（及原因）

| 不做 | 原因 |
|---|---|
| 录制时实时放大 | 放大目标取决于用户下一步点哪里，录制时没有后见之明；且烧进画面不可逆 |
| 录制时合成（摄像头 PiP、背景） | 多一路渲染吃 60fps 预算；合成出错会污染不可再生素材；导出侧本来就要做一遍 |
| 多素材拼接 / 多轨剪辑 | 产品口径是"单素材录屏包装"；多素材需要另一套工程模型 |
| 从现成视频反推光标 | 光标已烧进画面，CV 追踪不可靠 |
| HDR 录屏 | WGC 当前只取 BGRA8 SDR；场景层与 `forceHDR` 直通拓扑互斥（见 §6.4） |
| macOS / Android | 采集实现完全另一套（ScreenCaptureKit / MediaProjection），v1 只 Windows |
| 引入 avfilter/avdevice | 构建里已禁用（`script/ffmpeg/build_ffmpeg.py:83-85`），且不该为了抄近路重开 |
| v1 分段录制 | MKV 无实际容量上限，48k 立体声 WAV 到 4GB 约 6 小时；分段要定 IDR/音频切点/段清单与 concat 规则，属 P3（§4.9） |

## 1. 架构与关键决策

### 1.1 三条约束事实

1. **录制的帧是渲染后的帧**：`SourcePlayer.cpp:243-256` 先 `windowRender->render()` 再
   `pushFrame()`。所以"加个合成层就会自动进录像"成立，但那是实时烧录。
2. **引擎已有"解码 → 离屏渲染 → 编码"的成熟通道**：`TranscodeRecorder` 在
   `setOffSurface()` 后无窗口跑完整 VK 图（`TranscodeRecorder.cpp:319-323`），
   `surfaceRender` 在构造时创建（`:16`），因此可以在 `open()` 前挂场景。
3. **VK 图是同步的**：每帧 `vkQueueSubmit` 后 `vkWaitForFences(..., UINT64_MAX)`
   （`VkPipeGraph.cpp:284-285`）。这决定了采集侧不能靠"多张纹理异步轮转"来补帧（§3.2）。

### 1.2 决策表

| # | 决策 | 理由 |
|---|---|---|
| D1 | 录扁平素材 + 光标数据，包装全部后期 | 可撤销；自动缩放需要后见之明 |
| D2 | 录显示器上的固定矩形，不直接录窗口 | WGC 窗口采集中途改尺寸会 Recreate 帧池导致分辨率漂移，而 `RawMuxer` 的尺寸守卫会直接丢帧；窗口移动还会让光标映射漂移。代价见 R12 |
| D3 | 中间素材 = 屏幕原生分辨率；最大放大倍数 = 源/输出分辨率比 | 4K 屏录、1080p 出，2× 放大时可见区域正好 1:1 映射。**这条同时是产品承诺的上限：已拍板不强制 4K，1080p 源不放大（§8.2）** |
| D4 | 一个会话时钟；视频 pts 必须是真实流逝时间 | 采集侧现在用墙钟（`CaptureWindows.cpp:362`），且不能改用帧计数器（§3.2） |
| D5 | 时间轴求值器在 C++，自动缩放生成算法在 Dart | 导出时没有 UI 参与，求值必须确定性；生成算法是纯数据变换，好迭代好单测 |
| D6 | 音频每条轨原样写 WAV，不实时混、不重采样 | 麦克风与回环是两套硬件时钟，实时混要处理漂移/丢块/补静音；分轨落盘还能给导出做增益 |
| D7 | 多输入 = 多文件，录制不做合成 | 见 §0.2 |
| D8 | 固定能力走结构体，长尾能力走 option 键 | 结构体有契约、编译期可查；option 只承担"以后才出现、不值得动 ABI"的键 |
| D9 | 新组件 `CaptureSession` 与 `SourcePlayer` 并列，不继承 `ISourcePlayer` | SourcePlayer 的抽象（单源、音视频一起 ready、渲染即录制）与录屏相反 |
| D10 | 放大深度先按"不损失细节"封顶，超分另案 | 见 §8.2：不封顶会拿糊画面换倍率；Screen Studio 靠本地 AI 超分做到 4×，这是后续独立工程 |
| D11 | 工程模型从第一天就带"源时间 → 成片时间"映射 | 中段剪切/分段变速是同类产品底线（§12），后补会让缩放段、光标、音频全部返工 |

## 2. 产物与工程格式

### 2.1 目录

```
<输出目录>/2026-10-29-1423/
  screen.mkv       原始视频（BGRA→NV12→H.264 缺省，原生分辨率，CFR；
                   hevc_mf 依赖系统 HEVC 扩展, 1029 实测本机无扩展全帧拒编, 回退 h264_mf）
  capture.mkv      成品预览用（screen.mkv + 混音音轨，finalize 产出）
  camera.mkv       可选第二路视频
  audio/mic.wav    麦克风原始 PCM（不重采样）
  audio/sys.wav    系统回环原始 PCM
  cursor.bin       光标采样（定长二进制）
  shapes/NNNN.png  光标形状位图（形状变化才新增）
  shapes.json      每个形状的尺寸/热点/DPI/类型
  events.json      点击 / 几何变化 / 暂停点
  session.json     引擎写：输入表 / 每文件规格 / 时钟起点 / 采集几何
  project.json     产品写：场景样式 / 缩放段 / 音频增益 / 裁剪与剪切
```

中间容器选 **MKV**：录制中途崩溃时截断仍可播放；MP4 丢 moov 就全废。成品导出再出 MP4。

### 2.2 `cursor.bin`

定长 16 字节，240Hz 采样：

```
u32 clockMs   ; 会话时钟（ICaptureSession::getClockMs 同源，已扣暂停）
i32 x         ; 采集矩形内容坐标（像素）
i32 y
u16 flags     ; bit0 可见 / bit1 在矩形内 / bit2 左键 / bit3 右键 / bit4 中键
u16 shapeId   ; 形状索引，形状未变沿用上一个
```

10 分钟约 2.3MB。跳变（相邻采样位移 >250px 且间隔 <50ms）单独落一条
`events.json` 记录，后期平滑时按它切轨，避免把光标画成横穿全屏的斜线。

### 2.3 `shapes.json`（补）

每个形状必须带定位与缩放所需元数据，否则后期无法精确落位：

```json
{ "shapes": [{ "id": 7, "file": "shapes/0007.png",
               "width": 32, "height": 32,
               "hotspotX": 5, "hotspotY": 3,
               "dpi": 120, "type": "arrow", "animated": false }] }
```

`hotspot` 来自 `GetIconInfo` 的 `xHotspot/yHotspot`；`dpi` 记录录制时的系统光标基准
（`GetSystemMetrics(SM_CXCURSOR)` 与显示器 DPI），否则 150% 缩放下光标会偏。

### 2.4 `session.json`（引擎写）

```json
{
  "version": 1,
  "clock": { "t0Mono100ns": 812345678, "t0WallMs": 1793250000123,
             "videoPts0Ms": 0, "audioStartMs": 0 },
  "geometry": { "x": 0, "y": 0, "width": 2560, "height": 1440 },
  "cursorMode": "disabled",
  "videos": [{ "id": "screen", "path": "screen.mkv", "width": 2560,
               "height": 1440, "fps": 60 }],
  "audios": [{ "id": "mic", "path": "audio/mic.wav", "sampleRate": 48000,
               "channels": 2, "format": "s16", "startMs": 0 }]
}
```

`geometry` 是采集矩形左上角的**虚拟屏绝对物理像素**坐标 + 内容尺寸，光标映射只需
`content = screenPos - geometry.xy`。`cursorMode` 三态：
`disabled`（已关光标，后期重画）/ `baked`（未能关闭，光标烧进画面）/ `absent`（GDI 路径本身不带光标）。

### 2.5 `project.json`（产品写）

```json
{
  "version": 2,
  "source": { "video": "capture.mkv", "session": "session.json" },
  "scene": {
    "outputWidth": 1920, "outputHeight": 1080,
    "padding": 0.06, "radius": 0.02,
    "shadow": { "radius": 0.03, "alpha": 0.45, "offsetY": 0.012 },
    "background": { "mode": "gradient", "color": [0.09,0.10,0.14],
                    "color2": [0.16,0.18,0.26] },
    "cursorScale": 1.0
  },
  "timeline": {
    "cuts": [], "speed": [],
    "zoom": { "mode": "auto", "maxZoom": 2.0,
              "segments": [{ "t0": 1234, "t1": 5678,
                             "rect": [1210, 640, 1280, 720],
                             "easeIn": 480, "easeOut": 480, "follow": true }] }
  },
  "audio": [{ "id": "mic", "gainDb": 0, "mute": false },
            { "id": "sys", "gainDb": -3, "mute": false }]
}
```

- 缩放段存**源像素矩形**而不是倍数：改输出分辨率不会让全部关键帧失效。
- `timeline.cuts/speed` 是 v2 预留：v1 允许为空，但**时间映射必须从 v1 就存在**
  （D11）。所有 `t0/t1` 与 `cursor.bin` 的 `clockMs` 都是**源时间**；成片时间由
  `cuts/speed` 映射求出。v1 映射恒等，但代码路径要留出来。

## 3. 引擎改动 A：采集源

### 3.1 采集参数结构体（C1）

`src/avox/AvoxSource.h`，`IVideoSource` **末尾追加**（往中间插虚函数会让旧二进制静默调错）：

```cpp
struct CaptureVideoParam {

  double fps = 0.0;
  // 是否把系统光标烧进画面；缺省 true = 保持现有行为

  // WGC 采集黄框；缺省 true = 保持现有行为
  bool border = true;
  // 采集矩形：虚拟屏绝对物理像素；w/h<=0 = 整屏（会话不传这个捷径，见 §3.4）
  int32_t regionX = 0;
  int32_t regionY = 0;
  int32_t regionW = 0;
  int32_t regionH = 0;
};

class IVideoSource {
  ...
  // 采集策略，open 前设置生效；不支持该能力的源忽略
  virtual void setCaptureParam(const CaptureVideoParam& param) {}

```

**默认值必须是"存量行为"**：不调用 `setCaptureParam` 的旧路径（`DeviceSource`/`SourcePlayer`/
`avox_cmd device`）不能被改成 60fps、丢光标、去黄框。60fps + 关光标由 `CaptureSession`
在 `start()` 时显式下发。

### 3.2 CFR 节拍（C2）

现状（`src/avox_windows/winrt/CaptureWindows.cpp`）：单线程"拉一帧 + sleep 到下一个 tick"，
fps 硬编码 30（GDI `:89`、WGC `:304`），没有补帧。三个问题：Windows 默认定时器精度
15.6ms（`WindowRender.cpp:336` 的 `timeBeginPeriod(1)` 只作用于渲染刷新线程，采集线程
必须自己调）；屏幕静止时 WGC 不产帧；**帧计数器不能当时间**——一旦某帧耗时超过周期，
计数器会落后墙钟，录出来是快放。

改造（WGC 路径）：

```
timeBeginPeriod(1)                        // 本线程成对调用，退出 timeEndPeriod(1)
t0   = timeTick()                         // 100ns 单调
tick = 0
while (running()) {
  due = t0 + tick * 10000000 / fps
  sleepUntil(due)                         // 绝对到期
  frame = framePool.TryGetNextFrame()     // 可能为空
  if (frame) CopySubresourceRegion(outTex, frame)   // 单张输出纹理，见下
  emit(outTex, pts = round(tick * 1000.0 / fps))
  // 用时钟反推下一拍，而不是 tick++：慢帧时跳拍，绝不快放
  int64_t nowTick = (timeTick() - t0) * fps / 10000000LL
  if (nowTick > tick + 1) missed += nowTick - tick - 1
  tick = nowTick + 1
}
```

三条硬约束（上一版方案在这三处都错了）：

1. **pts 用排期时刻 `tick*1000/fps`，tick 由时钟反推**。慢帧时跳拍并计入 `missed`，
   文件时长始终等于墙钟时长；绝不能 `tick++` 硬推。
2. **只用一张输出共享纹理，不搞多张轮转**。VK 侧在建图时 `bindD3D` 一次
   （`VkInputLayer.cpp:143`），`VkWinImage::updateInputContext` 在对端指针变化时只
   置 `bInit=false` 就 `return`（`VkWinImage.cpp:183-199`），不会重新导入；换纹理等于
   第二帧起读旧图。补帧（WGC 没给新帧）**直接重发同一张帧、不做拷贝**——内容是重复的，
   没有写方竞争。
3. **GDI 路径单独写**：它是 `BitBlt`（`CaptureWindows.cpp:167`），没有 framePool、
   没有空帧分支，区域裁剪改 `srcX/srcY` 而不是 `srcBox`，pts 在 `:178`。

`E2b（条件项）`：如果实测单帧 render+encode 的 p95 > 周期 80%，再加节拍/处理双线程。
届时要先把 VK 输入侧改成"按槽重绑 + 每槽 fence"（新增能力，不是改几行），所以
**P0-a 不要为异步预留复杂度**。

### 3.3 光标与边框（C3）

在 `session.StartCapture()`（`CaptureWindows.cpp:272`）之前：

```cpp
if (auto s2 = session.try_as<IGraphicsCaptureSession2>())
    s2.IsCursorCaptureEnabled(param.captureCursor);
if (auto s3 = session.try_as<IGraphicsCaptureSession3>())
    s3.IsBorderRequired(!param.border);      // 仅 Win11
```

三态落 `session.json`：

- QI 成功且已关 → `cursorMode="disabled"`；
- QI 失败（老系统）→ `cursorMode="baked"`，产品禁用光标特效；
- 走 GDI 路径 → `cursorMode="absent"`（BitBlt 本身不含光标）。

注意：Win10 无法关黄框（`IsBorderRequired` 仅 Win11），录像会带黄边，UI 需说明。

### 3.4 区域裁剪（C4）

帧池仍按显示器真实尺寸建；输出纹理改成裁剪矩形尺寸，拷贝时用 `srcBox`：

```
srcBox = { rx - monitorX, ry - monitorY, 0, cw, ch, 1 }
cw/ch  = 偶数对齐后的矩形尺寸
```

- 矩形先与显示器矩形求交，空交集直接 `open` 失败，不静默出黑帧。
- 奇数宽高向上对齐偶数，多出的最右/最下 1 像素留黑。
- **会话不传 `regionW/H<=0` 的捷径**（整屏也要显式给矩形），否则 geometry 需要源回报
  显示器原点，多一层耦合且首帧前无几何可用。`:w<=0` 只留给非录屏宿主。
- 换分辨率/改缩放/拔显示器时 WGC 会 `Recreate` 并改变内容尺寸，尺寸守卫会全丢帧；
  v1 的处置是**停录并报错，保留已有文件**（§4.8）。

### 3.5 时间戳

`gpuFrame.pts/dts` 改为节拍网格值，不再用 `timeStampMS()`。音频侧不改采集逻辑，但
`WasAudioSource.cpp:124` 的 pts 是 `timeStampMS()`（系统墙钟，且在 drain 时打戳），
**不能直接当设备时钟用**——会话只记录首包到达的会话时刻，漂移处理见 §4.7。

## 4. 引擎改动 B：CaptureSession

### 4.1 职责边界

只做一件事：**把 N 路设备输入变成 N 个文件 + 一份会话元数据**。不做合成、不做混音、
不管光标采样（那是宿主的）。

### 4.2 公共接口

新头 `src/avox/AvoxCapture.h`，需在根 `CMakeLists.txt` 的 `copy_head` 组补一行
（`CMakeLists.txt:362-378`）。SWIG 暂不纳入。

```cpp
namespace avox {

enum class CaptureState : int32_t { idle, starting, recording, paused, stopping, stopped, failed };

struct CaptureVideoInput {
  IVideoSource* source = nullptr;   // 设备管理器所有；见 §4.6 所有权契约
  const char* id = "screen";        // 落盘名与工程标识
};

struct CaptureAudioInput {
  IAudioSource* source = nullptr;
  const char* id = "mic";
};

struct CaptureConfig {
  CaptureVideoParam video = {};     // 下发给主视频源；会话显式设 60fps/关光标
  VideoDesc outVideo = {};          // 0 = 跟源；非 0 = 转换腿缩放
  VideoEncodeParam videoEncode = {};
  const char* container = "mkv";
};

struct CaptureStats {
  double achievedFps = 0;           // 近 2s 滑动窗口
```

### 4.4 视频腿（每路一个）

```
IVideoSource --(源线程回调)--> VideoLeg::onVideoFrame
    ├─ WindowRender（离屏，NV12/YUV420P 输出）= 格式转换器
    └─ RawMuxer（每腿一个文件）
```

- `WindowRender` 只当转换器：`setOffSurface(YuvType::nv12)`，不启用任何画质/字幕/水印层。
- `RawMuxer` 每腿一个，**必须显式 `setMuxerType(MuxerType::ffmpeg)`**：`MediaMuxer::open`
  在 `muxerType==none` 时会落到 zlmediakit（`MediaMuxer.cpp:62-64`），写本地文件必错。
- 输出 desc 在 `start()` 前就能算出来（宽高 = 区域偶数对齐、fps、NV12），因此
  **先建 muxer 并 open，再打开源**，避免片头丢帧（§4.5）。
- 预览：`getPreviewRender()` 返回 primary 腿的 `WindowRender`；`setSurface(hwnd)` 后
  同时出画面与录像（display 支路与 yuvOut 支路本就并存）。

### 4.5 音频腿与启动顺序

每条音频输入一个裸 WAV 写入器：`RIFF` 头 + PCM 原样 append，不重采样、不混音、不编码。
**落盘统一走公共 `IWavSave`（`WavSave`，1030 收口）**：头在 open 时占位（崩溃也是可播
文件）、线程安全、4GB 上限、`patchHeader()` 周期回填；planar→interleaved 转换也在它
体内。P0-a 曾另建内部 `WavWriter`，与既有 `IWavSave` 重合（用户指认），已删并统一。

启动顺序（顺序错了会丢片头或丢音频头）：

1. 由配置算视频 desc → 建 `RawMuxer`（ffmpeg）→ `setInVideoDesc` → `open`（进入 recording）；
2. 打开音频源，等 `onAudioDesc` → 写 WAV 头（长度字段先占位）→ 开始收 PCM；
3. 打开视频源 → 首帧到达即推 muxer；
4. 首帧确定 geometry 后，`onCaptureState(recording)` 通知宿主开始光标采样。

音频帧在 WAV 头写好之前到达的，丢弃并计入统计（约几毫秒）。磁盘慢/杀毒扫描导致写队列
满时**阻塞优先**，同时把丢弃样本数计入 stats 并报 `onCaptureError`，不允许静默丢。

### 4.6 设备所有权与生命周期契约

- 源指针归 `IVideoManager/IAudioManager` 所有；会话**不拥有**。
- `addVideoInput` 时给源打"占用"标记（`IVideoSource` 侧的原子计数，或会话内的
  `unordered_set` + 静态互斥）：**同一源被两个会话同时 `open` 会互相覆盖内部的
  framePool/session，必须拒绝**。
- ~~`CaptureWindowsMgr::onRefreshDevices` 只 append 不清空~~ **已修（1030）**：刷新改为
  枚举进临时表后原子换 `devices`；`bOpening()` 或 `markVideoSourceBusy` 占用中的源对象
  pin 住原样保留，与 pin 源同目标的重复枚举条目跳过（占用登记走
  `VideoSource.hpp` 的跨模块 `markVideoSourceBusy`，平台管理器与会话共用一张表）。
  `WasAudioSourceMgr` 刷新仍是 no-op（音频设备集稳定，暂不处理）。
- `~CaptureSession` 强制 `stop()`：停源 → join 源线程 → `removeObserver` → `unlinkOption`
  → flush/关 muxer → 回填 WAV 头。顺序不能换（`Observer::dispatch` 持锁回调，
  session 先析构会打野指针）。

### 4.7 时钟与漂移

- 唯一时间基：`SessionClock::activeMs() = (now - t0)/1e6 - pausedAccum`。
  视频 pts、光标 `clockMs`、音频首包 offset 全部用它。
- `t0` 在 `start()` 里取，`session.json` 同时记 `t0Mono100ns` 与 `t0WallMs`。
- 视频 pts 的 0 点与音频首包的 0 点可能相差几十毫秒：分别落
  `clock.videoPts0Ms` 与 `audios[].startMs`，finalize 按它们对齐。
- **漂移是物理存在的**：消费级声卡 50~100ppm，10 分钟就是 30~60ms。v1 不在录制时
  校正，而是在 finalize 时用 swresample 把音频时长锁到视频时长（`swr_set_compensation`）。
  验收因此不能写死"10 分钟 <40ms"，改为"经 finalize 补偿后 <40ms，补偿前实测值记录在案"。

### 4.8 失败与恢复

| 场景 | 处置 |
|---|---|
| primary 打不开/首帧超时 2s | 会话 `failed`，不建空文件 |
| 第二路视频/任一音轨失败 | 降级继续，`onCaptureError(id,...)` |
| 磁盘满/写失败 | `failed`，停源、flush、回填 WAV 头、保留已有文件并报错（不能静默继续） |
| 编码器 EAGAIN | ~~静默丢~~ **已修（1030）**：`VideoStream::encodeFrameImpl` 对 `dataNoReady`（=send_frame EAGAIN，帧被拒）计数，经 `RawMuxer::getEncoderDropped` 暴露到 `CaptureStats.encoderDropped`；尺寸守卫/帧率门丢弃同样计数（`droppedBySize`/`droppedByFpsGate`），session.json 每腿落 `dropped` |
| 分辨率/缩放变化 | 停录报错、保留文件；v1 不支持录制中切几何 |
| 进程被杀/断电 | 启动即写 `session.draft.json`；WAV 头每 5s 回填一次长度；MKV 截断可播 |
| 麦克风独占/隐私开关 | 音轨降级 + UI 明示；录制页做权限预检 |
| 自家 UI 被录进去 | 控制条/预览窗 `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`（Win10 2004+，需实测子窗口）；两个仓目前都没有这个调用 |

### 4.9 明确不做：分段

`segmentSeconds` 从 v1 移除。要做得先定：段首强制 IDR、音频按采样点切并记 `startSample`、
`session.json.videos[].segments[]` 清单、finalize 的 concat 规则。这四件不定死，
分段出来的素材无法导出。放到 P3 单独设计。

## 5. 引擎改动 C：option 体系

### 5.1 三层配置边界

| 层 | 承载 | 例子 |
|---|---|---|
| 结构体 | 固定能力，有确定语义、必须生效、UI 有控件 | `CaptureVideoParam`、`CaptureConfig`、`VideoEncodeParam` |
| option 键 | 冷门/调试/远程下发/以后才出现，且不想为它动 ABI | `rec.hard.encode`、`rec.encode.gop` |
| 自描述 schema | 键多到需要 UI 枚举时才建 | 现在不建 |

判断标准一句话：**会不会有人忘了设它？会不会在 UI 上出现？会不会影响 ABI？**
前两个"会"就是结构体。

### 5.2 三处必须修

`src/avox/module/JsonOption.cpp`：

| # | 现状 | 后果 | 修法 |
|---|---|---|---|
| O1 | `linkOption()` 不摘旧父（`:53-65`） | 源被重链后旧树仍持有观察者，旧树 set 会打到不归它的链上 | 进入时先 `removeObserver(this)` |
| O2 | 只有析构函数解绑（`:47-51`） | 源归设备管理器所有、比会话活得久；会话先析构则源之后解绑野指针 | 新增 `unlinkOption()` |
| O3 | `linkOption` 盲转 `(JsonOption*)` 且不判空（`:59` 会解引用空） | 传错类型/`nullptr` 直接崩 | 判空 + 类型检查 |

同时补一条契约注释：**`linkOption` 遍历 Json 对象不加锁，只能在停止态、由同一控制线程调用。**
另外 `JsonOption::getInt` 读缺键会抛（`Json.hpp:330-338`），会话构造时必须把默认值 seed 进树。

### 5.3 接线

```
CaptureSession : JsonOption               ← 配置根，getOption() 返回 this
  ├─ IVideoSource（dynamic_cast 到 OptionLink）
  ├─ IAudioSource（同上）
  └─ WindowRender（VideoRender 已是 OptionLink）
RawMuxer 不进链：会话读 rec.* 后转成结构体，open 前塞给 muxer（同 TranscodeRecorder）
```

`VideoSource`（`VideoSource.hpp:11`）与 `AudioSource`（`AudioSource.hpp:9`）各加一个
`public OptionLink` 基类。注意口径：

- 不是"零 ABI"：会给这两个具体类增加基类子对象。但宿主持有的始终是 `IVideoSource*`/
  `IAudioSource*`，它们的 vtable 槽位不变，具体类的布局变化只影响静态链接 SDK 的宿主
  （Apple 静态库）——必须随 SDK 重编。
- **当期没有任何键给它们消费**，纯为以后加采集侧冷门键留口子。不想要可以整体删掉，
  不影响 §3/§4。

### 5.4 未来加键的规则

1. 键必须在 `src/avox/module/OptionKey.hpp` 里声明并写一行注释（类型、默认值、生效时机）。
2. 消费方只在 `onOptionChange` 里读（它跑在 setter 线程），值必须落到 `std::atomic`
   或加锁成员；采集线程禁止直接 `getLink()->getInt()`（既竞态，缺键还会抛）。
3. 键名分区前缀（`cap.*` / `dev.*` / `rec.*` / `mp.*`），消费方严格按前缀过滤，
   漏一个就会误吃别人的键并抛异常。

## 6. 引擎改动 D：场景合成层

> **施工记录 2026-10-30（P1-a R1-R4 已落地）**：`glsl/source/scene.comp` + `VkSceneLayer`
> （2 入 1 出，inCount=2：0=内容/1=图集，图集缺省 1x1 透明兜底统一描述符）+
> `EditorScene`（控制侧快照，set* 即拷贝升代数）。静态样式（背景渐变/圆角/阴影/
> padding/比例适配居中）像素级验收过（内容区边界 166,64-1113,656 与计算值一致、
> 圆角弧外为背景、投影带 11-16 vs 远景 24）。接口按 §6.5 放 `AvoxCapture.h` 末尾
> （`SceneSource` 内部视图与公共 `IEditorScene` 分离，快照结构不进公共头）。
> 落地偏差：①镜头段 v1 直切（easeIn/easeOut/follow 字段收下不用，P2 R5 接）；
> ②光标 v1 最近可见样本+格子正方形近似；③`smoothstep` 投影要形内全量形外淡出
> （首版写成内阴影+边缘倒置两个错，剖面校出）；④attach 后 set* 生效靠代数比对，
> **初始代数须置 UINT64_MAX 强制首载**（gen=0==snapGen=0 比对永假的坑）。

### 6.1 为什么必须单层

- `VkResizeLayer` 参数一变就 `resetGraph()`（`VkResizeLayer.cpp:43-49`）——不能逐帧改；
- `VkCropLayer` 只支持偏移、没有缩放，且未接入任何图；
- 水印用的 `VkBlendLayer` 透明度语义是反的（`VkBlendLayer.cpp:24` 把 `alaph` 当
  opacity，`blend.comp:37`），且只能做整图矩形映射；
- `VkVrLayer` 的"固定输出尺寸 + 逐帧 UBO 采样映射"是正确范式。

所以新增 `VkSceneLayer`（2 入 1 出，一趟 shader 做完），不复用上面任何一个。

### 6.2 shader 输入与 UBO

- 输入 0：屏幕内容（`yuv2RGBA` 之后，已是目标色彩空间）
- 输入 1：光标图集（CPU RGBA，**固定 1024×1024**，形状变化只换内容不换尺寸——
  尺寸一变 `VkInputLayer` 会 `onFormatChange → graph->reset()`，录制中闪断）
- 输出：画布尺寸（= 导出目标分辨率）

UBO：

```
vec4  cropRect;        // 源像素 xywh（当前镜头）
vec4  canvasRect;      // 画布内内容区 xywh（已含 padding）
vec2  outSize;
float radius;          // 圆角半径，画布宽占比
float shadowRadius;    // 阴影模糊，画布宽占比
float shadowAlpha;
vec2  shadowOffset;
vec3  bgColor0, bgColor1;   // 纯色时两者相同
vec4  cursorPosSize;   // 源像素：x,y,w,h
vec4  atlasUv;         // 图集细胞 UV
float cursorAlpha;
vec4  ripple[4];       // 源像素 xy + 起始时刻(秒) + 强度
float nowSec;
```

绘制顺序（同一 pass）：背景 → 圆角阴影 → 按 `cropRect` 采样屏幕内容（降采样 ≥2× 时
4-tap tent）→ 圆角 alpha mask → 光标精灵（画布空间合成）→ 点击涟漪（0.6s 内）。

**限制先说清**：单 pass 的阴影是 SDF 近似，不是真高斯模糊，边缘会更"实"。要真柔和
得加一个低分辨率 mask + 可分离 blur 的 pre-pass；v1 先接受，验收按"与设计稿接近"。

### 6.3 时序

层不自带时钟。`VkVideoRender::onPreFrame()` 里把当前帧 pts 推给场景（**不要放
`onParametUpdate`**：它只在 `graph && !bResetFlag` 时被调，重建那一帧不调
（`VkVideoRender.cpp:530-537`），场景会用上一帧时间跳一下）。场景在 `onPreFrame` 内
按 pts 求值并写 UBO：镜头（查段 + 缓动）、跟随（死区平移）、光标（插值）、涟漪。

**求值器只有这一份**：预览与导出走同一个 `VkVideoRender`，不另写 Dart 版插值。

### 6.4 挂载、尺寸与 HDR

- 图里位置：`yuv2RGBA` 之后、`rgba2YUV` 之前。
- **场景启用时跳过 `VkResizeLayer`，但保留 `bUseNewSize`**：`enableSizeChange(canvasW,
  canvasH)` 仍要调，因为 `getOutSize()` 只在 `bUseNewSize` 时返回画布尺寸
  （`VkVideoRender.cpp:486-493`）；而 resize 层必须跳过，否则先缩到画布再裁切会丢细节。
  实现是在 resize 分支加 `&& !bEnableScene`（`VkVideoRender.cpp:687-701`）。
- **`forceHDR` 与场景互斥**：直通拓扑会裁掉全部可选层（`VkVideoRender.cpp:575-577`），
  场景若挂在 `!bPt` 分支会静默消失。`attachEditorScene` 时若 `hdrMode==forceHDR`
  直接返回 false；导出入口也要拒绝 HDR 源。
- **aspect**：场景启用时 `setAutoAspect(false)`。否则输出层按输入帧宽高比算 viewRect
  （`VideoRender.cpp:267-270`、`VkOutputLayer.cpp:338-351`），会把画布 padding 裁掉。
  验收要有"16:10 源 + 16:9 画布"用例。
- 画布尺寸只有一个 owner：`setCanvas` 与 `setVideoDesc` 的尺寸必须相等，不等**建图时
  被拒**（见 §7.2）。

### 6.5 接口

放在 `AvoxCapture.h`（与录屏同模块），用自由函数挂到渲染面，避免动 `ISurfaceRender`

```cpp

  virtual void setCursorTrack(const SceneCursorSample* samples, int32_t count) = 0;

AVOX_EXPORT IEditorScene* createEditorScene();
AVOX_EXPORT void destroyEditorScene(IEditorScene* scene);
// 挂到渲染面：open 前或首帧前挂上；后者触发一次图重建
```

线程契约：`set*` 在控制线程调用，内部拷贝成快照 + 原子代数交换；渲染线程看到新代数

## 7. 引擎改动 E：导出

### 7.1 fps 门必须先接通（X1）

> **已修（2026-10-30）**：`RawMuxer::setVideoDesc` 守卫放宽到仅 recording（opening 是
> onReady 声明规格的窗口）；`TranscodeRecorder::onReady` 在 `setInVideoDesc` 前调
> `setVideoDesc(gateDesc)`（显式 outVideo 用宿主口径含 fps，无声明用源尺寸+90/270
> 换向，滤镜路用滤镜输出）。实测 60fps 源声明 30 → 360 包进 180 包出 @30fps。
> ⚠️ 此修复让**所有**转码导出启用尺寸守卫+帧率门（存量行为变化），panvox 录制腿
> 回归须过一遍。

**现状是断的**：`TranscodeRecorder::setVideoDesc` 只存成员（`TranscodeRecorder.cpp:107-110`），
`onReady` 只把 width/height 用于 `enableSizeChange`，**从不调用 `muxer->setVideoDesc`**；
而 `RawMuxer::recordFpsGate` 读的是 `outVideoDesc.fps`（`RawMuxer.cpp:184`），该值恒为 0
→ 帧率门旁路。60fps 素材导出 30fps 实际仍是 60fps。

修法：`onReady` 里在 `setInVideoDesc` 之前调 `muxer->setVideoDesc({canvasW, canvasH, outFps,
yuvType})`（会同时启用 fps 门与尺寸守卫；尺寸与渲染输出一致才安全）。

### 7.2 场景尺寸契约（X2）

场景启用时：

- `enableSizeChange(canvasW, canvasH)` 照调（为了 `getOutSize` 正确）；
- 图里跳过 `VkResizeLayer`（§6.4），场景层输出画布；
- `setVideoDesc` 的尺寸必须等于画布尺寸；不等的处理是**建图时拒绝**（不产生半成品图、
  不把 `bRebuilding` 粘死），此后每帧重试 —— 宿主把 `setCanvas` 改对即自动恢复出帧，
  无需重挂或重开；日志只在拒绝原因变化时打一条（探针 `scenetest recover`）。

### 7.3 三步出片（X3）

`IRecorder::open` 只接受一个输入 URL（`AvoxMuxer.h:273-275`），音频来自两份 WAV，
所以不能"一条 recorder 全做完"：

1. 视频轨：`createRecorder(true)` → `setVideoCodec` → `setAudioCodec(none)` →
   `setVideoDesc(canvas)` → `attachEditorScene(surface, scene)`（**open 前**）→
   `open(inputVideo, tmp.video.mkv)`；
2. 音频轨：读 `mic.wav` + `sys.wav` → swresample 统一 48k/立体声 → 按工程增益相加 →
   按 §4.7 的漂移补偿锁时长 → 编码 AAC → `tmp.audio.m4a`；
3. remux：`tmp.video.mkv` + `tmp.audio.m4a` → 成品，两轨直拷。

第 2、3 步在 avoxkit shim 里做（已链 avformat/avcodec/swresample），不进引擎。
同一个函数在录制结束后也跑一次，把混音轨并进 `capture.mkv` 供预览。

### 7.4 裁剪区间

`project.timeline` 的入出点用 `IRecorder::seek(inMs)`（`AvoxMuxer.h:284`，open 后等
`recording` 再调），到 `outMs` 由 `onProgress` 主动 `close()`；音频混音按同样区间裁样本。
v1 不做中段剪切（`cuts[]` 留空），但时间映射代码路径要在（D11）。

### 7.5 编码与封装参数

- **默认 H.264，HEVC 作为高质量选项**：HEVC MP4 在 Chrome/网页上传/部分播放器上兼容性差，
  交付件不能只有 HEVC。
- 预设：1080p / 4K × 30 / 60；只允许降帧率（`recordFpsGate` 只丢不补）。
- HEVC 输出要 `hvc1` tag；统一 `avoid_negative_ts`；AAC 用初始 priming/edit list；
  成品 `+faststart`。用 Windows Media Player、Chrome、QuickTime 各验一遍。

## 8. 自动缩放算法（Dart）

### 8.1 输入输出

输入：`cursor.bin` + `shapes.json` + `events.json`（点击时刻）+ 画布与源尺寸。
输出：`timeline.zoom.segments[]`（源像素矩形 + 缓动 + 是否跟随）。

### 8.2 现实倍率（必须先对齐产品承诺）

`maxZoom = min(srcW/outW, srcH/outH)` 在常见组合下：

| 采集 | 输出 | 最大放大 |
|---|---|---|
| 1080p | 1080p 16:9 | **1.0（不能放大）** |
| 1440p | 1080p 16:9 | 1.33 |
| 4K | 1080p 16:9 | 2.0 |
| 4K | 4K 16:9 | 1.0 |
| 4K 16:9 | 1080×1920（9:16） | 约 1.125 |

也就是说"2× 放大"只在"4K 采集 + 1080p 横屏输出"这一种组合成立。

**已拍板（2026-10-29）：接受"1080p 源不能放大"，不强制 4K 采集。** 由此推出的产品约束：

- 录制页按"显示器物理分辨率 + 目标比例"实时算出可放大倍数，直接显示
  "放大能力：无 / 1.33× / 2×"；为 1.0 时给"4K 屏录制才能放大"的提示；
- 工程打开时若 `maxZoom < 1.1`，自动缩放默认关闭（生成 0 段），只保留手动缩放；
- 编辑/导出页不出现放大相关控件，不承诺做不到的效果；
- 超分（D10）继续作为独立后续工程，不并入本方案。

### 8.3 生成步骤

1. **聚簇**：1.5s 内、300px 内的点击归为一簇；
2. **目标矩形**：该簇内轨迹包围盒 + 边距，按画布比例修正；下限 = 全屏 / `maxZoom`；
3. **分辨率钳制**：见 8.2；
4. **合并**：相邻簇间隔 <2s 合并，单段最短 1.5s；
5. **跟随**：`follow=true`，层内按死区（40%）平移，带阻尼；
6. **退出**：静默 2s 推回全屏；
7. **缓动**：进/出各 450~550ms，cubic in-out，末尾约 3% 过冲（可配）；
8. 跳变事件不参与包围盒。

### 8.4 无点击场景的兜底

规则法在滚动、终端输入、幻灯片、游戏、纯视频播放上**不会产生任何缩放段**。
Screen Studio 同样如此（官方 auto-zoom 指南明确只对点击区域生效），它的兜底是
"任意时刻手动加一段缩放 + Instant"。所以：

- P2 必须同时交付**手动缩放一等 UX**（时间轴任意位置加段、拖边、改倍率、Instant）；
- 产品文案不得承诺"全自动跟随鼠标"。

> **修正 2026-10-30：stop/finalize 拆开（ABI 1.9）。** 会话状态在 native 内跟着
> 创建它的 isolate；实例方法里的闭包被 `Isolate.run` 发送时会隐式捕获 `this`
> （`State` 挂着 `Timer`），报 `object is unsendable`，表现为「点结束录制提示失败、
> 录制还在继续」。现在 `ak_capture_stop` 只在主 isolate 调（只落盘，快），
> `ak_capture_finalize(dir)` 只读文件、放后台 isolate，失败退回主 isolate 兜底。

> **修正 2026-10-30（二次定位，推翻上面「WGC 恒黑」与「NT 共享纹理不能 GPU 拷」两个结论）：
> 真正原因是一个空 `D3D11_BOX`。** 源帧本身有画面（亮度 35.8），但
> `CopySubresourceRegion` 的 box 只填了 left/top/right/bottom，`front/back` 仍是 0；
> 3D 盒 0/0 是空盒，驱动静默拷 0 字节，目标纹理保持黑。整帧 `CopyResource` 没有 box，
> 所以「hop」探针一直有画面，把排查方向带偏到共享纹理/驱动上。对照探针复现：同一
> `MISC_SHARED | SHARED_NTHANDLE | GDI_COMPATIBLE` 目标，补上 `front=0/back=1` 后
> `CopySubresourceRegion`（含子区 box）拷入读出的亮度与源帧一致。
> 修法：保留纯 GPU 直拷，只补 `srcBox.front/back = 0/1`；此前「staging 读回 +
> `UpdateSubresource`」的 CPU 上传已全部删除（那只是掩盖空 box 的绕路，每帧多两次
> 全画面拷贝）。实测 2560×1440@60 → 59.9fps、289 帧/5s、丢弃 0、`screen.mkv` 抽帧
> 亮度 42.1、导出 38.7。GDI 兼容路仍不采用（GetDC+BitBlt 与 Flutter 同进程时在
> `flutter_windows.dll+0x3C16A` AV 崩宿主）。旧结论「IDD 下 WGC 恒黑」同样由空 box
> 解释，WGC 在 IDD 与物理屏都能出画面。
> 另: `AVOX_CAPTURE_GDI` 这类环境变量在静态 CRT 的 DLL 里读不到宿主 `_putenv_s`，
> 宿主进程环境变量才生效——做 A/B 时必须从父进程设置。

### 10.3 全局验收判据

- 视频时长与墙钟误差 <1%（抓"快放"）；
- 音画漂移：finalize 补偿后 10 分钟 <40ms，补偿前实测值记录；
- 单帧耗时 p95 < 周期的 80%（否则上 E2b）；
- 导出 4K60 输入 → 1080p30 输出 ≤2× 实时；1080p60 输入 → 1080p60 ≤3× 实时；
- 预览与导出同一时间点抽帧，PSNR ≥45dB（不要写"≤1 LSB"，BGRA→NV12→HEVC 往返做不到）；
- 诊断用例：磁盘满、进程 kill、显示设置变化、麦克风独占。

## 11. 风险与回退

| # | 风险 | 触发条件 | 回退 |
|---|---|---|---|
| R1 | 两路 `WindowRender` 并发（共享 `VkContext::Shared()`，submit 有全局锁） | 加摄像头时 | 只做单路视频，第二路留到 P3 |
| R2 | 4K60 吞吐压不住（VK 图同步 fence + MF 编码） | p95 帧耗时 > 80% 周期 | 上 E2b 双线程（需先做 VK 输入多槽 rebind）；仍不够则采集侧直出 NV12 走 D3D11 硬编（注意：`FFDx11Encoder` 的注册 `initFuncs.push_back` 在 `FFDx11Encoder.cpp:34` 是注释掉的，`AvoxManager.cpp:168` 那个调用等于空转，等于"当前没有 DX11 硬编"） |
| R3 | 单张共享纹理与异步硬编的竞争 | 60fps 下编码器仍读上一帧 | 先实测（抽帧找撕裂/错帧）；复现则降帧率或给 VK 输入加"按槽重绑 + 每槽 fence" |
| R4 | 编码器 EAGAIN 静默丢帧 | 高码率/低性能机 | 计数暴露 + 提示降码率；必要时给 VideoStream 加有界重试 |
| R5 | MF 高码率画质不够 | 放大后可见压缩痕 | 降录制分辨率/帧率，或走 GPL 渠道 libx264/x265 |
| R6 | `IsCursorCaptureEnabled` QI 不到 | 老系统 | 降级 `baked`，产品禁用光标特效 |
| R7 | 多显示器/混合 DPI 导致光标映射错位 | 主屏 150% + 副屏 100% | 用 `MonitorFromPoint`+`GetDpiForMonitor` 统一到物理像素；首帧角标自校准；列入验收 |
| R8 | 音频漂移 | 10 分钟以上 | finalize 用 `swr_set_compensation` 锁时长 |
| R9 | HEVC 兼容性 | 网页上传/Chrome | 成品默认 H.264 |
| R10 | 场景与 forceHDR 互斥 | 导出 HDR 源 | attach 直接失败并报错 |
| R11 | 阴影/降采样画质不达预期 | 4K 输出近看 | v1 接受；需要真模糊时加 pre-pass |
| R12 | 固定矩形录不到窗口后续变化 | 用户移动/缩放窗口 | 产品提示"录制矩形固定"；P3 评估窗口跟随 |

## 12. Screen Studio 对标与差距

来源：screen.studio 官网与 guide/changelog（auto-zoom、cursor、trimming、speed、
aspect-ratio、export settings、changelog 4.0/4.1 等页）。

### 12.1 一个关键校正

**Screen Studio 的自动缩放不是 AI 理解窗口，就是点击驱动**——官方 auto-zoom 指南明确
"只聚焦录制中发生点击的区域，在没有点击的地方不会缩放"，iPhone/iPad 录制因为无点击
甚至不支持自动缩放。方案 §8 的方向与它同类，差距不在"有没有 AI"，而在**放大深度、
镜头质量、无点击兜底**。

同理，它的光标也是"录制时忽略、后期用精确鼠标数据贴回"，方案的架构（关光标 + 遥测 +
位图精灵）方向一致，差距在**高清/样式/去抖/运动模糊**。

### 12.2 覆盖情况

| 能力 | 方案状态 |
|---|---|
| 点击驱动自动缩放、手动缩放段 | 覆盖（P2）；缺 Instant/数值输入等 UX |
| 放大深度 4×/6.5×（本地超分） | **未覆盖**（方案封顶在分辨率比，§8.2） |
| 镜头风格（Focused/Smooth、运动模糊、Loupe） | 部分（只有一种缓动） |
| 关光标 + 后期重贴 + 大小/样式 | 部分（位图回放，缺高清/样式/静止隐藏） |
| 点击涟漪 | 覆盖 |
| 背景/圆角/阴影/padding/比例 | 部分（无图片/壁纸背景、无 inset、无阴影角度） |
| 麦克风 + 系统声分轨 | 覆盖 |
| 降噪/响度归一化 | **未覆盖** |
| 入出点裁剪 | 覆盖 |
| 中段剪切 / 分段变速 / 打字加速 | **未覆盖**（需要 cuts/speed，D11 已预留模型） |
| 摄像头单独录制 + 后期构图 | 采集覆盖，构图未排（P3） |
| 键盘按键显示 | 未排（P3） |
| 字幕/转写/去口癖 | **未覆盖**（avox_sherpa 是现成资产） |
| 遮罩/高亮/敏感数据遮挡 | **未覆盖** |
| 导出 MP4 720p/1080p/4K60、GIF、ProRes | 部分（只有编码 + remux，缺预设与 GIF） |
| 窗口录制 | 不做（D2/R12） |
| 暂停/倒计时/控制条/崩溃恢复 | 部分（暂停有；录制 flag、2 秒落盘恢复未排） |

### 12.3 差距结论（三件事）

按这个方案做出来，和 Screen Studio 的主要差距是：

1. **放大深度与镜头质量**：2× 封顶且只在 4K→1080p 成立；无超分、无运动模糊/Loupe。
   这决定"能不能看清"。
2. **光标表现**：位图回放、无高清替换/样式/去抖/运动模糊。光标是录屏的主要视觉主体。
3. **编辑能力**：只有入出点，没有中段剪切/分段变速/转写。这决定"几分钟能不能出片"。

录制与包装管线已经接近；上面三件决定它像不像 Screen Studio。

### 12.4 必须补 / 可以后置

**必须补（同类产品底线）**：H.264 导出与分辨率/帧率预设；中段剪切（cuts）+ 分段变速；
光标高清/重绘 + 静止隐藏 + 元数据；手动缩放一等 UX；音频降噪/归一化（可离线）；
窗口录制或窗口跟随的明确策略。

**可以后置**：超分、运动模糊/Loupe、GIF/ProRes、背景图库、设备边框、摄像头抠像/人脸跟随、
字幕/转写、遮罩/敏感数据、点击音效、分享/团队。
