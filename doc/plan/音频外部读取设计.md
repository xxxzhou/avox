# 音频外部读取设计

> 状态:**已实现,5 节待定项待运行时验证**。

## 1. 目标

让外部拿到正在播放的音频数据,**不影响现有推入/播放流程**。`IAudioRender` 大家都在用,直接在它上面扩展。外部可定制**输出格式**与**切片大小**(ASR/STT 友好)。`TranscodeRecorder` 也能用(无设备输出,tap 照常)。

## 2. 约束

推入(`render`)和设备拉出播放各有用途,**不能直接拿原数据**。改为:中间层组合一个 `AudioTap` 对象(自带线程),由它备份、重采样/切片、回调上层(**push**,非 pull)。默认关闭,上层 open 才启动。

## 3. 方案

### 3.1 结构(三层)

```
IAudioRender     公共: volume/aec + openTap/closeTap + IAudioTapOb(onAudioDesc/onFrame)
  ↑
AudioRender      通用中间层: setDesc/render模板方法 + AudioProcess + AudioTap + observer转发
                  render() 里: tap push → process → onDeviceRender(虚函数,默认空)
  ↑
AudioOutput      设备层: onInit/onDeviceRender/onClose + empty/full/getQueueMS/pause/flush/speed
  ↑
WasAudioRender / AndAudioRender / IOSAudioRender

AudioTap (新,AudioRender 的成员对象):
  public RunTask, public AudioReshaper, public Observer<IAudioTapOb>
  成员: RingBuffer<AudioFramePtr> queue(有界,满丢最旧)
```

### 3.2 职责划分

**AudioRender(通用中间层)**:
- `setDesc / render / close` —— 模板方法(初始化 process、分发帧)
- `onAudioProcess` —— process 回调,转发给 onDeviceRender
- `enableAec / disableAec` —— 开关 process
- `desc / frameMs / frameSize / volume` —— 状态字段
- `audioProcess` —— 3A 处理
- `audioTap` —— 备份 + reshape + 回调
- `openTap / closeTap` —— tap 生命周期
- `onDeviceRender` —— **新虚函数,默认空体**(设备 override 推硬件;TranscodeRecorder 不 override → 天然静音)

**AudioOutput(设备层,原 AudioRender 改名)**:
- `onInit / onDeviceRender / onClose` —— 平台钩子(原 onInit/onRender/onClose)
- `empty / full / getQueueMS / pause / flush / speed` —— 设备缓冲/时钟控制
- `setVolume / getVolume` —— 设备音量(WASAPI 有实现)

### 3.3 数据路径

```
音频线程 render(frame,pts):
  ├─ if (tap && tap->bOpen()) tap->push(raw 深拷贝)          // queue 存 raw,满则丢最旧,不阻塞
  ├─ (AEC开) audioProcess->process → onAudioProcess → onDeviceRender
  └─ (AEC关) onDeviceRender(frame)                           // AudioOutput override 推设备;默认空体

tap 线程 onRunTask():
  queue.pop(raw) → AudioReshaper::process(raw)             // 累积 + 重采样到 outDesc
                 → 攒满 frameMs → onProcess()              // 定长块就绪
                 → dispatch(&IAudioTapOb::onFrame, AvoxData, pts)   // 帧仅回调内有效
```

### 3.4 API

- `IAudioRender::openTap(const AudioDesc& outDesc, int32_t frameMs)` —— 配置输出格式 + 切片,启动 tap(lazy 创建对象 + `startTask`)。`outDesc==源` 则不重采样。
- `IAudioRender::closeTap()` —— `stopTask` + 销毁 tap。
- `addAudioTapOb` / `removeAudioTapOb` —— observer 注册(与 open/close 分开:谁听 vs 泵开不开)。
- 典型:`addAudioTapOb(ob) → openTap(16k mono s16, 20ms) → … → closeTap() → removeAudioTapOb(ob)`。

> 命名不用 `channel`(音频里 = 声道,歧义)。想"跟随源格式"传空 `AudioDesc`(`sampleRate=0`);不用 C++ 默认参数——SWIG/napi 取不到正确值(见 `AvoxPlayer.h` 注释)。

### 3.5 TranscodeRecorder 接入

用裸 `AudioRender` 实例(不派生 AudioOutput):tap 照常工作,`onDeviceRender` 默认空体 → 天然静音。无需 NullAudioOutput。

## 4. 关键点

- **默认关闭 = 真零成本**:关闭时 `render()` 只多一个 atomic flag 判断,不做 memcpy、不建对象。
- **音频线程只做 raw 深拷贝 + 入队**(满丢最旧,不阻塞)→ 上层再慢、reshaper 再重都不影响播放。
- **重采样/切片在 tap 线程**(消费侧),复用 `AudioReshaper`(`initConfig`/`process`/`onProcess`),**零新增处理代码**。`outDesc==源` 不建 `FFResample`。
- **帧仅在回调内有效**:上层回调内处理完或复制带走(`onProcess` 后 `curFrame` 会被复用)。
- **丢由 SDK 控制**:tap 把 dequeue 到的每帧都 reshape 后交给上层,不跳帧;丢只发生在 queue 满时(音频线程丢最旧)。
- **组合而非继承**:`AudioRender` 组合 `AudioTap`,设备继承链干净;`AudioTap` 自身多继承 `RunTask + AudioReshaper + Observer`(沿用 `AudioProcess` 范式,三独立基类无菱形)。
- **深拷贝在入队时**:源帧是 `bRef`(引用解码器 buffer,会被复用)。
- **onDeviceRender 默认空体**:TranscodeRecorder / WASM 用裸 AudioRender,tap 照常、设备 no-op。

## 5. 决策与待定

### 已定

- push 模型(tap 线程回调),非上层 pull;不提供 pull。
- queue 有界,满丢最旧;帧仅回调内有效;丢由 SDK 控制。
- 组合 `AudioTap`(`RunTask + AudioReshaper + Observer`);默认关闭、lazy 创建。
- `openTap(outDesc, frameMs)` / `closeTap`;observer 走 `add/removeAudioTapOb`。
- 重采样复用 `AudioReshaper`,跑在 tap 线程;`outDesc==源` 不重采样。
- 单 tap 单格式(多格式以后再泛化成 handle)。
- 三层:IAudioRender → AudioRender(通用)→ AudioOutput(设备);onDeviceRender 默认空体。
- TranscodeRecorder 用裸 AudioRender,本期接入。

### 待定

- **queue 容量**:几帧?约 40ms/帧,~25 帧≈1s。[荐 16~32]
- **openTap 时机**:源格式(`AudioRender::desc`)就绪后才能 init reshaper → openTap 须在播放起来后调。[确认此约束]
- **FFmpeg 关闭时**:openTap 仅支持 `outDesc==src`(不重采样,仅切片)。[确认]

### 6.2 SWIG 绑定(重生,非手改)

跑 SWIG 重生 `swig/{python,csharp,nodejs}/files/*`。

### 6.3 不用改

- **`MediaPlayer`/`AudioTrack`/`IMediaPlayer`/`ISourcePlayer`/`IRtcPlayer`** —— getAudioRender() 返回 IAudioRender*,零改动。
- **`IAudioRender` 现有 volume/aec** —— 不动。
- **`Observer`/`AudioReshaper`/`RingBuffer`** —— 直接复用。

### 6.4 风险点

1. **`AudioTap` 多继承** `RunTask + AudioReshaper + Observer` —— 三独立基类无菱形;dispatch 持锁回调里别 removeAudioTapOb(Observer.hpp:99)。
2. **析构竞态**:closeTap 先 stopTask 等线程退出再销毁,避免回调时上层已析构。
3. **pts 透传**:reshaper 累积时输出块 pts 对齐 frameMs 边界。
4. **WASM**:getDefaultAudioType 返回 none → 无 AudioOutput,tap 不启动;wasm 无音频播放,不构成问题。
5. **平台子类改名量**:onRender→onDeviceRender 是机械替换,但三个平台文件都要改,需逐一验证编译。
