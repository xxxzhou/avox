# 离线超分转码方案 (avox TranscodeRecorder × panvox, Real-ESRGAN)

> 状态: 进行中 · 上次核对: 2026-09-17 · 权威源: -

## 1. 定位

实时超分上限已明(见[实时增强方案调研](实时增强方案调研.md)): Real-ESRGAN iGPU 540P 才 ~15fps,
1080P 实时无望。**画质要求高的场景改走离线**: 用 `createRecorder(true)` 转码链路
解码→GPU 图像处理→编码, 提前出增强片源, 播放时直接放增强后的文件, 不再赶帧。

**决策 (2026-09-17): 离线只走 Real-ESRGAN** (`realesr-general-x4v3`)。
理由: 盲退化训练覆盖压缩+模糊+噪点, 离线三档里效果上限最高; BSD-3-Clause 可商用(见 §2);
`skipFrames=0` 逐帧路径天然适配离线。FSR/Anime4K 保持实时轨使用, 不进离线链路。
超分产品化总盘见 [a11-superres-frc](../backlog/a11-superres-frc.md), 本方案是其离线支线。

## 3. 现状盘点 (2026-09-17 摸底)

**已具备, 不用新写**:

- `TranscodeRecorder` (`src/avox/muxer/TranscodeRecorder.cpp`) 全链路通:
  解码(软/硬可选) → 离屏 `SurfaceRenderVk` → `getCpuFrame` 回读 → RawMuxer 编码;
  onProgress/onComplete/seek 齐全; 源管线无墙钟节拍, 5 帧环形队列反压,
  **自由跑速天然支持超实时** (消费速度=GPU处理+编码速度)
- Real-ESRGAN 层就绪: `VkQEnhanceLayer` (`src/avox_vulkan/quality/VkQEnhanceLayer.cpp`),
  推理分辨率 = 输出/scale (如 2x 档 1080p → 推理 540p, 全帧单次推理无需 tile);
  后端自动降级 OV GPU → OV CPU → ORT CPU; `skipFrames=0` 即逐帧
  (`VkQEnhanceLayer.cpp:342`)
- **模型权重已入库仓并接通构建 (2026-09-17)**: `../avc_library/assets/models/quality/`
  预置 `realesrgan-general-x4v3.onnx` (fp32, 溯源/许可见库仓 README);
  `cmake/FindRealEsrgan.cmake` 按 libsmb2/libtorrent 式可选定位 (AVOX_EXTERNAL_LIBRARY_DIR
  → `../avc_library` → 工程内兜底), 命中后经 `QUALITY_MODELS` 既有通道随 assets/models
  拷进运行目录, 运行期 `getModelFilePath("quality/realesrgan-general-x4v3.onnx")` 解析;
  缺权重不致命 (宿主注入 modelsRoot 仍可用); panvox 随包即用, 免按需下载
- `QualityEnhanceParamet` 已进 SWIG 绑定 (model/outputMode/skipFrames)
- panvox 已有同款离线 worker 先例与 job 模型: `pvx_thumb` / `pvx_aisub`, 均基于
  `createRecorder(true)` — 本方案的 `pvx_enhance` 直接镜像该模型
  (`../panvox/native/include/panvox_c_api.h`)
- avox_cmd `record -tc` 命令已是转码录制的 CLI 参照 (`src/avox_cmd/commands/CmdRecord.cpp`)

**缺口/坑 (需修)**:

| # | 问题 | 位置 | 影响 |
|---|------|------|------|
| G1 | 色彩空间硬编码 `bt601+full`, 不随源 | `TranscodeRecorder.cpp:163` | 电影片源多为 bt709/limited, 直出偏色; 离线产品不可接受 |
| G2 | 离屏空输出 (outputUrl=null) 崩, 两条 panvox worker 靠临时 mp4 绕过 | panvox_c_api.h 注释; `TranscodeRecorder.cpp` bNoOutput 分支 | 需复核是否已修; 未修则修 (非本方案阻塞) |
| G3 | 降噪强度缺失: 官方 general-x4v3 支持 `-dn` 0~1 (低码率源降噪/清晰源防过糊), 我们的 ONNX 链路未支持 | `VkQEnhanceLayer` / `QualityEnhanceParamet` | 核心画质旋钮, 放开设置项的前提 |
| G4 | 音频一律重编 AAC, 默认 32kHz/s16/立体声 | `TranscodeRecorder` 构造 | 产品用须显式设 48k; 音频直拷列为优化项 |
| G5 | 转码链路无超实时开关: IO 层 `setFastRead(true)` 仅 StreamRecorder 调用 | `StreamRecorder.cpp:67` | 本地文件 demux 本身自由读, 先实测; 不达预期再补 |

## 4. 设置项清单 (尽可能放出)

三层放齐: SDK 参数 → shim API → 产品 UI。标 ✅=已有直放, 🔨=需新增。

### SDK 层

| 设置项 | 现状 | 动作 |
|---|---|---|
| 输出倍率 1x(restore)/2x/4x/Auto (`outputMode`) | ✅ `QualityEnhanceParamet` | 直放; Auto= ≥1080p→2x, <1080p→4x |
| 降噪强度 0~1 (`denoiseStrength`) | 🔨 G3 | 复刻官方 `-dn`: P0 先验证机制(双权重插值或带辅助输入重导出 ONNX), 再定参数 |
| 模型枚举 (`model`) | ✅ 仅 x4v3 | 保留枚举位; animevideov3(动漫第二模型, 同仓 BSD)列开放项 |
| 逐帧/抽帧 (`skipFrames`) | ✅ | 离线恒 0 不对外; 保留实时轨用 |
| 视频编码 h264/h265 (`setVideoCodec`) | ✅ | 放出, 默认 h264 |
| 硬编/软编 (`setHardEncode` / rec.hard.encode) | ✅ | 放出, 默认硬编 |
| 硬解/软解 (rec.hard.decode) | ✅ | 放出, 默认软解(画质优先); 4K HEVC 源建议硬解 |
| 输出分辨率声明 (`setVideoDesc`+`enableSizeChange`) | ✅ | shim 按倍率自动算, 不直接暴露 |
| 音频输出格式 (`setAudioDesc`) | ✅ | shim 默认 48kHz AAC(勿用 32k 默认值); 直拷 P2 |
| 色彩空间透传 | 🔨 G1 | 修为自动透传, 不对外 |
| 推理后端/设备 | ✅ 自动 OV GPU→CPU→ORT CPU | 不对外; 手动选设备列开放项 |
| tile 分块 | 不需要 | 推理分辨率已降采样, 全帧单次即可 |

### shim 层 (`pvx_enhance_start` 参数)

| 参数 | 默认 | 说明 |
|---|---|---|
| `url` / `work_dir` / `out_path` | — | 同 pvx_aisub 口径 |
| `scale` | auto | restore/2x/4x/auto |
| `denoise` | 0.5 | 0~1, G3 落地后生效 |
| `codec` / `hard_encode` | h264 / true | 成品编码 |
| `stop_at_ms` | 0=整片 | 🔨 试转预览: 进度到位调 close, 「先转 5 分钟看效果」 |
| 回调 | — | stage/pct 进度 + 耗时秒 + 最终码; exactly-once 契约同 pvx_aisub |

### 产品层 (Dart 设置页/发起对话框)

- 倍率/降噪/编码收进「高级」, 默认 Auto 发起, 零配置可用
- **发起前耗时预估**: 源分辨率 × 倍率 × 设备档(集显/独显) → 直接展示「预计 X 小时」
- 4x 只对 <720p 源开放; ≥1080p 源输出封顶 4K 并提示 (防 8K 巨文件)
- 模型按需下载 (models root `quality/`, 带下载进度) + BSD-3-Clause 声明文件随包
- 试转预览入口 (转前 5 分钟 → 确认效果 → 再整片)

## 6. 验收

1. 独显 1080p 2x 档 ≥1× 实时; 集显 1x restore 档全片过夜可完成
   (540ms/帧 → 2x 约 19h, 131ms/帧 → 1x 约 5h, 按 90min/24fps 估)
2. 降噪强度 0/1 两端出图可辨: 0 档清晰源不过糊, 1 档高噪源噪点去净
3. bt709 片源直出无偏色 (与源并排对比)
4. panvox 端到端: 选片→耗时预估→增强(或 5min 试转)→进度→成品可播,
   取消/失败不产生坏文件

## 7. 风险与开放问题

- iGPU 2x 档天级耗时是现实, 产品上必须把耗时预估摆在发起前 + 主推试转预览, 防预期崩塌
- `skipFrames=0` 逐帧路径实时轨从未主跑, 层内异步时序(mutex/cv 双缓冲)需 T1 实测确认
- G3 降噪强度的 ONNX 链适配是未知数(官方 -dn 的权重组织方式待查证), T4 先验证再定
  产品口径; 若短期不通, 先放其余设置项, 降噪固定默认值
- 4x 档分辨率与文件体积爆炸风险 → 产品层 4K 封顶硬限制
- 内封软字幕轨转码即丢, 外挂不受影响 — 产品文案需说明
- 模型分发合规: BSD 版权声明+许可文本随分发, ONNX 转换件来源与转换脚本留档
