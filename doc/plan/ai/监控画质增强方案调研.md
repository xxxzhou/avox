# 监控画质增强方案调研

> 监控终端渲染端,N 多厂商摄像头,画面标称 1080P/2K 但观感只有 ~640P,根因不确定(压缩 / 光学 / 假分辨率 / 噪点 / ISP 差,每家不一样)。约束:集显实时、不训练、通用覆盖、要 AI、C++/Vulkan 集成。

## 1. 核心结论

**没有单一现成方案能同时满足下面四条**,这是图像恢复领域的结构性现实:

```
集显实时 1080P  +  不训练(现成权重)  +  通用覆盖多退化  +  监控真实场景对口
```

- 学术 All-in-One 模型(PromptIR / AdaIR / DiffBIR)10-100M+,集显跑不动,且训练退化不含视频压缩——**排除**。
- 监控专用公开数据集/权重几乎为零——安防厂商画质增强都是闭源商业方案。
- 真正能落地的是 **Real-ESRGAN 系轻量盲退化变体 + ONNX/DirectML 集成**,辅以压缩专用 PowerVQE STDF,必要时传统 ISP 兜底。

**最佳单方案**:`Real-ESRGAN general-x4v3`(1.21M 参数,盲退化训练覆盖压缩+模糊+噪点),经 ONNX+DirectML 集成(复用 avox_onnx,不改核心 Vulkan 设备),集显降采样(540P→1080P)或抽帧近实时。

## 2. 根因谱系与对症

| 根因 | 放大看特征 | 对症任务 | 代表方案 | 能否救 |
|---|---|---|---|---|
| **H.264/H.265 高 QP 压缩** | 8×8/16×16 块网格、蚊噪、振铃 | 去压缩伪影 | PowerVQE STDF/MFQEv2 | ✅ |
| **光学镜头差/跑焦** | 无网格,边缘发软晕开 | 去模糊 | RealBasicVSR、Real-ESRGAN | ✅ |
| **ISP 过度平滑** | 像抹凡士林,细节被压 | 学习型恢复 | Real-ESRGAN general | ✅ |
| **高 ISO 噪点(夜间)** | 暗部满屏噪点 | 去噪 | FastDVDnet、CBDNet | ✅ |
| **假分辨率(传感器低清拉伸)** | 无块无噪无晕,但无真细节,油画感 | 超分"脑补" | Real-ESRGAN | ⚠️ 只能脑补 |

> **盲退化恢复模型**(Real-ESRGAN/RealBasicVSR)对"根因不确定"是对症的——学的是"退化→清晰"通用映射,不挑根因。纯锐化(unsharp mask)会无脑放大噪声/块,方向反了。选型看 blind SR,不看 PSNR 排行。

## 4. 重点方案详评

### 4.1 Real-ESRGAN general-x4v3 —— 首选

之前认为 Real-ESRGAN 集显不行——**那是 x4plus(16.7M)**。`general-x4v3` 是官方轻量通用变体:

- **1.21M 参数 / 4.66MB(float)、1.25MB(int8)**(Qualcomm AI Hub 实测),比 x4plus 轻一个数量级。
- **盲退化训练**:OTF 二阶退化(模糊+下采样+噪声+JPEG 压缩+sinc),覆盖监控多个根因。
- **`-dn` 旋钮**可在线调降噪强度,适配不同厂商摄像头。
- 权重直链:`github.com/xinntao/Real-ESRGAN/releases/download/v0.2.5.0/realesr-general-x4v3.pth`
- **当天可验证**:`realesrgan-ncnn-vulkan.exe -i 监控帧.jpg -o out.png -n realesr-general-x4v3 -s 1 -v`

坑:训练 patch 128×128,1080P 要 tile 推理;通用盲退化≠每路最优;对车牌/人脸可能虚构细节,安防取证慎用。

### 4.2 PowerVQE STDF-Y —— 压缩视频对口最强

`ryanxingql/powervqe`(Apache 2.0),专为 H.264/H.265 训练,数据集 LDVv2 用 HM 16.20 QP=37 压缩,跟监控码流一致。时序模型(利用相邻帧),正好用上监控静态场景多的优势。STDF-Y(Y 通道)最轻,集显可行。坑:DCN(可变形卷积)转 ONNX→DirectML 算子兼容性需实测。

### 4.3 RealBasicVSR —— 综合退化对口,但偏重

CVPR 2022,~3.3M,同时处理压缩+模糊+噪点。坑:NTU S-Lab License 商用需确认;光流子模块转 ONNX 有算子兼容问题;3.3M+双向传播集显 1080P 实时困难,需降采样到 540P。

### 4.4 传统 ISP(双边+时域降噪+FSR)—— 零依赖兜底

Vulkan compute shader,集显全帧 30fps,对症压缩块+静态降噪。零权重、零训练、立即可做、所有厂商不崩。天花板低(不脑补细节),但作为实时兜底层非常稳。avox 已有 `VkBilateralLayer` + FSR plan 可直接落。

## 5. Top 推荐

### 🥇 主方案:Real-ESRGAN general-x4v3 + ONNX(DirectML)

模型选 `general-x4v3`(1.21M / 盲退化通用 / 现成权重)。**集成走 ONNX+DirectML,不走 ncnn-Vulkan**:ncnn 需改 avox 核心 VkDevice 扩展列表(推理扩展 fp16/push descriptor 等一个没启用)、ncnn::VkMat 与 avox VkImage 非零拷贝(每帧 2 次 GPU 拷贝+1 次同步)、DCN 算子 ncnn 不支持(PowerVQE 上不了)、引入全新依赖;而 ONNX+DirectML 复用 avox_onnx 基建(OnnxSessionCache/资产加载/SWIG 绑定全现成)、只加一个 `AppendExecutionProvider_DML` 分支、跨平台统一(DirectML/NNAPI/CoreML)、OCR/inpaint 已走"取帧→CPU→推理→回写"路径可直接复用。**ncnn 仅用于 P0 效果快速验证**(有现成二进制),确认成立后转 ONNX 集成。ONNX 性能不确定性(DirectML 开销)需 P0 实测,若比 ncnn 慢 >3× 再重新评估。

### 🥈 增强方案:PowerVQE STDF-Y(压缩主因时叠加)

某些厂商压缩是主因(块效应明显),在 general-x4v3 前叠一层 STDF-Y。Apache 2.0,有时序,对口 H.264/H.265。需解决 DCN 算子转换。

### 🥉 兜底方案:双边+FSR(老集显/全帧实时刚需)

最老最弱的集显也跑得动,全帧 30fps,所有厂商不崩。作为 AI 增强跑不动的硬件 fallback。

## 6. 落地执行计划

> 每阶段含【动作】【验收】【决策门】。决策门不通过则不进下一阶段。

### P0(1-2 周):基线验证——零 C++ 代码

| # | 动作 | 验收 | 产出 |
|---|---|---|---|
| P0.1 | 下载 `Real-ESRGAN-ncnn-vulkan` 二进制,目标 iGPU 跑 `general-x4v3 -s 1 -v`,测 1080P/540P/不同 tile 的 fps | fps 表(1080P/540P/tile=0/128/256) |
| P0.2 | 收集 N 家厂商代表性画面(日间/夜间/低码率/假分辨率各 ≥3 帧),建评测集 | 评测集目录就绪,含分类标注 |
| P0.3 | ncnn 二进制跑评测集,主观评分(1-5:1=更差,3=无感,5=明显改善) | 每类评分,整体均分 ≥3.5 |
| P0.4 | `general-x4v3.pth` 转 ONNX,`pip install onnxruntime-directml` 同一集显测 fps | DirectML fps 表,与 ncnn 对比 |
| P0.5 | PowerVQE STDF-Y Python 版,对比压缩块消除效果 | STDF-Y 压缩画面评分 |

**决策门 P0→P1**:
- ✅ 540P ≥15fps **且** 均分 ≥3.5 → 进入 P1(ONNX 集成)
- ⚠️ 540P 10-15fps 或均分 3.0-3.5 → 降级:抽帧或换 animevideov3
- ❌ 540P <10fps 或均分 <3.0 → 放弃 AI,走 P2 兜底(双边+FSR)
- ❌ DirectML 比 ncnn 慢 >3× → 重新评估 ncnn 集成

### P1(4-8 周):集成主方案——ONNX+DirectML 进 avox

**前置**:P0 决策门通过。

| # | 动作 | 涉及文件 | 验收 |
|---|---|---|---|
| P1.1 | `avox_onnx` 加 DirectML EP:`ONNXRuntime.cpp` 的 `useGPU` 分支加 `#ifdef _WIN32` → `AppendExecutionProvider_DML` | `plugins/avox_onnx/ONNXRuntime.cpp` | DML EP 编译通过,OnnxSessionCache 可创建 DML session |
| P1.2 | `general-x4v3.onnx` 打包为资产,加入 `assets_manifest.json` | `script/assets_manifest.json` | 模型随构建部署到 install 目录 |
| P1.3 | 新建 `VkQualityEnhanceLayer`(VkGroupLayer):取帧→CPU→ONNX 推理→回写 VkImage | `src/avox_vulkan/` 新文件 | 单帧增强可跑,无崩溃 |
| P1.4 | API:加 `ISurfaceRender::enableQualityEnhance(...)` / `disableQualityEnhance()`,参数含模型/降噪强度/处理分辨率 | `src/avox/AvoxLayer.h` + SWIG | C#/Java/Node 可调用 |
| P1.5 | 接入 `VkVideoRender::vaildAndInitGraph()`:YUV2RGBA 后、blend 前插入节点 | `src/avox_vulkan/VkVideoRender.cpp` | 开启正常,关闭零开销 |
| P1.6 | 性能调优:降采样(1080P→540P→FSR 回 1080P)、抽帧(静态场景每 N 帧增强一次) | `VkQualityEnhanceLayer` | 540P ≥15fps,1080P 抽帧 ≥10fps |

**决策门 P1→P2**:
- ✅ 540P ≥15fps,效果可接受 → P1 完成
- ⚠️ 540P 10-15fps → INT8 量化/抽帧/降分辨率
- ❌ 集显跑不动 → 回退 P2 兜底,AI 增强标记"独显/未来"

### P2(按需):叠加增强层 + 兜底

| # | 动作 | 前置 | 验收 |
|---|---|---|---|
| P2.1 | 压缩主因:接 PowerVQE STDF-Y(需先验证 DCN 在 DirectML 兼容性) | P1 + DCN 验证 | 压缩块画面改善 |
| P2.2 | 综合退化:接 RealBasicVSR(540P,需确认商用许可) | P1 + 许可确认 | 综合退化画面改善 |
| P2.3 | 老集显兜底:双边+FSR(Vulkan shader,集显全帧 30fps) | 无(独立) | 1080P ≥30fps,不崩 |
| P2.4 | SRMD(条件化去噪,`-n` 可调噪声等级)作为可调降噪备选 | P0 验证 SRMD | 噪声场景可调改善 |

### 性能预期(集显)

| 方案 | 处理分辨率 | 预期 fps | 备注 |
|---|---|---|---|
| general-x4v3 ONNX+DML | 540P→1080P | 10-25 | DirectML 开销待 P0.4 实测 |
| general-x4v3 ncnn | 540P→1080P | 15-30 | P0.1 实测基准 |
| general-x4v3 ONNX+DML | 1080P 原尺寸 | 3-8 | 需抽帧 |
| STDF-Y | 540P | 8-15 | DCN 优化后 |
| 双边+FSR | 1080P | 30+ | 全帧实时,零 AI |

**集显 1080P 全帧 30fps 对深度模型基本不可能**,必须降采样或抽帧。监控静态多让"抽帧+时序"很自然。

## 7. 数据集与生态

- **监控专用配对数据集:空白**。SCFace/WIDER Face/PEViD 带 surveillance 名字的都是检测/识别用,非画质增强。
- **真实退化数据集**(稀缺,偏消费级):RealSR、DRealSR、VideoLQ(RealBasicVSR 附带)、SIDD(手机噪声)。
- **合成退化**(行业主力):Real-ESRGAN 二阶退化是事实标准,意外覆盖监控退化。DIV2K / Vimeo-90K / REDS 是训练基底。
- **压缩视频数据集**:PowerVQE 的 LDVv2 / MFQEv2,AIM 2024 VSR-QA。
- **端侧挑战赛**(Mobile AI / NTIRE ESR):大多用 DIV2K(bicubic 退化)训练,**只放大不恢复**,对压缩块/光学模糊几乎无效;"real-time"指 RTX 3090 上 <33ms,不等于集显实时。

## 8. 关键坑

1. **集显 1080P 全帧实时**对深度模型不可能——必须降采样/抽帧/独显。
2. **DCN 算子**:STDF/BasicVSR++ 依赖,转 ONNX→DirectML 兼容性需实测,不行退单帧版。
3. **animevideov3 在真实监控过锐**:训练偏动漫,需调参或用 general-x4v3。
4. **Real-ESRGAN 虚构细节**:车牌/人脸身份识别可能脑补错误,安防取证慎用。
5. **RealBasicVSR 商用许可**:NTU S-Lab License,需法律确认。
6. **ONNX+DirectML 性能未知**:DirectML 开销可能比 ncnn-Vulkan 慢,P0.4 必须实测;若慢 >3× 需重新评估 ncnn 集成(接受改 VkDevice 扩展的成本)。
7. **NanoVSR(arxiv 2607.10495,2026.7)**:边缘实时 VSR,开源状态待验证,若开源可能是强候选。

## 附:决策路径速查

```
画面主要是哪种糊?
├─ 压缩块(网格/蚊噪) → PowerVQE STDF-Y(对口)+ Real-ESRGAN general(通用)
├─ 光学糊(边缘晕)   → RealBasicVSR / Real-ESRGAN general

├─ 假分辨率(油画感) → Real-ESRGAN general(脑补,上限有限)

```
