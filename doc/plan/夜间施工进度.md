## A-7 AI 字幕识别缺行: 根因与修复 (09-18 02:00, R3)

用户直接点名「字幕识别比正常少很多」(即 09-17 backlog A-7 缺陷), 指令=找到并解决,
故超出 T5「不动代码」勘察范围, 完成了全链修复。

**根因**: aisub 离线链路 (panvox shim `pvx_aisub_start` → TranscodeRecorder 离屏解码
→ AudioTap → SherpaAudioStt) 里解码不限速, 而 STT 消费链两级队列满时均「丢最旧」
(SherpaAudioStt frameQueue 100×100ms + AudioTap 32×100ms), SenseVoice CPU 推理速度
追不上解码 → 持续大量丢音频 → cue 骤减 (23.6min 片 123 条)。日志里 `PTS jump` 恒为正
就是丢帧的直接证据; 关停时 eos 哨兵帧带墙上时钟 PTS 还会触发重校准, 把末段 cue
时间戳污染到 epoch 级 (09-17 记录的两个旁证全部对上)。

**修复** (avox `404be3f` + panvox `0c30f3e`, 构建互依须同部署):
- 引擎: 新增可选能力接口 `IAudioSttFeedControl`(独立接口不动 IAudioStt vtable) +
  导出 `setAudioSttFeedBlocking` / `setAudioRenderTapBlock`(dynamic_cast 探测, 旧插件
  兼容); SherpaAudioStt 阻塞喂料(满则 enqueueWait 反压到解码线程, stop 先 setClose
  释放生产者, 收尾 drain 忽略 bClose 零丢尾帧); eos 帧不参与 PTS 重校准;
  `[stt-metrics] received/dropped_frames/recalibrations` 计量埋点
- shim: aisub_worker 开两级反压; `PANVOX_AISUB_NOBACKPRESSURE=1` 回退旧行为(A/B 用);
  失败/取消路径补删临时 mp4(修泄漏); 时间戳越界段兜底不入 SRT; trace 加对账计量
- 实时口播链路 (SubtitleView/CmdVoice) 不受影响: feedBlocking 默认 false, 行为不变

**A/B 实测** (SAPI 合成 250s 编号句 48k wav, 同机同片, 产物在 panvox
`build_aisub_test/`): 旧行为实收 91s/丢 158s(63%)/29 次重校准/32 cues;
修复后实收 249s(100%)/dropped=0/重校准 0/66 cues/无 >5s 空洞;
耗时 14.2s vs 12.5s (≈零成本, STT 本就是瓶颈)。`ctest` 2/2 绿。

  processAudio 在 `!muxer` 处提前 return, 视频 bNoOutput 又不入编码队列,
  `updateProgress()` 两条链都走不到 → progress 恒 0。
  **已修**: `TranscodeRecorder::onVideoFrame` 在 bNoOutput return 前补
  `updateProgress()` (视频帧是所有模式共有的推进源; 自身有 nowPts 变化门阀,
  与 processVideo 的调用不会重复派发)。提交 `13cca10`。
  实证: 空输出复跑 `media=9133ms` (修复前恒 0), speed 42x 正常。
- `frames=0` — **增强+有输出模式结构性必现** (样例唯一模式, 100% 复现):
  增强路径 `setOffSurface(YuvType::other)` → `disableYuvOut` → `bCpuOut()=false`,
  `SurfaceRenderVk::onRenderOut` 只在 bCpuOut 分支派发 `ISurfaceRenderOb::onFrame`;
  而 image 分支设计为零拷贝直投用户缓冲、**不设 observer**
  (VkVideoRender.cpp:682 注释「不设 observer, 用 setOutputBuffer 直投」)。
  实证: 有输出复跑 `media=6033ms frames=0`; 空输出模式 frames=274 正常
  (该模式保留 yuv-out 派发)。
- **frames 修复方案 (有决策点, 未动代码, 留晨会)**:
  - 方案 ①: `onRenderOut` 增补 image 分支派发 (bEnableImage && imageOutBuffer 时
    dispatch 该 buffer, YuvType::other)。约 3 行; 代价: 建图期 dummy 渲染帧会 +1 计数
    (千分位噪声, 可文档化), 且给「image 分支不回调」的隐式契约开了口子
    (现无其他使用方, 实际风险低)。**建议采纳**。

    样例改 override。无 dummy 噪声, 但动公共 ABI + SWIG 四语言同步, 成本高。
  - 方案 ③: 不修引擎, 样例 fps 改由 media 增量推算 (失真, 不建议)。
