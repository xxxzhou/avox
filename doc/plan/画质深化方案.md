排位理由(按「用户能不能感知」, 不按工程完整性):

1. **① 第一**: HDR→SDR 是付费人群在非 HDR 屏的主路径, 且五域里只有它有过被用户抓到的可见缺陷
   (ACES 偏亮 1.6~2.3×、DV P5 偏暗, 7c21ed7/2547463 记录); 同时是 2B(HDR10+)逐窗的硬前置。
2. **③ 第二**: Apple 硬件无透传、5.1 源下混双声道把 FC 压 -3dB 是具体且尖锐的痛点; 与 a08 同窗零额外
   排期成本。「音量忽大忽小(片源间)」已被默认开启的 R128 均衡覆盖, DRC/soxr 缓。
3. **② 第三(闸已跑=弱命中)**: 数值闸(§3 T0)证实台阶存在, 但量级=8bit 输出固有水平(相邻码对比度与曲线
   无关), dither 收益属**通用 1~2 有效位改善、非 HDR 特有缺陷修复** —— 维持「顺手做、默认关、不宣传」,
   不升级为必修。
4. **④ 缓**: 色度双线性只是把 VK/DX11 拉齐到 Metal 现有水准(正确性对齐), 不产生新能力; location/scaler
   同理, 后置。
5. **护城河不在本稿**: 真正的差异化是 2A(DV P7 FEL)/2B(HDR10+ 逐窗)两块硬骨头(§0 待立卡); 本稿五项
   本质是「把已有体验磨干净」。**若本稿任一项与 2A/2B 争资源, 让位 2A/2B。**
6. **相邻卡不重复**: 2D 刷新率/AV 校准在 [a13](backlog/a13-refresh-rate.md)(judder 对发烧友的可感知度
   高于 dither, 但归 a13 不归本稿)。

### 1.5 审计结论(2026-10-12, 双 agent 只读)

- **现状比计划描述完善**: tone map 已拿系统/VLC 三方对照标定过(7c21ed7 记录; 锚点基线见 avox-test
  `lib/hdr_anchor.py`); Metal 色度已是双线性。
  ⚠ **订正(2026-10-12 查证源码/官方文档)**: 原稿写「三腿 bilinear 与业界默认同级(mpv/VLC 默认同样
  bilinear)」——**不成立**。实况: mpv **v0.37.0(2023-11-21)起**默认 `scale=lanczos` 且 `cscale` 未设时
  **继承 scale** ⇒ 现代 mpv 色度是 **lanczos**(≤v0.36.0 才是 bilinear, 今仅 `[fast]` profile 用);
  libplacebo `pl_render_default_params` 默认 `upscaler=lanczos`(未设 `plane_upscaler` ⇒ 色度同 lanczos);
  FFmpeg `swscale` 默认 **bicubic**(`sws_flags`/`sws_getContext(flags=0)`); VLC **全部实际显示腿都是双线性**
  (3.x/4.x 一致: GL/GLES 与 macOS 共用腿 = `GL_TEXTURE_MIN/MAG_FILTER=GL_LINEAR`; Windows D3D11 =
  `D3D11_FILTER_MIN_MAG_LINEAR_MIP_POINT`, 另一个 POINT sampler 只用于越界边界像素), 仅**软件缩放腿**
  (`swscale-mode=2`)是 bicubic, VLC4 的可选 libplacebo 腿是 lanczos。
  ⇒ 一句话: **VLC = 双线性(全显示腿); mpv 现代 = lanczos**。所以"双线性"有 VLC 全腿背书, 但**不是
  现代 mpv 的做法**; ④ T1 选双线性的理由**只有一条是硬的: 跨腿一致性**(Metal 腿既是双线性, 就对它对齐)。
  ⚠ **再订正(2026-10-12 实测)**: 也不成立的说法是「双线性比最近邻"更准"」。本机解析+实图实测: 只有
  **色度带限于色度 Nyquist 以内的内容**(自然/实拍: 低频正弦 双线性 21.7dB vs 最近邻 14.0dB; 线性斜坡
  82.5 vs 55.4)双线性误差确实更低; **色度含高于 Nyquist 细节的内容**(图形/彩条/硬彩边/字幕: 实测最近邻
  72.9dB vs 双线性 38.8dB; 近 Nyquist 正弦 4.8 vs 2.1)**最近邻 MSE 反而更低** —— 因为它忠实保留 2×2
  块均值, 而任何插值都会把能量摊到邻块。⇒ 本质: **4:2:0 编码先低通再抽样, 色度高频已丢; "取周边多个算
  一个"不是恢复信息, 只是换一种重建/换误差分布**。双线性的真实收益是**伪影类型**: 最近邻留下 2 像素一格的
  **块状阶梯**(平滑色度区=块状/带状, 斜彩边=锯齿), 双线性把它换成"硬彩边软 ~1 像素"; "块状比轻软更难看"
  是**业界取舍**(故主流底线=双线性), 不是可证的 MSE 优势。
  **(图像 MSE 表带已知污染)**: 参考真值取自行解码帧(其色度已被解码器上采样过)+色度位置未知(见 §5 T2),
  故上列图像数字只作方向参考; 可信的是解析信号那两条 + 下表。
  **滤波器代价实测(半分辨率色度干净台阶 128→200, 单位=色度码)**:
  | 重建 | 过渡像素 | 过冲(振铃) |
  |---|---|---|
  | 最近邻 | 0(硬台阶=块状) | 0 |
  | 双线性 | 2 | 0 |
  | bicubic(Catmull-Rom) | 2 | 5.1 |
  | lanczos3 | 6 | 7.4 |
  ⇒ 高阶滤波的收益在**带限内容**(频响更接近理想, 实测 MSE 全面优于双线性), 代价在**硬彩边**(振铃/halo)。
  ⇒ 要"两种内容都不吃亏", 唯一确定的方向是**T3 质量档(bicubic/lanczos3 + 抗振铃)且内容自适应**,
  不是在最近邻/双线性之间选。
  响度均衡(EBU R128)产品**默认已开**(`MediaPlayer.hpp:143`),
  「音量忽大忽小(片源间)」主诉已覆盖 —— ③ 的 DRC 是**片内**动态范围压缩, 属功能增量非补漏。
- **HDR/DV 人群主观看模式=直通链, 而直通链整段裁图像处理**(`VkVideoRender.cpp:556` bPt 全裁; HDR 文档
  「直通不做图像处理」)→ deband/LUT/scaler/色度等增量只有**链F** 能触达他们 (mac 链F 不存在, 见 HDR
  文档 G7/G10), 「感知面」勿高估; 各节验收时应按「链F 或降 SDR 档」的真实路径取样。
- **可感知度排序(同日重排 §1)**: ① 首要 → ③ 次之 → ② 先测后定(§3 T0 闸) → ④/⑤ 缓; **deband 划掉**。
- **被低估**: ④ chroma(location 需 FFmpeg 腿新通道; 采样改动 6-7 个 shader); ① 的工程面(EGL 双份
  shader 是隐藏第二现场); ⑤ 若走 16F 3D 纹理(全仓零 3D 纹理基建)。
- **被高估**: ② dither 覆盖面(纯 SDR 是 8bit 进 8bit 出, 无收益); ① 的「sdrWhite 跟系统」——现曲线里
  `sdrWhite` 是**膝点形状参数**而非 100nit 锚, 单独接系统值(常见 200~500nit)会把画面整体压暗
  (1000nit 源的 100nit 块 181→约127 码推算), **必须与换曲线同批**。
- **默认档纪律(全案)**: 凡「每帧改变像素」的新增(dither / chroma location / sdrWhite 探测)一律默认关或
  保守档, 否则撞「SDR 片零变化」与 HDR 文档 R1/R2 真机验收判据(「肉眼无 banding 差」/高光顶出)。

## 2. ① Tone mapping 参数化 + 标准算法

## 3. ② dither(先测后定) + deband(划掉)

### 出口判据(前置: T0 实测闸通过; 不过闸则本项不投入)

1. 闸判据: HDR10 暗场/高光渐变素材走现管线 tone map 出 8bit, 梯度区码值台阶计数 + 肉眼判定 ——
   有色带才立项; 无色带则降级为记录页(保留本文供重开), 预算转 ①。

3. 16bit 渐变合成素材: 肉眼看不出色带改善前置状态 + 数值检测(台阶计数下降)通过。
4. 直通链(链A)/直通态零变化。

### 现状(代码落点)

  8bit 量化 banding 为已知代价, 并写「可选 dither 缓解, 另批评估」)。
- **8bit 量化终点实态(审计)**: 纯 SDR 播放全程 8bit 进出, **dither 无收益**(源已带色带, 加噪不还原创码);
  真正新增量化只有两处 —— HDR/DV→SDR 的 tone map 输出, 与链F 的 PQ 码升样。覆盖面比原计划小。

## 4. ③ 音频补链(对白增强 / 下混系数 / 夜间 DRC / 重采样质量)

### 出口判据

4. swr 质量档可设(soxr 评估), **不破坏既有 desc 全等短路**。
