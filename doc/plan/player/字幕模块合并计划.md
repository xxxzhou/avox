# 字幕模块合并计划(统一 canvas 通道: 一个视图 + 一条渲染路径)

> 2026-09-15 规划,同日两轮修订。
> v1:文本全迁 libass、font layer 退役——ASR 跨 DLL 喂 chunk 有事件覆盖
> 风险,且无插件时文本字幕全灭。
> v2:统一视图 + 双渲染后端(font layer 管 SRT/ASR,canvas 管 ASS/PGS)——
> 改动最小,但两条渲染路径并存。
> **v3(主方案)**:统一 canvas 通道——所有字幕(含 SRT/ASR 文本)都产出
> RGBA8 bbox canvas,经同一个 `ICanvasLayer` sourceOver 混合出帧;font layer
> 的 R8 canvas + drawFontBlend 从字幕路径退役。差别只剩"谁画 canvas":
> libass(样式轨)、PgsDecoder(位图)、新增核心文本光栅化器(纯文本)。
> 同日定稿追加两项:①外挂唯一入口命名 `loadSubtitle`(接口不出现具体格式
> 名,内部分流);**②删除字幕侧翻译链路**(端上小模型翻译质量不行,产品
> 侧翻译由应用层 AI 管线负责;范围界定见 D5)。
> 背景:仓库并存两套字幕链路(旧 SRT/ASR + 新 ASS/PGS),同一 .srt 外挂
> 文件有两个公共 API 入口、两种渲染路径。

## 1. 现状盘点(两套链路)

| | 旧链路(2026-09-03, f5ecf57) | 新链路(2026-09-13~15) |
|---|---|---|
| 视图 | `SubtitleView`(ISurfaceRenderOb) | `AssOverlayView`(ISurfaceRenderOb) |
| 内容源 | `SubtitleFile`(SrtParser, 外挂 .srt)、`SubtitleAsr`(ASR+翻译) | 内封 ASS/SSA/SRT 轨 chunk、外挂 .ass/.srt(插件内转 ASS)、PGS(`PgsDecoder` → AssCanvas) |
| 渲染 | FreeType 字形 → `VkFontLayer` R8 alpha canvas + 全局单色 → drawFontBlend | libass/pgssub → RGBA8 canvas → `VkCanvasLayer` + sourceOver |
| 公共 API | `getSubtitle()->loadSrt()/enableAsr()/翻译` | `setSubtitleTrack()/loadSubtitleFile()/subtitleTrackInfo/Count` |
| 时钟 | AVTrack 同步 `subtitleView->getClock()`(`AVTrack.cpp:149`) | 同函数再同步 `assOverlayView->getClock()`(`AVTrack.cpp:154`) |
| 样式 | `IFontLayer::setFont/setColor/setScale` 能力齐备(FreetypeExport.h:26),但 SubtitleView 写死 simhei 40 | libass 全量样式/排版 |

### 痛点(合并动机)

1. **同一 .srt 两个入口两条路**:`getSubtitle()->loadSrt()`(无样式)与
   `loadSubtitleFile()`(libass 全样式),调用方不知道该用哪个。
2. **跨后端无互斥**:两个视图同挂一个 windowRender。font 层内部已有单槽
   仲裁(`SubtitleView::update` ASR 优先、其次文件),但 font 层不感知
   canvas 层:选内封轨/外挂 .ass 时旧 SRT、ASR 照画,双字幕只靠调用方自觉。
   外挂文件方向已有单向压制(`subTrackIndex=-2`,`MediaPlayer.cpp:489`),
   反向与 ASR 均无仲裁。
3. **接线双份**:VideoTrack 挂双视图(`VideoTrack.cpp:47-53`)、AVTrack 同步
   双时钟、MediaPlayer close/seek 各写两份。
4. **canvas 格式与 blend pass 二套**:R8+drawFontBlend vs RGBA8+sourceOver,
   能力不对等(R8 装不下逐像素/逐元素颜色)。
5. 每加一种格式(DVB/VOB/WebVTT…)都要先回答"走哪条路"。

## 2. 合并方向(v3):统一 canvas 通道

两条链路其实早已共享同一个管线位置(VK PipeGraph 画质层之后、出帧之前的
混合槽),差别只在 canvas 格式与 blend pass。所以合并 = **把 canvas 格式
归一成 RGBA8 bbox,blend pass 归一成 sourceOver,渲染路径只剩一条**:

```
canvas 生产者(谁画 RGBA8 bbox canvas)              统一渲染(唯一)
├─ libass 插件: 内封 ASS/SSA/SRT 轨、外挂 .ass   ─┐
├─ PgsDecoder: PGS                                ├→ SubtitleView(统一视图,三槽位仲裁)
└─ 核心文本光栅化器(新增): 外挂 .srt / ASR 文本  ─┘     → ICanvasLayer(VkCanvasLayer)
                                                        → sourceOver blend → 出帧
```

- **核心文本光栅化器**:FreeType 排版 → RGBA8 bbox canvas(样式参数化:
  字体/字号/颜色/位置,默认对齐现观感 simhei 40 底部)。实现上可搬
  VkFontLayer 的 CPU 字形代码改为输出 RGBA8(或 R8 渲染后 CPU 着色扩张,
  底部横条尺寸小,开销可忽略)。`IFontLayer` 样式能力(回应"可设定")在新
  组件里保留为参数,不再写死。
- **ASR/AI 文本走自家光栅化器**:核心内直达,无跨 DLL、无 libass 事件
  覆盖问题(v1 的主要风险消失);翻译链路删除(D5),识别结果直接进
  光栅化器。
- **font layer 退役**(字幕路径):`VkFontLayer`/drawFontBlend/IFontLayer
  不再被 src/avox/subtitle 引用;avox_freetype 模块保留(avox_cmd 的 OSD
  仍用,文本光栅化器也复用其 FreeType 依赖)。
- **降级语义**:无 avox_ass 插件 → 样式轨/PGS 不可用(显式报不可用),
  纯文本(外挂 .srt/ASR)照常——比 v1 优雅,与现状一致。

**v1/v2/v3 取舍**:

| | v1 全迁 libass | v2 双后端统一视图 | v3 统一 canvas(主) |
|---|---|---|---|
| 渲染路径 | 一条 | 两条 | **一条** |
| ASR 文本通路 | 跨 DLL 喂 chunk,事件覆盖风险 | font layer(现状) | 核心光栅化器,零跨 DLL |
| 外挂 .srt 观感 | 变(libass 默认样式) | 零变化 | 零变化(默认对齐,样式可配) |
| 翻译 | 需特殊通路 | 零改造 | **删除**(D5,端上小模型质量不行) |
| 无插件降级 | 文本字幕全灭 | 文本照常 | 文本照常 |
| 工作量 | 5~8 天 | 3~5 天 | 4~6 天(多在文本光栅化器) |

## 3. 目标架构与决策点

- 视图命名:**复用 `SubtitleView`**(旧类删除,统一视图顶用旧名,不新造
  长名),由 AssOverlayView 扩展而来:持三槽位状态 + ICanvasLayer 接线。
- **仲裁规则(引擎内,替代调用方自觉)**:三槽位(内封轨/外挂文件/ASR)
  一个胜者,**后激活者胜**——选内封轨 → 清外挂与 ASR;loadSubtitle →
  清内封轨与 ASR;enableAsr → 清内封轨与外挂。胜者空窗就空屏,不回落,
  避免两条字幕闪替。close/切轨/seek 按槽位释放。
- **D1 路由规则(按内容固定)**:样式/位图源(内封 ASS/SSA/SRT 轨、外挂
  .ass、PGS)→ 插件/PgsDecoder;纯文本源(外挂 .srt、ASR)→ 核心文本
  光栅化器。内封 SRT 轨(libass 样式)与外挂 .srt(光栅化器样式)观感不同,
  记为已知差异——内封轨是"片源作者的字幕",样式交给片源/libass。
- **D2 互斥语义**:后激活者胜 + 空窗不回落。「AI 字幕 vs 片源字幕」的
  产品开关 = 重新调 enableAsr / setSubtitleTrack,引擎不再需要额外开关;
  panvox shim 的互斥逻辑可删(P0 确认)。
- **D3 API 收口(破坏性,不做兼容)**:外挂唯一入口命名 **`loadSubtitle`**,
  接口不出现 SRT/ASS 等具体格式名,扩展名/轨类型内部分流;删
  `ISubtitle::loadSrt`;`ISubtitle` 收缩为 ASR 控制 + 生命周期
  (enableAsr/close,翻译接口随 D5 删除)。SWIG 四绑定按破坏性变更重生成,
  samples 同步改。
- **D4 时钟接线合一**:AVTrack 只 sync 统一视图一个 Clock;VideoTrack 只
  attach 一个视图;MediaPlayer close/seek 只操作一个对象。
- **D5 删除字幕侧翻译链路**:端上小模型/HTTP 翻译质量与大模型差距是能力
  天花板,且产品侧(povex AI 字幕管线)已由应用层用大模型产 SRT,引擎内
  翻译是更差的重复实现。范围:
  - 删:`SubtitleAsr` 翻译线程与 BaseTranslator 接线、`SubtitleFile` 查找
    时翻译钩子、`ISubtitle::enableTranslation/disableTranslation`。
    ptsSync 模式保留识别队列(识别 ~500ms 延迟仍需 PTS 对齐),端到端延迟
    约 1s → 0.5s。
  - 留:翻译基础设施(ITranslator hub、avox_zlmediakit 的 HttpTranslator、
    avox_cmd translate 命令)——字幕之外有消费方,不动。
  - 留:ASR 识别本身。实时识别不存在"被大模型碾压"问题,直播/采集实时
    CC(SourcePlayer streaming 模式)是真实场景,要的是低延迟不是翻译
    质量;且合并后 ASR 只是文本光栅化器的一个文本源,保留边际成本低。
    产品若确认无人用引擎 ASR,可后续整体再删,不影响统一架构。

## 5. 风险

- **文本光栅化器观感对齐**:默认样式必须对齐现 simhei 40 底部(参数可调),
  P2 截图对比验收;多行/换行排版沿用 VkFontLayer 现有逻辑,别重写。
- **ASR 流式高频重上传**:部分结果 ~100ms 一次,底部横条 RGBA8 约
  8~12MB/次上传(R8 时代 2~3MB)——先量实测;超预期时文本变化才重排 +
  bbox 裁剪已经天然限制尺寸,预计可接受。
- **互斥状态机边界**:seek/切轨/外挂加载失败/close 的槽位释放顺序,
  P1 用例表先行(选轨失败要回到原胜者,不能三清)。
- **shim/Flutter 同步**:引擎接管互斥 + loadSrt 删除后,panvox 侧调用点
  与旧互斥逻辑同步改(P0 对齐,破坏性变更一次说清)。
- **回归面**:每阶段 ctest + play_regress 离线子集;P2/P3 追加
  assmkvtest/asspostest/asstest/sherpaTest/sourcettstest。

## 6. 验收标准(合并完成定义)

1. 渲染路径唯一:所有字幕经 RGBA8 bbox canvas → ICanvasLayer → sourceOver;
   `VkFontLayer`/drawFontBlend 不再被 src/avox/subtitle 引用(avox_cmd 不受影响)。

   `enableTranslation/disableTranslation` 已删除;SWIG 四绑定生成物同步

   HttpTranslator/avox_cmd translate)不受影响。
