# 动态加载组件设计

> 把依赖大三方库的可选模块（opencv/onnx/sherpa/translation/inpaint）做成可独立编译的「组件」，
> avox 启动扫描 `plugins/` 运行期探测，库/模型缺失则优雅降级；动态/静态一行配置切换，iOS/Apple 也能走通。

## 1. 目标
- 组件迁 `plugins/`，物理隔离核心/非核心；avox 启动自动扫描 avox.dll 同级 `plugins/avox_*.{dll,so}`。
- 运行期探测（库/模型/算力缺否）→ 优雅降级，不崩。
- iOS/Apple 强制 STATIC（App Store 禁止加载第三方可执行代码），照样能探测降级。
- 「组件↔内置」一行配置切换，业务代码零改动（位置无关 include，src↔plugins 迁移 include 不改）。

## 2. 接口（src/avox/module/）
- `IModule`：`loadModule(IOption*) -> bool`（探测+初始化，false=不可用≠崩）、`unloadModule()`；依赖用成员 `deps` + `addDep(name)/depCount()/getDep(i)->const char*`（不返回 STL 容器，跨 DLL 安全）。
- `ModuleMgr`：`startup()`（lazy，首次 `checkLoadModel` 触发，防 DllMain `LoadLibrary` 死锁）扫描+递归依赖加载；`checkLoadModel(name)` 降级查询。
- 注册宏 `AVOX_REGISTER_MODULE(Class, avox_name)`：动态导出 `NewModule/GetModuleABI`（ABI 守卫）；静态（`AVOX_ENABLE_STATIC`）走 `StaticLinkModule` 构造期注册，不导出符号。
- 命名：目录 `avox_<name>`，dll `avox_<name>.dll`，模块名 `avox_<name>`（全链路一致），IModule 子类 `<Name>Module`（短，不带 Avox 前缀）。

## 3. CMake（cmake/avox_module.cmake）
- 根 `option(AVOX_ENABLE_PLUGINS)` 总开关；组件 option（`AVOX_ENABLE_OPENCV` 等）在 `plugins/options.cmake`（根早期 include，保证 src 的 gate 可见）。
- `plugins/CMakeLists.txt` 两列表：`PLUGINS_DYNAMIC`（独立 dll）/ `PLUGINS_STATIC`（编进 avox）。
- `register_plugin(avox_<name> DYNAMIC|STATIC [DEPS avox_*] [LIBS ...] [DEP_DLLS ...])`：
  DYNAMIC 建 SHARED target，输出 `${CMAKE_INSTALL_PREFIX}/$<CONFIG>/plugins/`，复制第三方 dll 自包含。
- 「提升到内置」= 名字从 DYNAMIC 挪到 STATIC，业务代码 0 改动。

## 4. 扫描 + 依赖
- Windows `FindFirstFile(avox_*.dll)` / Linux `opendir(libavox_*.so)` / iOS(APPLE) no-op（靠静态注册表）。
- `LoadLibraryEx` 传**完整路径** + `LOAD_WITH_ALTERED_SEARCH_PATH`（让 plugin 从同目录找 `opencv_world4xx.dll` 等依赖）。
- 依赖分两类：**外部库**（opencv_world 等）dlopen 自动探测无需声明；**avox 组件间**（inpaint→onnx+opencv）`addDep()` 显式声明，递归 load + 失败传播。
- 静态探测（iOS 无 dlopen）：探运行期条件（模型 `fileExists`、onnx EP、Metal 设备、`sherpaEngine->init()` 失败即不可用），非库存在性。

## 5. 平台
| 平台 | 扫描 | 默认模式 |
|---|---|---|
| Windows/Linux | dlopen plugins/ | DYNAMIC |
| iOS/Apple | 全 STATIC | STATIC |
| Android | STATIC（jniLibs 不能枚举目录） | STATIC |
| WASM | 预链接 | STATIC |

`AVOX_DLL_TYPE==STATIC` 时 CMake 定义 `AVOX_ENABLE_STATIC` → 注册宏走静态分支、`AVOX_PLUGIN_API` 为空。
引擎层静态/动态一致：`loadModule` 静态工厂（`onLoadEvent`）优先、ABI 只校动态、`scanPluginsDir` 在 iOS no-op。

## 6. 跨 DLL 安全规范（/MTd 实测 2026-07-06）

avox 全链路 /MT（静态 CRT），每个 DLL 拥有独立 CRT 堆实例。简单跨 DLL new/delete 安全（UCRT 静态堆复用 `GetProcessHeap()`），但 **STL 容器跨 DLL 传递必崩**——inline 析构在错误 CRT 释放内存，触发 `__acrt_first_block == header` 断言。

**安全 ✅**：`const char*`（只读不释放）、原始类型/枚举、C 函数指针、inline 函数（每个 DLL 自己实例化）、虚析构（dispatch 到子类 DLL 的 CRT）。
**不安全 ❌**：`std::string`/`std::vector` 等 STL 容器（inline 析构跨 CRT 撞堆）、返回 STL 容器的虚函数/导出函数。

**已修复的跨 DLL STL 崩溃**：
① `IModule::dependsOn()` 返回 `vector<string>` → 改为成员 `deps` + `addDep()/depCount()/getDep()` 返回 `const char*`；子类构造函数中 `addDep("avox_onnx")` 声明依赖，虚析构走插件 CRT 正确释放 `deps`。
② `extractFile()` 返回 `std::string`（AVOX_EXPORT，avox.dll 创建，插件析构崩）→ 改为 `extractFileInline()` inline 函数，零分配直接返回 `const char*` 指向 `__FILE__` 静态串内部，每个 DLL 自己实例化，彻底消除跨 CRT 问题。

**设计原则**：插件接口只传 `const char*` 和原始类型；需要字符串的日志/工具函数用 inline 实现（放头文件），让调用方 DLL 自己实例化；STL 容器只在本 DLL 内部构造和析构，绝不跨越 DLL 边界传递。

## 7. 现状
**已迁**（6 个 DYNAMIC plugin）：
- `avox_opencv`：扫描→loadModule 探测；dll 改名 false 降级。
- `avox_sherpa`：`SubtitleAsr` 走 `audioSttHub.create("sherpa")` 查表；`SherpaModule` 注册工厂。
- `avox_onnx`：**接口归核心**——`IONNXSession` 纯抽象移 `src/avox/neural/`（核心零 onnxruntime 依赖），`ONNXSession` 实现迁 plugin；`OnnxModule` 注册 `onnxSessionHub.reg("onnx")` 工厂。
- `avox_translation`：`OnnxTranslator` 持 `unique_ptr<IONNXSession>`（改自 `ONNXSession` 具体类），`load()` 走 `onnxSessionHub.create` 查表拿实例；构造函数 `addDep("avox_onnx")`；`SubtitleAsr` 走 `translatorHub.create("onnx")` 查表（去 include + `#ifdef`）。
- `avox_cv`：**接口归核心**——`IWatermarkRemoval` 纯抽象移 `src/avox/neural/`（同目录 IONNXSession，核心零 onnx/opencv 依赖），`WatermarkRemoval` 实现迁 plugin；3 个类（YOLODetector/LamaInpainter/AOTGanInpainter）改持 `unique_ptr<IONNXSession>` + `onnxSessionHub.create("onnx")` 查表；`CvModule` 注册 `watermarkRemovalHub.reg("inpaint")` + `yoloDetectorHub.reg("yolo")` 工厂；构造函数 `addDep("avox_onnx"), addDep("avox_opencv")`。
- `avox_webrtc`：WebRTC PeerConnection + 音频 3A → `plugins/avox_webrtc` 动态插件；`WebrtcModule` 注册 `regRtcPlayer("webrtc")` + `regAudioProcess("webrtc")` + `rawSources.regInitFunc(RawSourceType::WebRTC, "webrtc")` 工厂；`IRtcPlayer` 纯接口归核心 `src/avox/AvoxPlayer.h`，RtcPlayer/RtcParse/RtcAudioProcess 实现迁插件。

**核心解耦模式**（sherpa/onnx/translation/inpaint 四例验证）：核心持纯接口（`AudioStt`/`IONNXSession`/`BaseTranslator`/`IWatermarkRemoval`）+ `AvoxManager` 工厂表（`RegeditFactory<>::reg`/`create`），plugin `loadModule` 注册工厂；核心模块调 `ModuleMgr::ensureStarted()` 触发 plugin lazy 加载后查表。核心对组件零编译期 include/库依赖。

**踩坑**：
① plugin 继承的核心类须 `AVOX_EXPORT`（虚表引用其方法）：sherpa 的 `AudioReshaper`/`RunTask`/`AssetLoader`，translation 的 `BaseTranslator`（`AudioStt`/`ITranslator` 不用——虚函数全 override + 析构 inline）。
② `LoadLibraryEx` 用 `LOAD_LIBRARY_SEARCH_DLL_LOAD_DIR`（传递依赖搜索，sherpa 两层 `sherpa-c-api→onnxruntime` err=126）。
③ onnx 接口归核心（非导出 `ONNXSession` 具体类）——plugin 间通过核心接口 + 工厂表解耦，不直接 include 对方实现。
④ swig `common.i` 随迁移调整：C 工厂符号在 plugin dll 内时 swig wrapper 链 `avox.lib` 拿不到（`LNK2019 __imp_saveTencentApi`）→ 去 `%include avox_translation/TranslationExport.h`；nodejs swig 命令行 `-I` 加 `plugins/`（迁移后路径）。**已解决**：`saveTencentApi` 随 HttpTranslator 迁 `src/avox_zlmediakit/`，`AVOX_EXPORT` 编进 avox.dll，`%include "avox_zlmediakit/ZlmExport.h"` 恢复绑定。
⑤ `AVOX_ENABLE_ZLMEDIAKIT=0` 无法稳定覆盖全局 `=1`（MSVC 宏重定义）→ 原 `register_plugin` 加 `SOURCES` 参数显式排除 `HttpTranslator.cpp`；**已解决**：HttpTranslator 整体迁 `src/avox_zlmediakit/`（内置模块，mk_httpclient 天然可链），不再在 plugin 中。
⑥ **工厂表用 C 函数指针 typedef**（非 `std::function`）：`std::function` 的 type-erasure manager 实例化在 plugin 的 `regXxx` 调用点，进程退出 `AvoxManager` 析构晚于 plugin 卸载 → 调已卸载 manager 退出 segfault（test_plugin 曾 exit 139）；裸函数指针析构不调代码。无捕获 lambda 隐式转换。

**已知遗留**：
- swig C# 绑定的 sherpa C 工厂：符号随 plugin，`common.i` 已去 `%include`（不生成绑定）；运行期由 plugin 工厂表替代，C#/Java 调用待重设计。
- `build_windows.py` 加 `AVOX_BUILD_AI=ON` 开关（默认 Web 构建 AI OFF；AI ON 构建插件 + sherpaTest 等 sample）。

**内置模块**（随 avox.dll 编译，不走 plugin 加载）：
- `HttpTranslator`（腾讯云 http 翻译）：原在 `plugins/avox_translation/` 因 mk_httpclient 未导出无法编进 plugin dll；迁 `src/avox_zlmediakit/` 后 mk_httpclient 天然可链，工厂 `regHttpTranslator()` 在 `AvoxManager::init()` 注册；`saveTencentApi` 随迁并以 `AVOX_EXPORT` 导出（`ZlmExport.h`），swig 绑定恢复。
