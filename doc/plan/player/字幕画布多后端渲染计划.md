# 字幕画布多后端渲染计划(HDR/SDR × DX11/Metal/GLES/VK)

> 状态: 已落地 · 上次核对: 2026-10-03 · 权威源: -(实施 b09df9a, 2026-10-03)

> 2026-10-02 方案讨论定稿(拍板口径 §二), 未实施。
> **同域**: HDR 链路/直通/翻转口径的权威源 = [多平台HDR统一重构方案](../gpu/多平台HDR统一重构方案.md)(本计划 VK V2 并入其 R2/R3 批次); canvas 通道与挂载位既有契约 = [字幕模块合并计划](字幕模块合并计划.md)(已落地)与 [ASS字幕渲染计划](ASS字幕渲染计划.md)(§3.4)。平台渲染器内部(YUV→RGB/tone map/交换链/翻转)事实以 HDR 方案为准, 本文档权威范围 = 字幕画布混合的多后端化与 HDR 域处理。

## 一、背景与现状(三个事实)

1. **TextRasterizer 是纯 CPU 生产者, 后端中立**: FreeType 出字形 → 排版 → RGBA8(premultiplied) bbox 画布(`src/avox/subtitle/TextRasterizer.cpp`)。绑定 VK 的只是消费端——`enableRenderCanvas(ISurfaceRender*)`(src/avox/Avox.cpp:970) `dynamic_cast<VkVideoRender>` 取 `VkCanvasLayer`(canvasBlend.comp source-over), 取不到返回 nullptr, SubtitleView 降级不渲染。⇒ **lane=1 原生直渲(DX11/Metal/GLES 呈现)的字幕今天是静默缺失的**(层挂进不被喂帧的 VK 图, 无报错无画面), 不只是缺 HDR。
2. **「只有 SDR 路径能用」是刻意裁剪**: `VkVideoRender.cpp:559` `bPt = hdrMode==forceHDR` 时整图裁最小直通链, font/canvas/geometry 全不建节点(注释「字幕/OSD 线性域合成归 V2」)。HDR 方案登记在案: 验收矩阵「直通态字幕 → V2 专项遗留(R3)」+ 风险台账「VK 16F 域层兼容」。
3. **三平台后端输出域不同**(HDR 混合的真正技术点):

| 后端 | SDR 输出 | HDR 直通输出 | 域 |
|---|---|---|---|
| Dx11CSVideoRender + Dx11Window | R8G8B8A8 | R10G10B10A2_UNORM(Dx11Window.cpp:73/353) | PQ 码域(码值原样写) |
| MetalRender(macOS/iOS 同份代码) | RGBA8Unorm | RGBA16Float + extended linear ITUR-2020 EDR(**1.0=100nit**, 实测修正: 原判「PQ 码域」有误, shader forceHDR 分支 pqToLinear×100 上屏, MetalRender.mm:127/329) | 线性域(100nit 标尺) |
| VkVideoRender(链F/V2) | rgba8 | FP16 交换链, pqUpsample 后全程 16F 线性域 | 线性域 |
| EglVideoRender(Android/Linux) | rgba8 | 无(EglWindow `setHdrPassthrough` 恒 false, EglVideoRender.cpp:149; HDR 呈现面 = HDR 方案 G8/R4 另批) | 仅 SDR |

## 二、拍板口径(2026-10-02, 用户定稿)

1. **PQ 码域混合用「CPU 侧预编码画布」起步**: 画布内容低频变化(每换一句台词一次), CPU 侧一次 SDR→线性→×参考白→PQ 编码(256 项 LUT)后上传, GPU 混合代码与 SDR 完全同一条, 逐帧零增量。线性域逐帧混合(全帧 PQ 解码→线性混合→再编码 pass)留作画质升级路径, 起步不做。
2. **VK V2 并入 HDR 方案 R2/R3 批次, 不单开**。
3. **范围只做字幕画布层, VkFontLayer/OSD 不带**。核实: 字幕三槽位(libass 内封轨/外挂文件/ASR)全走 TextRasterizer→ICanvasLayer→VkCanvasLayer, 不经 VkFontLayer(subtitle/ 内仅注释提「同源」)。VkFontLayer 仍存活: `enableRenderFont()`(avox_freetype/FreetypeExport.h:43)是宿主 OSD 公共 API, samples/swig 绑定在消费; 维持现状(VK/SDR/bPt 时被裁), HDR 直通下 OSD 不显示是既有行为非本批回归。日后清理单开「OSD 归并画布层」账, 与本批解耦。
4. **逻辑单点收公共单元, 平台只留薄适配**(「能在一处实现就不多平台放一份」):
   - 共享一处(subtitle/ 新公共单元, CanvasRender 一并下沉): PQ 预编码 LUT + 参考白常量; transform→uniform 全部数学(CPU 算好 center/width/height/origin/invScale 下发, shader 只采样乘加, 三端不各算); bbox 上传状态机(清旧 bbox→blit 新 bbox→静止零上传); 画布尺寸策略(subtitleCanvasSize); lane 路由与翻转 contentStale 语义。
   - 平台薄层只剩三样: ①纹理上传 API 调用(CopySubresourceRegion/replaceRegion/glTexSubImage2D) ②20~30 行混合着色器文本(HLSL/GLSL/MSL 各一份, 着色语言差异免不掉; glsl→SPIR-V→spirv-cross 交叉编译为 20 行 shader 引新工具链, 不值) ③管线挂接点。每后端约 100~200 行。
5. **零字幕零影响条款**(§六, 硬性)。

## 三、结构设计

- **ICanvasLayer 接口不动**(src/avox/subtitle/SubtitleCanvas.hpp 本就后端中立: updateCanvas/clearCanvas/setCanvasTransform/takeContentStale)。TextRasterizer、SubtitleView 三槽位仲裁、subtitleCanvasSize 零改动。
- **CanvasRender 稳定前端下沉 subtitle/**: 「层随图重建换指针 + 建图期暂存 + 变换权威副本 + contentStale」是纯逻辑与 VK 无关, 三后端复用。
- **VideoRender 基类加虚口** `enableRenderCanvas()/disableRenderCanvas()`(默认 nullptr/no-op), **WindowRender 按 lane 路由**: lane=0→vkVideoRender, lane=1→pVideoRender。Avox.cpp 的 VK 特判删除, SubtitleView 零改动。
- **lane=0 平台腿禁叠字幕**(易踩点): 平台渲染器输出在 lane=0 是喂 VK 的对接面(rgba8 共享纹理/IOSurface), 在那里叠字幕会 ①双重字幕(VK canvas 层再叠一次) ②字幕在超分/增强之前被合成, 违反「字幕不被超分重采样」挂载位(ASS字幕渲染计划 §3.4)。DX11 上同一张 outSharedTex 两种消费者(lane=1 Dx11Window quad 上屏 / lane=0 VK 导入), 注入点必须按 lane 分流(WindowRender 持 lane, 向渲染器下发「混合使能」仅在 !bVulkan 时)。

## 四、混合域数学

画布 = SDR BT.709 gamma 域 rgba8(premultiplied)。

| 输出域 | 策略 |
|---|---|
| SDR rgba8(全后端) | gamma 域 premultiplied source-over, 语义 = 今 canvasBlend.comp, 零新东西 |
| HDR·PQ 码域(DX11 r10a2) | **CPU 预编码画布**(§二.1): 上传前编码为 PQ 码, GPU 混合代码与 SDR 同一条, 着色器不感知域 |
| HDR·16F 线性域(VK V2 / Metal f16) | 帧已线性, canvas 采样在 shader 内线性化×参考白再混合, 域正确且零额外 pass(VK 1.0=80nit ×203/80; Metal 1.0=100nit ×203/100) |

- **参考白**: BT.2408 惯例 203 nits(SDR 白在 PQ 域的锚点), 常数收共享头**一处**定义(联动 HDR 方案遗留挂账「tone map sdrWhite 恒 100nit 不跟手」, 不再散第三份)。
- **翻转一致性**: 输出域翻转(SDR↔HDR)时画布预编码域失效 → takeContentStale 置位强制重传, 对齐 HDR 方案「输出跟呈现面实态同帧对齐翻转」纪律。
- **PQ 码域混合的已知误差**: 混合发生在 PQ 码域而非线性域, 边缘过渡带与线性混合有轻微差异; PQ 感知均匀性好 + edgeFuse smoothstep 本在收窄过渡带, 预期不可察; 真出 halo 再升级线性域逐帧 pass(§二.1 升级路径)。

## 五、逐后端做法

### 5.1 DX11(Windows)

- Dx11CSVideoRender 的 CS 已是全帧一趟(色彩处理总入口 → 写 outTexture), canvas 作第二个 SRV 在写 UAV 前叠加, bbox 外直通, 不加新 pass; 混合后纹理仍由 Dx11Window 既有 quad 采样上屏(Dx11Window.cpp:191), 窗口侧零改动。
- **双变体, 不恒绑定**: 预编译「带画布 SRV / 不带」两变体, 挂层会话才切; 无字幕/空窗跑原变体, 热路径无常驻空采样。
- 上传: staging → CopySubresourceRegion(bbox 裁剪), 复用「CPU 画布清旧 bbox → blit 新 bbox」模式。
- R10G10B10A2 的 2bit alpha 无碍: CS 算好终值直写, 不走 OM 硬件混合。
- SDR 态: 交换链 R8G8B8A8, 画布不编码, 同一条混合代码。

### 5.2 Metal(macOS/iOS 同份代码)

- render pass 内加第二 draw(同一 encoder): 全屏 quad + FS 采样 canvas 纹理, blend state one/one-minus-src-alpha(premultiplied 正好)。
- 管线态照 `bF16Pipeline` 翻转模式加 f16 变体; 空内容/opacity=0 直接跳过第二 draw。
- 上传 replaceRegion(bbox); f16 直通为 extended linear(1.0=100nit), canvas 在 shader 内线性化×(203/100), 域翻转零重传(线性化在 shader, 画布数据域无关)。
- iOS 同享 SDR 路先通; iOS EDR 呈现面在 HDR 方案 G5/R3 另评估, 不在本批。

### 5.3 GLES(Android/Linux)

- EglVideoRender 第二个 draw: `glBlendFunc(GL_ONE, GL_ONE_MINUS_SRC_ALPHA)`, bbox UV 变换吃公共单元产出的 uniform。
- **GLES 没有 HDR 字幕也不做**: EGL 腿无 HDR 呈现面(EglVideoRender.cpp:149), 且 Android 恒 VK 车道 → Android 的 HDR×字幕 = VK 侧 V2。GLES 只交付 SDR。

### 5.4 VK(HDR 方案的 V2, 并入 R2/R3)

- 现状: forceHDR 时 bPt 连 canvas 层都不建(链F 注释「使下游(合成/字幕/图像处理)在扩展线性域进行」的承诺未兑现)。
- 做法: forceHDR 拓扑恢复 canvas 层挂线(bEnableCanvas 门控, 无字幕时拓扑仍是最小直通链), canvasBlend.comp 加 16F 线性域变体(canvas 采样线性化×参考白)。
- 三平台 lane=0 的字幕(含 Android/Linux 的全部 HDR 字幕)都靠它, 收益面最大, **排最前**。

## 六、零字幕零影响条款(硬性)

1. **挂层入口即门控**: SubtitleView::checkWindowRender 只在有内容槽位时 enableRenderCanvas(SubtitleView.cpp:115), 无人挂层 → 后端零注入。
2. **资源惰性创建**: 画布纹理/管线变体/staging 首挂才建, 无字幕会话零新增显存与驱动对象。
3. **变体翻转非恒绑定**: DX11 双变体; Metal/GLES 空内容跳过第二 draw。
4. **静默段(有轨无词)沿用现有语义**: clearCanvas + 层直通 + 序号不变零上传; 粘性层纪律照旧(播放期不摘层, VK 0923 图重建驱动死锁教训)。
5. **VK forceHDR 拓扑**: bEnableCanvas=false 时恢复后的拓扑仍是最小直通链, 与今天逐节点相同。
6. **旁路消费者不受染**: 直通态截图/回读维持拒绝口径; 录制/yuvout 烧字幕语义跟随所在 lane(VK 图内 canvas 在录制支路前 / 平台腿混合进呈现输出同理), 无字幕时无差别。

## 九、风险与边界

- **PQ 码域混合边缘误差**(§四): 起步接受, 升级路径明确(线性域逐帧 pass)。
- **R10G10B10A2 共享兼容性**: 平台腿混合不新增格式不新增共享链路, 互操作风险归 HDR 方案 R1 台账。
- **iOS EDR 呈现面**: 归 HDR 方案 G5/R3, 本批 iOS 只保 SDR。
- **Android/Linux HDR 呈现面(G8/R4)**: EGL HDR 口未开, GLES 恒 SDR; HDR×字幕在 VK 层。
- **lane 换道须重开**(HDR 方案 §6.6 硬约束): 本批 lane 路由沿用, 不做播中换道。
- **图重建死锁教训**(0923): 挂/摘层沿粘性层纪律, 播放期只清内容不摘层。
