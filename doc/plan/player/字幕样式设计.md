# 字幕样式与位置 设计文档 (v3 · 定稿)

> 覆盖范围:SRT/ASR 文本字幕的样式(字体/字号/颜色/对齐/位置/边距/换行)与三层通用变换(scale/offset/opacity)。
> 本文替代早期的需求 handoff 稿与两版接口草稿(工作区 `.trae/documents/` 内, 未入库)。
> 相关: [字幕模块合并计划](字幕模块合并计划.md)、[ASS字幕渲染计划](ASS字幕渲染计划.md)。

## 1. 目标与非目标

**目标**:把字幕观感配置放出来,分两层能力。

1. **纯文本样式**(SRT/ASR):字体、字号、颜色、对齐、位置、边距、换行宽度 → `TextRasterizer`(CPU)。
2. **全局变换**(SRT/ASR + ASS + PGS 三层通用):scale / offset / opacity。

**平台前提**:ASS/PGS 需要 Vulkan 后端的 canvas 混合层。非 Vulkan 时 `enableRenderCanvas` 返回 `nullptr`(`src/avox/Avox.cpp:1002`),轨字幕本来就不渲染;文本路径与纯文本样式不受影响。

**非目标 / 本期不做**:ASS/PGS 逐样式覆盖(样式归片源)、行距字距(`hSpace/vSpace`,二期)、内嵌字体/MKV 附件、运行时能力查询。

## 2. 接口定稿(`ISubtitle`)

```cpp
// src/avox/AvoxPlayer.h — ISubtitle
// 字幕控制器: ASR 开关 + 观感设置。ASS 样式归片源(libass)、PGS 是位图:
// 纯文本 setter 对二者静默忽略; 全局变换对三层都生效。
class ISubtitle {
 public:
  virtual ~ISubtitle() = default;
  // ---- ASR 开关(既有) ----
  virtual void enableAsr() = 0;
  virtual void disableAsr() = 0;

  // ---- 全局变换: SRT/ASR + ASS + PGS 通用 ----
  // 文本路径在 CPU 侧按最终观感重栅格化(清晰), 轨路径在 canvas 合成处做(位图重采样)
  virtual void setScale(float scale) {}                    // 1.0=原尺寸; <=0 忽略
  virtual void setOffset(float offsetX, float offsetY) {}  // 帧归一化平移(0.1=帧宽10%)
  virtual void setOpacity(float opacity) {}                // 0.0~1.0(1=不透明, 0=隐藏)

  // ---- 纯文本样式: 仅 SRT/ASR 有效(ASS/PGS 忽略) ----
  virtual void setFont(const char* fontName, int32_t fontSize) {}  // 字号 1080 基准, 随帧高缩放
  virtual void setColor(float r, float g, float b) {}              // 0.0~1.0
  virtual void setAlign(HAlignType h, VAlignType v) {}             // 默认 mid/bottom
  virtual void setPosition(float anchorX, float anchorY) {}        // 归一化锚点, 默认 0.5/0.8
  virtual void setPositionMargin(float marginX, float marginY) {}  // 1080 基准像素, 按对齐方向内收
  virtual void setMaxWidth(float ratio) {}                         // 自动换行宽度(帧宽比例), 默认 0.8
};
```

**全部带默认空实现**:`MediaPlayer`(转发到 `subtitleView`)、`SubtitleView`(真实实现)覆盖,既有实现者零影响。
`HAlignType/VAlignType` 来自 `AvoxLayer.h`;`AvoxPlayer.h` 经 `AvoxMuxer.h→AvoxSource.h→AvoxVideo.h` 传递包含,可直接引用。**接口形状一次定齐**,后续不再加方法。

### 2.1 生效矩阵

| setter | SRT / ASR(文本路径) | 内封 ASS 轨 / 外挂 `.ass` | PGS 位图轨 |
|---|---|---|---|
| `setFont/setColor/setAlign/setPosition/setPositionMargin/setMaxWidth` | 生效 | 忽略 | 忽略 |
| `setScale/setOffset/setOpacity` | **CPU 侧生效**(清晰) | GPU 合成 | GPU 合成 |

> 外挂字幕按扩展名分流(`.ass/.ssa` → libass,其余 → `TextRasterizer`),所以同一个 `loadSubtitle` 进来的文件可能"能改字体"也可能"不能",必须写进接口注释。

### 2.2 语义细节

- `fontSize`:1080 参考高度下的字号,实际像素 = `fontSize * frameH/1080 * scale`,`max(8, …)` 钳制。
- `marginX/marginY`:1080 基准像素,按对齐方向**内收**:`left` 加在左侧、`right` 减在右侧、`mid` 不参与(水平);`bottom` 在底边之上、`top` 在顶边之下、`mid` 不参与(垂直)。
- `setPosition(anchorX, anchorY)`:帧归一化锚点,配合 `setAlign` 决定文本块相对锚点的摆放。
- `setScale`:`<=0` 忽略(保持上次有效值);`setOpacity` 钳制到 `[0,1]`;`setOffset` 不钳制,越界由帧内钳制兜底(文本侧)或可见区域裁剪(轨侧)。
- 所有 setter **不触发图重建**(与 `VkFontLayer` 的 `setFont/setScale` 不同),任意线程、任意时刻(含 `open` 前)可调。

## 3. 实现机制

### 3.1 文本路径(CPU 侧,清晰)

落点 `TextRasterizer::TextCanvasStyle`,需三处改造 + 排版通用化。

**a. `fontName` 改 `std::string`**

```cpp
std::string fontName = "simhei.ttf";  // asset/fonts 下的字体名(FontMap 解析)
```

理由:`FontCache::setFont(const std::string&, int32_t)`(`src/avox_freetype/FontCache.hpp:24`)传 nullptr 直接崩;setter 存 `const char*` 会悬垂(脚本语言传临时字符串极常见)。

**b. 样式字段 + 样式版本号**

```cpp
struct TextCanvasStyle {
  std::string fontName = "simhei.ttf";
  int32_t fontSize = 40;                    // 1080 基准
  float colorR = 1.f, colorG = 1.f, colorB = 1.f;
  HAlignType hAlign = HAlignType::mid;      // 默认值 = 旧行为
  VAlignType vAlign = VAlignType::bottom;
  float anchorXRatio = 0.5f;
  float anchorYRatio = 0.8f;
  float marginX = 0.f;                      // 1080 基准像素
  float marginY = 0.f;
  float maxWidthRatio = 0.8f;
  int32_t hSpace = 3, vSpace = 5;
  // ---- 全局变换: 文本路径在 CPU 侧消费(所以不上 canvas 层) ----
  float scale = 1.f;
  float offsetXRatio = 0.f, offsetYRatio = 0.f;  // 帧归一化
  float opacity = 1.f;
};
```

`render()` 的缓存判定必须带上样式版本:现状只比 "文本 + 帧尺寸"(见 `src/avox/subtitle/TextRasterizer.cpp:36`),改样式不会重绘。加 `int32_t styleSeq`(调用方 `setStyle()` 时递增),`render` 内比 `lastStyleSeq`;保留"样式+文本+帧尺寸都没变 → 返回上次序号 → 零上传"的契约。

**c. 排版通用化(`render` 内)**

```cpp
const float dpi = (float)frameH / 1080.f;
const int32_t fontPx = std::max(8, (int32_t)(style.fontSize * dpi * style.scale));
// ... 逐行取字形/换行, 得到 totalW/totalH ...

const int32_t mX = (int32_t)(style.marginX * dpi);
const int32_t mY = (int32_t)(style.marginY * dpi);
const int32_t ax = (int32_t)(frameW * style.anchorXRatio);
const int32_t ay = (int32_t)(frameH * style.anchorYRatio);
int32_t startX = ax;
switch (style.hAlign) {
  case HAlignType::left:  startX = ax + mX; break;
  case HAlignType::right: startX = ax - mX - totalW; break;
  default:                startX = ax - totalW / 2; break;   // mid
}
int32_t startY = ay;
switch (style.vAlign) {
  case VAlignType::top:   startY = ay + mY; break;
  case VAlignType::mid:   startY = ay - totalH / 2; break;
  default:                startY = ay - mY - totalH; break;  // bottom
}
canvasX = startX + (int32_t)(frameW * style.offsetXRatio);
canvasY = startY + (int32_t)(frameH * style.offsetYRatio);
// 帧内钳制(沿用现状写法)
canvasX = std::min(std::max(0, canvasX), frameW - totalW);
canvasY = std::min(std::max(0, canvasY), frameH - totalH);
```

**默认值代入即现状公式**(`mid` + `bottom` + margin 0 + scale 1 + offset 0):`canvasX = anchorX*frameW - totalW/2`、`canvasY = anchorY*frameH - totalH`,与 `TextRasterizer.cpp:134-137` 逐值相同 ✔

**d. opacity(CPU 侧)**

写像素时把 alpha 乘上 `style.opacity`(premultiplied 语义下 rgb 同步乘):

```cpp
const uint8_t a = (uint8_t)(src[x] * style.opacity);
// px[0..2] = color * a, px[3] = a  (保持 premultiplied)
```

`opacity == 0` 时画布全透明,可走 `clearCanvas()` 省一次上传(可选优化)。

### 3.2 轨路径(GPU 合成)

#### 3.2.1 shader 必须改(`glsl/source/canvasBlend.comp`)

现状是**绝对 uv 采样**,rect 只做门控:

```36:43:glsl/source/canvasBlend.comp
    vec4 rect = vec4(ubo.centerX - ubo.width / 2.0f, ubo.centerY - ubo.height / 2.0f,
                     ubo.centerX + ubo.width / 2.0f, ubo.centerY + ubo.height / 2.0f);
    if (uv.x >= rect.x && uv.x < rect.z && uv.y >= rect.y && uv.y < rect.w) {
      vec4 overlay = textureLod(inTex2, uv, 0.0);
```

**只改 `width/height/center` 不会缩放内容**,必须加 uv 反算。UBO 扩字段(与 `CanvasBlendParamet` 严格同序,std140,全 float):

```glsl
layout(std140, binding = 3) uniform UBO {
  float centerX;   // 变换后门控矩形中心(帧归一化)
  float centerY;
  float width;     // 变换后门控矩形宽高(帧归一化)
  float height;
  float opacity;
  float pivotX;    // 缩放轴心(已叠加 offset, 见 3.2.2)
  float pivotY;
  float invScale;  // 1.0 / scale
} ubo;
```

主体:

```glsl
if (ubo.opacity > 0.0f) {
  vec2 uv = vec2(id.x + 0.5, id.y + 0.5) / vec2(size);
  vec4 rect = vec4(ubo.centerX - ubo.width * 0.5f, ubo.centerY - ubo.height * 0.5f,
                   ubo.centerX + ubo.width * 0.5f, ubo.centerY + ubo.height * 0.5f);
  if (uv.x >= rect.x && uv.x < rect.z && uv.y >= rect.y && uv.y < rect.w) {
    vec2 pivot = vec2(ubo.pivotX, ubo.pivotY);
    vec2 suv = pivot + (uv - pivot) * ubo.invScale;
    if (suv.x >= 0.0f && suv.x <= 1.0f && suv.y >= 0.0f && suv.y <= 1.0f) {
      vec4 overlay = textureLod(inTex2, suv, 0.0);
      // premultiplied source-over: rgb 必须一起乘 opacity
      vec4 src = vec4(overlay.rgb * ubo.opacity, overlay.a * ubo.opacity);
      color.rgb = src.rgb + color.rgb * (1.0f - src.a);
    }
  }
}
```

三个注意点:

- **uv 越界必须丢弃**,不能靠采样器 clamp/repeat(`setScale < 1` 时反算点会跑到画布外)。`canvasImage->createSampler(true)` 的地址模式实现时确认,并保留显式范围判断。
- **premultiplied 修正**:旧式 `color.rgb = overlay.rgb + color.rgb*(1-a)` 只在 opacity ∈ {0,1} 时正确,`setOpacity(0.8)` 会发白发亮。
- **`.spv` 是入库资源**:`glsl/target/*.spv` 被 CMake 直接复制成 assets(`src/CMakeLists.txt:272`),改完 `.comp` 必须跑 `python glsl/compileglsl.py`(需 `glslangValidator`)并**提交 `glsl/target/canvasBlend.comp.spv`**。

#### 3.2.2 参数合成(每帧,CPU 侧)

记 base 矩形(内容 bbox,来自 `rectX/rectY/rectW/rectH`)、轴心 `P`(帧归一化,ASS/PGS 固定 0.5/0.5)、用户 `scale s`、`offset o`。映射 `screen = P + (c-P)*s + o`,反算 `c = Q + (uv-Q)/s`,`Q = P + o`。

```cpp
std::lock_guard<std::mutex> lock(mtx);
if (bNeedUpdate) {
  bNeedUpdate = false;
  if (hasContent) cpuBuffer->upload(canvasData.data(), frameW * frameH * 4);
}
// 每帧由 base + user 重算, 不做增量累加(静止帧调 setter 也必须即时生效)
if (!hasContent) {
  vkParamet.opacity = 0.f;          // 无内容: 强制直通, 不能填 userOpacity
} else {
  const float baseCX = (rectX + rectW * 0.5f) / frameW;
  const float baseCY = (rectY + rectH * 0.5f) / frameH;
  const float qx = userPivotX + userOffsetX;
  const float qy = userPivotY + userOffsetY;
  vkParamet.centerX = qx + (baseCX - userPivotX) * userScale;
  vkParamet.centerY = qy + (baseCY - userPivotY) * userScale;
  vkParamet.width  = (float)rectW / frameW * userScale;
  vkParamet.height = (float)rectH / frameH * userScale;
  vkParamet.pivotX = qx;
  vkParamet.pivotY = qy;
  vkParamet.invScale = 1.f / userScale;
  vkParamet.opacity = userOpacity;
}
updateUBO(&vkParamet);
bParametChange = true;
```

要点:`hasContent == false` 时 `opacity` 必须为 0(否则去采样已清空的画布);`opacity == 0` 时 shader 走 `if` 外分支 = 完全隐藏(符合 `setOpacity(0)`)。

### 3.3 槽位下发策略(CPU/GPU 二选一,避免双份缩放)


触发时机:①任意 transform setter;②`activateTrack/activateFile/activateAsr`;③`onRender` 开头检测胜者槽位变化(一次比较,零开销)。三处都调,保证槽位切换当帧就正确。

### 3.4 图重建(`bResetFlag`)与 pending / contentStale

`bResetFlag=true` 的唯一消费点是 `VkVideoRender::vaildAndInitGraph()`(`src/avox_vulkan/vulkan/VkVideoRender.cpp:271`):`graph && !bResetFlag` 才走 `onParametUpdate()` 快路径,否则**整图重建**(新建 `VkPipeGraph` → 全部 `addNode` → 重连边 → `:454` 置回 false)。且它是**播放中的常态**:分辨率变化 / GPU 帧变化(`needReset`,`src/avox/video/VideoRender.cpp:171`、`:189`)、软硬解切换(`:168`/`:181`)、`setAspect`、`enableYuvOut`、`enableImage`、`enableWatermark`、首次 `enableRenderCanvas`。

| 重建会丢(随层/图销毁) | 重建不丢(存常驻对象) |
|---|---|
| 所有 VkLayer 节点(`VkCanvasLayer`/`VkFontLayer`/…) | `VkVideoRender` 的 enable 开关 + 参数结构体(重建时重新灌进新节点,`:289-343`) |
| 层的 CPU/GPU 资源:`canvasData`、`frameW/frameH`、`rectX/Y/W/H`、`hasContent`、`vkParamet`、`cpuBuffer`、`canvasImage`、descriptor/pipeline | `CanvasRender`(常驻前端,`VkVideoRender.hpp:106`):`stash/hasStash` 保留,`setCanvasLayer()` 补发 |
| `VkFontLayer` 的 blocks/tscale 等 | `FontRender` 的 `pending*` → `applyPendingSettings()` |
| 图内节点与边 | `SubtitleView`(player 级):槽位/rasterizer/样式/chunks/PGS 缓冲/clock 全存活 |

**三条硬约束:**

1. **transform 状态必须存 `CanvasRender`(常驻前端)并在 `setCanvasLayer()` 补发**。`SubtitleView::canvasLayer` 指向常驻 `CanvasRender`,图重建变的是它内部的 `layer` 成员,**外层指针不变 → SubtitleView 收不到"层换了"事件**,只靠它"重新下发"没有时机。
2. **内容也需要重建后的重传信号**。现状:新 `VkCanvasLayer` 为空且 `vkParamet.opacity=0`,而 `SubtitleView::lastSeq` 未变 → `renderText/renderTrack` 直接 `return`,**字幕消失到下次内容变化**。修法:`CanvasRender` 加 `std::atomic<bool> contentStale`(`setCanvasLayer(nullptr)`、或建层但无 stash 可补发时置位),`SubtitleView::onRender` 开头 `if (canvasLayer->takeContentStale()) lastSeq = -1;`。
3. **绝不**把状态存进 `VkCanvasLayer` 成员(一次性对象)。

### 3.5 线程模型

- 文本样式:**独立 `styleMtx`**。现状 `SubtitleView::renderText`(`src/avox/subtitle/SubtitleView.cpp:355`)不持 `mtx`,`rasterizer` 无锁访问,setter 直接写会数据竞争。
  做法:setter 锁内写 SubtitleView 的样式副本(含 `styleSeq++`);`renderText` 开头锁内把副本灌进 `rasterizer.getStyle()`,解锁后再 `render()` → 渲染期间无人写 rasterizer,**渲染线程本身不需要锁**。
- transform:走图层已有的锁(`VkCanvasLayer`/`CanvasRender` 的 `mtx`);`VkVideoRender` 侧成员用一把小锁或 `std::atomic<float>` + 版本号。
- **锁序**:`styleMtx` 与 `mtx` 不得嵌套(或统一顺序),避免与 IO 线程 `pushChunk` 反序死锁。

### 3.6 轴心与一致性(已知差异)

- **文本路径**:缩放通过"字号 × scale + 重排"实现,位置仍由 `align/anchor/margin` 决定 → 等效于**围绕对齐锚点缩放**(底对齐时向上生长),这是字幕最自然的观感。
- **ASS/PGS**:锚点由片源/libass 决定,不可知 → 用**帧中心 (0.5,0.5)** 作轴心(与旧 `VkFontLayer` 的"整画布拉伸"等价)。
- 差异只在"同一时刻显示不同槽位"时可见(SRT 与 ASS/PGS 互斥,不会同屏);`setOffset` 三层语义一致(帧归一化平移),需要对齐观感时用 offset 微调。
- UBO 已留 `pivotX/pivotY`,未来要开放轴心参数只改 `SubtitleView` 一处。

### 3.7 参考 `VkFontLayer` 的取舍

**借鉴**:
- `FontLayout` + `Alignment(HAlignType/VAlignType)` + 归一化锚点(`src/avox_freetype/FreetypeExport.h:8`)→ 本次 `setAlign/setPosition` 的模型;
- `computeLayout` 的对齐/居中/钳制算式(`VkFontLayer.cpp:277-337`)→ §3.1c 的通用化排版;
- `tscale = scale * dpiScale`(`VkFontLayer.cpp:63`、`:111`)→ "1080 基准"口径;
- `FontRender` 的 pending + 建层补发 → §3.4 的同款模式。

**不借鉴**:
- **opacity 语义是反的**(旧 `0=不透明`),且旧的是 `mix` 混色,新的是 premultiplied source-over;
- **旧的缩放实现**(画布 = 帧/tscale 再 GPU 拉伸,省光栅化但糊)→ 我们用 CPU 重栅格化(文本)/ UV 反算(轨);
- **`setFont/setScale/updateLayout` 会 `resetGraph()`**(图重建,贵)→ 新 setter 一律不重建图。

### 3.8 顺手修:`VkVideoRender` enable/disable 的幂等与 `bResetFlag` 竞态

本次要新增的 `setSubtitleCanvasTransform` 不改图,但**字幕层首次挂载走的是 `enableRenderCanvas`**,而这一族 enable/disable 有两个已存在的坑,建议同批修掉。

**坑 1:不判状态,重复调用 = 重复整图重建。** 现状(节选):

```154:191:src/avox_vulkan/vulkan/VkVideoRender.cpp
FontRender* VkVideoRender::enableRenderFont() {
  fontRender->setEnable(true);
  bResetFlag = true;
  return fontRender.get();
}
...
ICanvasLayer* VkVideoRender::enableRenderCanvas() {
  bEnableCanvas = true;
  bResetFlag = true;
  // CanvasRender 为稳定前端(层随图重建换指针), 外部长期持有
  return canvasRender.get();
}
```

守卫写法(返回值不变,只为避免无谓重建):

```cpp
ICanvasLayer* VkVideoRender::enableRenderCanvas() {
  if (!bEnableCanvas) {          // 已经是开启态: 图上已有该层, 无需求重建
    bEnableCanvas = true;
    bResetFlag = true;
  }
  return canvasRender.get();
}
void VkVideoRender::disableRenderCanvas() {
  if (bEnableCanvas) {
    bEnableCanvas = false;
    canvasRender->setCanvasLayer(nullptr);
    bResetFlag = true;
  }
}
```

同族:`enableRenderFont`/`disableRenderFont` 守卫 `fontRender->enabled()`;`enableRenderGeometry`/`disableRenderGeometry` 守卫 `geometryRender->enabled()`(`setLayer(nullptr)` 一并跳过);`enableSizeChange(w,h)`/`enableSizeScale` 参数相同即返回;`enableWatermark`/`enableAnime4K`/`enableFSR`/`enableQualityEnhance` 同理。`enableLut`/`enableBasicAdjust`/`updateSharpen` 已有守卫,可作参照。

安全性依据:`bEnableCanvas` 只在建图时被读(`if (bEnableCanvas) { canvasLayer = graph->addNode<VkCanvasLayer>(); … }`),为 true 时"当前图已有该层或下次重建会加上",不需要额外 trigger。

**坑 2:`bResetFlag` 在重建末尾清零,重建期间置位的请求会被吞掉。** `VkVideoRender::vaildAndInitGraph()` 末尾 `bResetFlag = false;`(`:454`),`VideoRender::renderFrame()` 系列还有两处同样写法(`src/avox/video/VideoRender.cpp:226`、`:261`)。重建可能耗时数十毫秒,期间其它线程(宿主 API)置的 `true` 会被一起清掉 → **那次设置永久丢失**(表现为"开了字幕轨/开了水印却没生效,直到下一次无关的重建")。建议改为**重建开始时消费**:

```cpp
bool VkVideoRender::vaildAndInitGraph() {
  if (graph && !bResetFlag) { onParametUpdate(); return true; }
  bResetFlag = false;   // 先消费: 重建期间新置的请求留到下一帧
  ...
  return true;          // 末尾不再清零
}
```

或把 `bResetFlag` 升为 `std::atomic<bool>` 用 `exchange(false)`。`VideoRender.cpp` 的两处 "通过后清零" 同理调整(改成进入重建前消费)。这条对本次功能是刚需:首帧 `enableRenderCanvas` 与宿主初始化调用可能落在同一个重建窗口里。

## 4. 默认行为零变更自检

- `hAlign=mid`、`vAlign=bottom`、`anchor 0.5/0.8`、`margin 0`、`scale 1`、`offset 0`、`opacity 1`、`maxWidth 0.8` 代入 §3.1c → 与现状 (b) 公式逐值相同;
- `styleSeq` 初始值参与判定,未改样式时缓存命中逻辑与现状等价;
- `invScale = 1` 时 `suv == uv`,shader 采样点与现状完全相同;`opacity ∈ {0,1}` 时新旧混色公式数值相同;
- `hasContent == false` → `opacity = 0`,与原"直通"一致;
- 回归:不调任何 setter 时逐字节一致(用截图回归自动化,不靠肉眼)。

## 7. 验收标准

1. 外挂 `.srt`:`setFont("simhei.ttf",60) + setColor(1,1,0) + setAlign(mid,bottom) + setPosition(0.5,0.9) + setPositionMargin(0,80)` → 字号变大、变黄、上移留底边距;**改动当帧之后立即生效**。

7. 播放中触发整图重建(切分辨率 / 开关水印 / 软硬解切换)后:字幕不消失、transform 仍生效。
8. 播放中 UI 线程连续调 `setFont/setScale` 不崩、不撕裂。
