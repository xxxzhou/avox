# 大对象（多实例）日志归属设计

> 讨论稿。多实例下日志全标 `[avox] [0]`，无法区分属于哪个大对象实例。
> 范围：`MediaPlayer`、`SourcePlayer`、`TranscodeRecorder`（都继承 `RunTask`）。第一阶段只在 `MediaPlayer` 验证。
> 根因：`logMsg` 全局单点，`LogItem` 无实例上下文；实例存活期内 tid 稳定，缺的只是「tid → 实例」映射。

## 方案：TaskTrack + TrackMgr（按线程创建树归属）

```cpp
// src/avox/module/TaskTrack.hpp
class TaskTrack {                            // 大对象继承此 mixin
 public:
  TaskTrack();                               // 构造时 TrackMgr::add(this)
  virtual ~TaskTrack();                      // 析构时 TrackMgr::remove(this)
  virtual const char* getTrackName() = 0;    // 子类实现 "MP"/"SP"/"TR"，不改子类构造签名
  std::thread::id creatorTid;                // 创建自身的线程，记录暂不用
  std::thread::id selfTid;                   // 自身主线程（根，独立不入 tids）
  std::vector<std::thread::id> tids;         // 子线程集合；~7 个，vector 优于 set
  void addTrack(std::thread::id tid, bool bSelf = false);  // bSelf=true 设 selfTid；否则去重入 tids
  void removeTrack(std::thread::id tid);
  bool haveId(std::thread::id tid);          // tid 是否归属本 track：先比 selfTid 再遍历 tids
};
class TrackMgr {                             // 单例，只持 TaskTrack 列表
 public:
  static TrackMgr& get();
  void add(TaskTrack* t);                    // TaskTrack 构造时自动注册
  void remove(TaskTrack* t);                 // 析构时销毁
  void bindTid(std::thread::id creatorTid, std::thread::id tid);  // 查 creatorTid 所属 track，把 tid 归入
  void unbindTid(std::thread::id tid);
  TaskTrack* findOwner(std::thread::id tid); // 遍历列表，返回 tids 含 tid 的 track
  TaskTrack* current();                      // this_thread::get_id()
  std::string currentTag();                  // 多实例返回 "MP0"，单实例空
 private:
  std::mutex mtx;
  std::vector<TaskTrack*> tracks;
};
```
> 记录只存 `thread::id`，不绑 `RunTask*`。`getTrackName` 是纯虚，构造时不能调；注册只存指针，name 在 `currentTag`/多实例判定时（对象已完整）才取。

**归属树原理**：`bindTid(creatorTid, tid)` —— creatorTid 属于谁，tid 就属于谁。根用 `addTrack(tid, true)` 自锚（bSelf 设 selfTid），之后层层创建的线程靠 `bindTid` 链自动继承。`bindTid`/`unbindTid` 内部调 TaskTrack 的 `addTrack/removeTrack`。
```cpp
void TaskTrack::addTrack(thread::id tid, bool bSelf) {
  if (bSelf) selfTid = tid;                       // 根：设自身主线程，不入 tids
  else if (!haveId(tid)) tids.push_back(tid);     // 子：去重入 tids
}
bool TaskTrack::haveId(thread::id tid) {
  if (tid == selfTid) return true;
  for (auto& id : tids) if (id == tid) return true;
  return false;
}
TaskTrack* TrackMgr::findOwner(thread::id tid) {
  for (auto* t : tracks) if (t->haveId(tid)) return t;   // haveId 先比 selfTid 再遍历 tids
  return nullptr;
}
void TrackMgr::bindTid(thread::id creatorTid, thread::id tid) {
  if (auto* owner = findOwner(creatorTid)) owner->addTrack(tid);
}
void TrackMgr::unbindTid(thread::id tid) {
  if (auto* owner = findOwner(tid)) owner->removeTrack(tid);
}
```
> Track 名取自 `getTrackName()`，故 TaskTrack 构造时只存指针、不查 name；`currentTag`/多实例判定时（对象已完整）才取。`findOwner` 遍历列表，track 数少可忽略；`current()` 用 thread_local 缓存避免 logMsg 高频遍历。

## RunTask 改造（一处覆盖所有子任务）

```cpp
bool RunTask::startTask() {
  auto creatorTid = std::this_thread::get_id();
  ...
  thread = std::thread(&RunTask::runTask, this);
  auto newTid = thread.get_id();
  if (auto* track = asTaskTrack()) track->addTrack(newTid, true);   // 根：自锚（bSelf 设 selfTid）
  else TrackMgr::get().bindTid(creatorTid, newTid);                  // 子：按创建者链查 owner 归入
}
void RunTask::stopTask() { ...; auto t = thread.get_id(); if (thread.joinable()) thread.join(); TrackMgr::get().unbindTid(t); }
```
- `asTaskTrack()` 是 RunTask 的虚函数（默认 `nullptr`），大对象 override `return this`。**用虚函数而非 `dynamic_cast`**：MediaPlayer 多重继承 `RunTask`+`TaskTrack`，两者是独立基类分支，`dynamic_cast<TaskTrack*>(RunTask*)` 跨分支转型**编译不过**。
- 大对象多写「继承 `TaskTrack` + override `asTaskTrack() return this` + `getTrackName` 返回 "MP"」，子任务零改动、不持父指针。

## 第三方线程

- **IOParseFF 不改**：IO 线程走 RunTask，自动覆盖。
- **IOParseZM 手动**：构造时记 `parentTid = this_thread`（player 主线程，IOParseZM 在 cmdOpen 主线程构造）；ZM 回调/dispatch 入口 `TrackMgr::bindTid(parentTid, this_thread)`，去重。WebRTC signal 同理。
- ⚠️ 若 ZM EventPoller 共享（一线程多 player），"绑过不绑"会串，回调入口需先 `unbindTid` 再 `bindTid`。待确认 ZM 线程模型。

## 日志

`logMsg` 入口（仍在工作线程）`item.tag = TrackMgr::get().currentTag()`，`LogItem` 加 `tag` 字段入队。输出时 tag 非空拼前缀（拼进 `msg`，零 ABI 破坏）。多实例判定按 `getTrackName` 运行时存活计数。

## 关键陷阱

1. **异步日志时序（最重要）**：归属必须在 `logMsg` 入口解析入队，不能在 LogTask 后台消费时查（否则查到 LogTask 自己）。
2. **tid 复用**：`bind`/`unbind`（start/stop）配对即规避。
3. **ZM 共享线程池**（待确认）：见上。
4. **性能**：`current()` 用 thread_local 缓存，避免热路径加锁查表。
