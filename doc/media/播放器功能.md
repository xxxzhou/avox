## 软/硬解切换

播放器在正常播放的过程，把解码器关了重开，主要有二点，一是这个关掉解码器引发过程，需要放在解码器自身的线程上，主要是网络流一播放是在I帧前插入配置帧，而在播放器因用户点击切换命令后，需要让解码器知道一个切换flag,当在读到配置帧，并到了I帧，说明已经有最新的配置帧了，并且因为下一个是I帧，新的解码器就可以直接用这所有信息马上重启解码，给用户最好体验。如下在播放器需要重置后，在解码线程检查到I帧，则退出相应的解码线程，并返回给播放器线程，由播放器线程来做后续重开解码与渲染，为什么需要重置渲染，主要是渲染对象会因解码是软/硬解有不同处理，比如软解的对象是内存对象，而硬解出来的纹理对象，在渲染会因解出来的对象而做不同处理，主要这并不影响窗口，当然需要先做到上面的解码渲染与窗口分离。

这个功能还可以应用到流有分辨率变化的时候，需要重置解码器的上面。

``` C++ 
// 播放器线程发出需要重置的命令，得到解码器线程执行
void MediaPlayer::cmdResetDecode(ResetDecodeCommandPtr cmd) {
  bool bHardDecode = cmd->getData();
  PBMediaAction pb = {};
  LOGFLF(LogLevel::info, bHardDecode);
  for (const auto &vtrack : videoTracks) {
    if (vtrack && vtrack->vaild()) {
      // 通知track准备重置解码器
      vtrack->setResetDecoderFlag();
      // 记录开始切换解码
      pb.mediaObject = MediaObject::decode;
      pb.action = MediaAction::reset;
      pb.trackType = TrackType::video;
      mpPingback->pushPB<MPPBType::MediaAction>(pb);
    }
  }
  // 记录track的状态
  recordRingBuffer();
}

// track里的Frame清空队列，软硬解队列使用不同数据
void VideoTrack::onResetDecoder() {
  // 不同解码器，帧队列可能不同，清空原队列
  frameQueue.clear([](const VideoFramePtr &frame) { frame->release(false); });
  clock->reset();
  // 当前在解码器线程中，转到播放器线程中重开解码器
  if (mediaPlayer) {
    mediaPlayer->onResetDecoder();
  }
}
// 解码器退出循环后给播放器发现消息
void MediaPlayer::onResetDecoder() {
  // 通知所有track重置解码器
  auto resetCompCmd = createCommand<MPCommandType::ResetDecodeComplete>();
  mpCommands.enqueueWait(resetCompCmd);
}
// 播放器线程重启解码对象，保持播放器内对象生死都在播放器内线程
void MediaPlayer::cmdResetDecodeComplete() {
  PBMediaAction pb = {};
  for (const auto &vtrack : videoTracks) {
    if (vtrack && vtrack->vaild()) {
      // 重置解码与渲染对象，渲染对象会因解码是软/硬解有不同处理
      vtrack->start();
      // 记录切换解码器完成
      pb.mediaObject = MediaObject::decode;
      pb.action = MediaAction::complete;
      pb.trackType = TrackType::video;
      mpPingback->pushPB<MPPBType::MediaAction>(pb);
    }
  }
  // 记录track的状态
  recordRingBuffer();
}
```

``` C++
  template <typename B>
  void
  enqueueWait(const B &item,
              std::function<bool(T &right, const B &left)> matchCond,
              std::function<void(T &right, const B &left, bool bMatch)> func,
              std::function<bool()> runCond) {
    {
      // 先查询队列最后一个元素,如果满足条件,则在最后元素上操作
      std::lock_guard<std::mutex> lock(buMtx);
      if (wcount > 0) {
        T &witem = buffer[(rindex + wcount - 1) % maxSize];
        if (matchCond(witem, item)) {
          func(witem, item, true);
          return;
        }
      }
    }
    // 封装一个新的 lambda 函数，将 bMatch 固定为 false
    std::function<void(T & right, const B &left)> adaptedFunc =
        [&func](T &right, const B &left) { func(right, left, false); };
    while (runCond()) {
      // 如果队列满了,等待
      if (enqueue(item, adaptedFunc, false)) {
        break;
      }
```
