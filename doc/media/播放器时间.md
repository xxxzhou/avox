# 播放器时间相关功能

记录下最近关于音视频同步, 倍速播放, 低延迟自适应功能相关实现.

## 音视频同步

### 视频渲染

视频帧由解码线程产生, 如果有窗口显示的, 一般由窗口线程消费视频帧, 控制窗口线程的刷新时间则是音视频同步的关键. 如下主要是仿ffplay里的同步逻辑.

如下假定没有音视频需要同步, 只有视频如何刷新.

1. 选择一个基准, 可以是第一个I帧渲染时对应的系统时间.
2. 根据二个PTS差值计算出duration(帧间隔), 在基准下算出下一个基准时间, 这里需要确认duration有效值, 比如过大或是少于0, 认为PTS失效或是跳变, 需要更新基准时间为当前系统时间.
3. 如果基准时间比当前时间快, 则跳出窗口tick等待下一个Tick, 这种可能是窗口刷新频率比PTS高, 或是解码失败, 比如25FPS, 默认是40ms, 如果有一帧解码失败, 则差值是80ms, 也会如此, 这种情况并没多大影响, 跳出tick等待就可.
4. 更新基准时间, 就是加上当前二帧PTS的差值, 对应下一帧的渲染时间, 正常情况下, 当下一帧进来时, 其基准时间与当前系统时间差值很小.
5. 检查基准时间, 如果基准时间比当前时间慢, 比如窗口刷新频率比视频的慢, 多帧后累积, 窗口线程卡住了等. 如果基准时间比当前时间慢不到duration, 认为是正常情况, 如果慢了超过duration, 但是不到100ms, 则认为基准时间还有效, 但是需要丢帧, 让窗口快速刷新追赶回来, 如果超过100ms, 认为基准时间失效, 一般是重设当前系统时间为基准时间.
6. 重复2-5流程.

基准时间, 我的理解是窗口渲染线程在系统时间线上记录一个刻度, 然后在每次窗口渲染时, 并根据视频的PTS增加, 保持刻度更新, 正常情况这个刻度应该与当前系统时间差值很小. 当然现实是会有各种异常情况的, 比如PTS跳变, 解码失败, 窗口线程Tick频率比视频慢等, 就需要根据上面逻辑调整基准时间.

从上面来看, 基准时间可以控制窗口渲染线程的刷新频率, 下一帧基准时间对应当前基准时间+duration, 如果改变duration的值, 比如减少duration, 则下一帧渲染时间提前, 则窗口渲染会变快, 如果增加duration, 则下一帧渲染时间延后, 则窗口渲染会变慢. 视频同步别的源就是基于这个原理.

### 音频渲染

音频的渲染相对视频来说, 会简单一些, 比如音频渲染没有FPS概念, 一般来说, 就是把数据丢给音频硬件去渲染, 正常来说, 也不会计算PTS与音频数据是否对应, 因为就算不对应, 默认方式也是把解码后的数据丢给音频硬件渲染, 别的方式丢音频或是加静音可能导致音频更不正常, 影响人耳感觉. 可以说, 如果没有视频, 音频的PTS差不多就是无效数据.

视频提到改变基准就可以改变窗口渲染频率, 那音频呢? 改变音频的渲染速度, 最简单的方式如下, 假定16K, 单通道, 16bit, 10ms的数据量是320字节, 如果把10ms对应数据缩短成160字节去播放, 5ms就播放完了, 从播放效果上来说, 就是音频播放快了一倍, 如何把320字节的音频变成160字节, 最简单的方式就是用重采样把16K的采样率变成8K, 但是同样的音调也变了, 为了更好的效果, 可以改为SoundTouch来处理.

### 同步渲染

音视频同步的前提是PTS统一, 在一个基础上进行比较, 比如音频以100ms起点, 视频500ms, 这可以认为都是100ms起头的. 但如果音频PTS是100ms开头, 视频是10000ms开头, 你可以假定音频以100开头, 视频以10000开头, 但是这个假定是不一定成立的, 还有PTS播放中有跳变, 以及在一段时间内, 音频与视频的跨度不一致等导致PTS不统一的问题, 这些现实情况如何处理都需要考虑.

音视频同步一般来说会选择音频渲染为主, 比如25FPS, 中间丢一帧, 人眼感觉并不明显, 如果是音频, 丢帧或是加快与慢, 耳朵会感知明显, 为了更好的感受, 一般会选择音频渲染为主, 视频根据音频渲染来调整.

二者间的同步, 需要在同一参考物来比较, 这个参照物一般选择系统时间, 相应逻辑在ffplay中是由clock封装, 以同样的系统时间为基准, 估算各自当前的PTS. 主要逻辑就是, 每次更新PTS时, 计算PTS与系统时间的差值, 在获取当前PTS时, 只需要计算当前与上次系统时间的差值, 就可以得到当前PTS.

有了clock, 音频与视频就可以随时比较PTS, 这里假定以音频为主, 根据音频PTS来调整视频, 相对原来视频渲染来说, 只需要调整第二步里的逻辑, 当视频计算出duration后, 需要根据音频与视频的PTS, 重新调整duration, 这样可以保证视频与音频的同步.

1. 正常情况, 比较音频与视频的clock估算的的PTS, 差值在100ms内, 视频不做处理, 还是以duration的逻辑渲染.
2. 视频比音频慢100ms以上, duration改为0, 把视频基准时间减少, 这样窗口会刷新比较快, 直到视频慢慢追赶上来.
3. 视频比音频快100ms以上且视频的duration大于100ms, duration改为duration加上差值, 把视频基准时间放大, 导致跳过取帧过程等待音频渲染上来.
4. 视频比音频快100ms以上当视频的duration正常, duration改为二个duration, 同3一样, 只是duration扩充没3大.

窗口需要感知到同步情况, 比如第二种, 就是想法让窗口快速刷新, 跳过sleep, 第三种和第四种跳过窗口渲染, 因为并没取到视频数据, 并等待合适时间尝试下一次tick.

如果音频以视频为主的话, 也是比较二个clock的差异, 主要区别是音频一般是收集足够的样本后, 然后计算平均误差, 再根据误差来调整输入与输出字节数据, 得到变化后的采样率, 重采样后再渲染.

## 变速播放

**核心原则: PTS永远不变, 调整渲染间隔.**

现在视频本身是25FPS, 这样每个间隔就是40ms, 如果每个间隔改为20ms, 则播放速度就变为2倍, 如果改为10ms, 则播放速度就变为4倍. 音频也是类似, 原来16K, 单通道, 16bit, 10ms的数据量是320字节, 如果现在把这320字节信息变成160字节, 则渲染器只需要5ms就渲染完, 这样音频速度就变为2倍.

基于上面, 假定4倍速的调整流程:

1. IO线程里, **PTS保持不变**, 原来正常25FPS, 其PTS还是40, 80, 120.
2. 视频窗口渲染中, **duration调整为 duration / speed**, 原40ms间隔现在变为10ms, 窗口以10ms间隔渲染.
3. 音频渲染中, 原16K采样率需要重采样到4K, 一般来说, 音频在0.5-2倍之间, 还给硬件去渲染, 在这个范围外, 渲染线程还是消费音频帧, 但是不渲染音频, 关闭音视频同步, 因为此时音频已经严重失真了.

注意: 改变速度后, 如果根据当前包的PTS来做, 这样当倍速变化后, 渲染间隔会跳变, 比如原来0.5倍, duration是80ms, 当切换成1时, duration变回40ms. 为了保证连续播放, 使用累积时间+duration/speed来计算下一帧渲染时间.

### RTSP服务器变速特殊情况

有些特殊倍速实现, 如RTSP源4倍速以上, 会选择只发I帧, 这时就会发生一种情况:

| 场景 | 收到间隔 | PTS间隔 | duration/speed |
|------|----------|---------|----------------|
| 正常1x | 40ms | 40ms | 40ms |
| 4x全帧 | 10ms | 40ms | 10ms |
| 8x只发I帧 | ~250ms | 1600-2000ms | 200-250ms |

正常情况下, 40ms来一个40ms间隔的包. 4倍及以下, 可能每10ms来一个间隔40ms的包. 而在8倍及以上, 可能需要250ms才来一个间隔1600-2000ms的包(I帧间隔).

这种情况下, **PTS仍然是原始I帧时间戳**, 但渲染间隔通过 duration/speed 计算, 大约为200-250ms.

### 代码实现

视频渲染端, 统一使用 duration/speed 调整渲染间隔:

```cpp
// VideoTrack::syncVideo()
int64_t sduration = duration;
// 变速后, 调整duration, 让间隔时间根据speed变化
sduration = (int64_t)((double)duration / speed);
```

音频渲染端, 通过重采样实现变速:

```cpp
// 倍速变化, 改变采样率
changeDesc.sampleRate = renderDesc.desc.sampleRate / speed;
speedResample->init(renderDesc.desc, changeDesc);
```

变速最开始是直接修改源包里的PTS时间, 但是这有个问题, 速度从低到高, 再从高到低, 如果每次是变速的时间为基点, 就会出现跳变, 如果累积时间, 错误就会积累, 再加上有时流里包的时间也会有错误, 这个逻辑会很复杂, 越复杂越容易出错, 最后以不改源包时间, 直接在最终渲染时做处理. 视频直接以间隔时间做变速处理, 而音频则是重采样做变速处理.

## 低延迟自适应播放

有些直播源的服务器秒播的实现会缓存当前GOP从配置与I帧到当前数据, 这样当播放端拉数据时, 会拉取比较久的数据, 表现播放的延迟会比较大, 还有网络影响下, 比如网络不好拉不到数据进入buffing, 然后又来了一大段数据, 播放就会以二个队列满数据高延迟来播放.

在完善音视频同步与变速功能后, 可以这二个功能的基础上实现低延迟自适应播放. 原理比较简单, 检查如视频队列中的延迟时间, 比如当前视频渲染队列(100-400ms), IO包队列(440-800ms), 这样整个延迟是700ms, 设定一个值, 大于这个双倍这个值, 自动1.5倍播放, 播放到少于设定值, 恢复正常播放.

上面流程相关代码参考.

IO包相关处理, 包含对齐包时间, 检查包时间戳跳变, 检查累积时间戳是否一致, 检查音频与视频跨度是否一致, 检查是否需要同步, 检查是否需要调整累积时间戳.

```cpp
// 对齐包时间
// 1. 如果有视频, 以第一个I帧为基准
// 2. 如果有音频没有视频, 以第一个音频包为基准, 否则以I帧视频后的音频为基准
// 3. 如果音频与视频时间差小于5秒, 以第一个I帧的PTS为基准
// 4. 如果音频与视频时间差大于5秒, 让播放器不要同步, 各播各的
// 5. 如果音频或视频时间戳有跳变, 重新设置基准时间
// 6. 如果音频与视频跨度差异太大, 让播放器各播各的
// 7. 计算受变速影响的累积时间, 并在每次变速后重新校准
void alignPacketPts(AvoxPacket &packet);
void checkJump(int64_t pts, TrackInfos &info);
void ajustPts(AvoxPacket &packet, TrackInfos &info);
// 多次变速后, 会导致累积时间误差变大, 检查累积时间是否一致
void checkAccPts();

void AVSource::alignPacketPts(AvoxPacket &packet) {
  // log(LogLevel::info, " pts:", packet.pts);
  PackType type = (PackType)packet.packtype;
  // 先确定基准时间
  if (type == PackType::video && videoInfo.firstPts == AVOX_NOVALID_PTS) {
    // 视频以第一个关键帧的时间为基准
    // 或者视频有跳变, 以跳变后时间为基准
    if (packet.frameType == 1) {
      videoInfo.firstPts = packet.pts;
      videoInfo.accPts = 0;
      baseTimeMS = videoInfo.firstPts;
      LOGFLF(LogLevel::info, "first video pts:", videoInfo.firstPts,
             " base time:", baseTimeMS);
    }
  } else if (type == PackType::audio && audioInfo.firstPts == AVOX_NOVALID_PTS) {
    // 音频如果在有视频的情况下, 以视频关键帧后包为基准
    if (videoInfo.bHave) {
      if (videoInfo.firstPts != AVOX_NOVALID_PTS) {
        audioInfo.firstPts = packet.pts;
        audioInfo.accPts = 0;
        LOGFLF(LogLevel::info, "first audio pts:", audioInfo.firstPts);
      }
    } else {
      // 如果没有视频, 音频其实并不需要设置PTS
      audioInfo.firstPts = packet.pts;
      audioInfo.accPts = 0;
      baseTimeMS = packet.pts;
      LOGFLF(LogLevel::info, "first audio pts:", audioInfo.firstPts,
             " base time:", baseTimeMS);
    }
  }
  // 如果有视频与音频, 比较firstAudioPts与firstVideoPts
  if (!bSyncPts && videoInfo.firstPts != AVOX_NOVALID_PTS &&
      audioInfo.firstPts != AVOX_NOVALID_PTS) {
    // 音频与视频时间差大于5s, 放弃同步, 大家各走各的
    if (std::abs(audioInfo.firstPts - videoInfo.firstPts) > 5000) {
      LOGFLF(LogLevel::warn, "first audio pts:", audioInfo.firstPts,
             " first video pts:", videoInfo.firstPts,
             " base time:", baseTimeMS);
    } else {
      // 如果时间差小于5s, 都以baseTimeMS为基准
      videoInfo.firstPts = baseTimeMS;
      audioInfo.firstPts = baseTimeMS;
      videoInfo.accPts = 0;
      audioInfo.accPts = 0;
      LOGFLF(LogLevel::info, "base time io:", baseTimeMS);
    }
    // 通知播放器, 重新调整了基准时间
    dispatch(&IAVSourceOb::onSyncPts);
    bSyncPts = true;
  }
  // 检查音频与时间跨度是否一致
  if (!bCheckOffset && videoInfo.firstPts != AVOX_NOVALID_PTS &&
      audioInfo.firstPts != AVOX_NOVALID_PTS) {
    int64_t videoOffset = videoInfo.prePts - videoInfo.firstPts;
    int64_t audioOffset = audioInfo.prePts - audioInfo.firstPts;
    // 采够足够时间后, 音频跨度与视频跨度是否大致一样, 查看
    if (videoOffset > 5000 && audioOffset > 5000) {
      double ratio = (double)audioOffset / (double)videoOffset;
      if (ratio < 0.5 || ratio > 2) {
        LOGFLF(LogLevel::warn, "io packet warning, video offset:", videoOffset,
               " audio offset:", audioOffset);
        // 这种情况下, 音频与视频的时间差越来大, 让播放器各放各的
        videoInfo.firstPts = AVOX_NOVALID_PTS;
        bSyncPts = false;
        bCheckOffset = true;
      }
    }
  }
  // 如果时间戳有跳变, 以跳变后时间重设
  int64_t packPts = packet.pts;
  if (type == PackType::video) {
    checkJump(packPts, videoInfo);
  } else if (type == PackType::audio) {
    checkJump(packPts, audioInfo);
  }
  // 每次变速后, 放在IO线程里来重新校准累积时间戳
  if (bSpeedChanged) {
    checkAccPts();
    bSpeedChanged = false;
  }
  // 对齐
  if (type == PackType::video || type == PackType::vconfig) {
    ajustPts(packet, videoInfo);
  } else if (type == PackType::audio || type == PackType::aconfig) {
    ajustPts(packet, audioInfo);
  }
}
```

视频以PTS间隔渲染, 以及同步, 参考ffplay实现.

```cpp
// ffplay video_refresh
// -1 视频帧慢了, 丢弃, 无效帧 0 同步帧 1 视频帧快了 2 队列没帧了
int32_t VideoTrack::syncVideo() {
  // 取队列的最前面frame的数据, 但是不弹出
  VideoFramePtr frame = nullptr;
  bool bGet = frameQueue.peek(frame);
  if (!bGet) {
    return 2;
  }
  double speed = clock->getSpeed();
  int64_t pts = frame->pts;
  int64_t tPts = prePts;
  // 记录自身基准, frameTimer
  renderFirst();
  // frame没有使用, 故不更新, 保持正常的duration
  if (pts != prePts) {
    // 更新pts与duration
    updatePts(pts);
  }
  int64_t sduration = duration;
  // 变速后, 调整duration, 让间隔时间根据speed变化
  sduration = (int64_t)((double)duration / speed);
  int64_t now = timeStampMS();
  // 时间戳跳变, 如何处理? 先记录
  if (sduration > AVOX_NOSYNC_THRESHOLD || sduration < 0) {
    log(LogLevel::warn, "video render jump:", duration, " now pts:", pts,
        " pre pts:", pts - duration, " main pts:", mClock, " speed:", speed);
    renderTime = now;
    duration = 0;
    sduration = 0;
  }
  // delay<duration视频慢了 delay>duration视频快了
  int64_t delay = computeDelay(sduration);
  // 还不到渲染时间, 让窗口等待
  if (renderTime + delay > now) {
    return 1;
  }
  // 下次更新时间, renderTime应该一直now的时间差不多
  // now受刷新线程影响, 如果刷新线程每次比duration慢1-2ms
  // 如果是20FPS, 大约20多帧后, renderTime比now小一帧时间, 引发丢帧
  renderTime = renderTime + delay;
  // renderTime应该与now差不多
  if (delay > 0 && now - renderTime > AVOX_SYNC_THRESHOLD_MAX) {
    log(LogLevel::warn, "reset render time:", renderTime, " now:", now,
        " delay:", delay, " duration:", duration, " pts:", pts,
        " pre pts:", tPts);
    renderTime = now;
  }
  // 更新时钟并同步给播放器
  updateClock(pts);
  // 渲染时间慢了, 需要丢帧
  if (now > renderTime + sduration * 1.5 && sduration > 0) {
    int64_t dropPts = 0;
    // GPU数据丢弃需要通知frame好做后续处理
    frameQueue.pop([&](const VideoFramePtr& frame) {
      dropPts = frame->pts;
      frame->release();
    });
    log(LogLevel::warn, "drop frame pts:", dropPts, " main pts:", mClock,
        " now:", now, " render time:", renderTime, " speed:", speed,
        " speed duration:", sduration, " pts:", pts, " pre pts:", tPts,
        " queue size:", packetQueue.size(), " frame size:", frameQueue.size());
    return -1;
  }
  // 视频慢了, 让窗口快速刷新, 不要sleep了
  if (delay == 0) {
    // return SyncResult::slow;
  }
  return 0;
}

bool Window::preTick() {
  if (!running()) {
    return false;
  }
  if (bPause) {
    return false;
  }
  // 窗口渲染环境是否有效
  if (!onValidWin()) {
    log(LogLevel::info, wdTitle, " is invalid");
    return false;
  }
  // 检查窗口大小是否变化, 变化后需要重新生成交换链
  updateSize();
  // 窗口在Tick前处理并决定是否渲染
  if (!onPreTick()) {
    return false;
  }
  // 通知观察者可以修改类似syncType等参数
  dispatch(&IWindowOb::onWinPreUpdate);
  // syncType>0, 表示窗口刷新快了, 数据还没渲染
  if (syncType > 0) {
    syncType = 0;
    return false;
  }
  return true;
}

void Window::onRunWin() {
  while (running()) {
    // 1tick=100ns, 1ms=10000tick
    int64_t fpsTick = getFrameTick(fps * speed);
    int64_t tempTick = timeTick();
    // 窗口渲染
    bool bTick = preTick();
    if (bTick) {
      tick();
    }
    // 去除Tick时间, 余下时间sleep
    int64_t sleepTick = fpsTick - (timeTick() - tempTick);
    // 窗口刷新慢了, 不等待
    if (sleepTick <= 20000 || syncType < 0) {
      continue;
    }
    if (sleepTick > 0) {
      // 如果fpsTick与实际的duration不一致, 跳帧丢帧会比较严重
      // 再加上sleep并不能精确控制时间, 所以每次减去2ms, 尽量不丢帧
      int64_t sleepMS = std::max(1LL, sleepTick / 10000LL - 2);
      // 视频快了, 先跳出来等半帧
      if (!bTick) {
        sleepMS = sleepMS / 2;
      }
      std::this_thread::sleep_for(std::chrono::milliseconds(sleepMS));
    }
  }
}
```

音频渲染, 倍速与同步相关实现.

```cpp
void ARenderTask::onRunTask() {
  int32_t waitTime = std::max(10, trackContext->getBufferMS() - 2);
  AudioFrame frame = {};
  auto frameAction = [&](const AudioFramePtr& cframe) { frame.form(*cframe); };
  while (running()) {
    // 倍速变化大, 就不渲染声音了
    double speed = trackContext->getClock()->getSpeed();
    if (speed > 4.0 || speed < 0.25) {
      bool bGet = trackContext->getFrameQueue().dequeueAction(frameAction);
      sleepTask(!bGet, 5);
      trackContext->updateClock(frame.getPts());
      trackContext->onFrameResult(true);
      continue;
    }
    // 渲染器队列数据很满了, 就不要再获取数据了
    bool bWait = audioRender->full();
    if (!bWait) {
      // 1 获取队列里音频数据
      bool bGet = trackContext->getFrameQueue().dequeueAction(frameAction);
      if (!bGet) {
        // 渲染器队列与帧队列里都没数据了, 通知播放器buffing
        if (audioRender->empty()) {
          trackContext->onFrameResult(false);
          sleepTask(false, waitTime);
        }
        continue;
      }
      AvoxData inData = {frame.point(), frame.getSize(), true};
      // 在这可以应用速度变化如SoundTouch处理变化后的数据
      if (speed != 1.0) {
        AudioDesc changeDesc = renderDesc.desc;
        // 倍速变化, 改变采样率
        changeDesc.sampleRate = renderDesc.desc.sampleRate / speed;
#ifdef AVOX_ENABLE_FFMPEG
        AvoxData outData = {speedBuffer.data(), (int32_t)speedBuffer.size(),
                           false};
        speedResample->init(renderDesc.desc, changeDesc);
        int ret = speedResample->resample(inData, outData);
        if (ret > 0) {
          inData.data = outData.data;
          inData.size = ret;
        }
#endif
      }
      // 同步外部时钟, 确定是否需要改变数据量
      int32_t wanted_bytes = trackContext->syncAudio();
      // wanted_bytes变少需要加快音频速度, 变多需要减慢音频速度
      if (wanted_bytes != inData.size) {
        AudioDesc changeDesc = renderDesc.desc;
        changeDesc.sampleRate =
            renderDesc.desc.sampleRate * wanted_bytes / inData.size;
#ifdef AVOX_ENABLE_FFMPEG
        AvoxData outData = {audioBuffer.data(), (int32_t)audioBuffer.size(),
                           false};
        syncResmaple->init(renderDesc.desc, changeDesc);
        int ret = syncResmaple->resample(inData, outData);
        if (ret > 0) {
          inData.data = outData.data;
          inData.size = ret;
        }
#endif
      }
      // 给渲染器inData
      audioRender->render(inData);
      // 记录当前包时间
      framePts = frame.getPts();
      // 检查渲染器队列占时长
      int64_t queuedMS = audioRender->getQueueMS();
      int64_t playPts = framePts - queuedMS;
      // 更新时钟
      trackContext->updateClock(playPts);
      trackContext->onFrameResult(true);
    }
    sleepTask(false, waitTime);
    // 加入暂停功能
    waitPause();
  }
}
```

播放器是否能跳出buffering状态与是否自动快进播放减少延迟.

```cpp
void MediaPlayer::tick() {
  // 倍速相关太大, 就关闭同步
  closeSync(cspeed > 1.5 || cspeed < 0.5);
  // 如果是buffering状态, 并且上次状态是playing, 避免暂停进入buffering回复播放
  if (state == PlayerState::buffering && preState == PlayerState::playing) {
    // 是否缓冲了足够的数据, 查看音频与视频最大的队列时间
    int64_t queueTime = getQueueTime();
    if (queueTime > delayMs) {
      // 恢复渲染
      pauseRender(false);
      setState(PlayerState::playing);
    } else {
      if (bufferChecker.timeout()) {
        // 一直buffing超时了, 还没打开, 关闭
        log(LogLevel::warn, "buffering timeout, close player");
        cmdClose();
      }
    }
  }
  // 播放下, 特别是刚连接服务器时, 服务器为了秒开会缓冲一组GOP
  // 服务器会把缓存的一段GOP数据过来, 如果正常播放, 时延会比较大
  if (bLowLatency && sourceMode == MediaSoureMode::live) {
    // 只有正常播放状态下才处理
    // 有B帧时不太好用, B帧计算getQueueTime是乱的
    // cspeed只记录用户设置的速度, 不记录自动调整的速度
    if (state == PlayerState::playing && cspeed == 1.0) {
      double autoSpeed = 1.5;
      // 有视频的源才启用自动快播, 也以视频的时延为准
      int64_t queueTime = getQueueTime(TrackType::video);
      // 队列数据太多, 播放速度1.5x, 减少延迟
      if (queueTime > delayMs * 2) {
        if (clock->getSpeed() != autoSpeed) {
          setSpeed(autoSpeed, true);
          log(LogLevel::info, "player auto speed 1.5x,queue time:", queueTime,
              " delayMs:", delayMs);
          recordRingBuffer();
        }
      } else {
        // 消费差不多了, 恢复1.0x
        if (queueTime != AVOX_NOVALID_PTS && queueTime < delayMs &&
            clock->getSpeed() != 1.0) {
          setSpeed(1.0);
          log(LogLevel::info, "player auto speed 1.0x,queue time:", queueTime,
              " delayMs:", delayMs);
          recordRingBuffer();
        }
      }
    }
  }
}
```
