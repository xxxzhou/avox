# 测试与修复工作流

> 配合 [环境与插件总览](环境与插件总览.md)（关系地图）使用；跑完的**结果**只更新
> [功能测试矩阵](功能测试矩阵.md)，本文只讲「怎么跑、怎么判、怎么归因、怎么修」。

## 1. 标准回归循环

任何功能修复/新特性，都走这六步，大模型可直接照做：

```
① 构建    改了主仓 C++ → python build_windows.py（改动只涉及 Android 时 build_android.py）
② 部署    Godot: junction 免拷贝，重建后自动生效
          Unity: avox-unity\tools\deploy_unity.ps1（拷 dll 进包 + /MIR 镜像 demo）
          UE:    avox-ue\tools\deploy_plugin.ps1（拷源码/dll/spv 进 demo Plugins）
          ⚠ Unity 走之前先过总览 §4 的 FFmpeg 代际检查
③ 推流    python script/testenv/push_streams.py（ZLM 本机；真机加 --lan-ip=<局域网IP>）
④ 跑测试  按下文 §2 分层命令跑，等 [AVOX][TEST] 判定行
⑤ 汇总    python script/testenv/collect_verdicts.py <日志|->
⑥ 记录    结果只写功能测试矩阵.md 对应波次；修复后必须回归同 case 并更新该行
```

## 2. 分层测试命令速查

分层思想（`platform/README.md`）：先无 UI 的底层验证，再上引擎，最后真机。低层绿了再往上排查。

### 第 0 层：单测（秒级，先跑这个）

```bash
ctest --test-dir build/windows/avox --output-on-failure -C Release
```

### 第 1 层：SDK 原生样例（无引擎，验证 SDK 本体）

| 目的 | 命令（产物在 `build\windows\avox\install\AMD64\Release\`） |
|------|------|
| 播放/渲染窗口 | `vulkantest` 系（vkwindowtest 等）；`functest` 系为控制台专项 |
| WebRTC 无头拉流 | `rtcplayheadless`（连接+首帧即 PASS，自带判定行 case=webrtc-play） |
| WebRTC 窗口拉流 | `webrtcplaytest <信令URL>`（URL 可 argv 传入） |
| 帧布局契约/截图 | `yuvouttest`；截图类用 `tooltest -screenshot ...` |
| mac 播放/RTC | `macplaytest` / `macrtcplaytest`（用法见矩阵 W5 段，可存图轮询） |

其它：`test_probe.gd`（torrent，依赖外网，只看退出码）；GUI 工具箱 `python platform/godot/run_tools.py hub|player`。

### 第 3 层：引擎内自动化

Unity（batchmode，装好编辑器后）：

```powershell
cd <root>\avox-unity\tools    # <root> = 与 avox 同级的父目录, 见总览 §1
.\deploy_unity.ps1
.\test_unity.ps1        # 冒烟(dll链+create/destroy) + 软解播放断言(尺寸+进度), 全绿 exit 0
python .\check_licenses.py   # deploy 后必跑
```

盲区（脚本头也写明）：batchmode 无渲染循环，**验不了 Vulkan 直通**（会崩）；GPU 直通只能交互式编辑器验，
唯一例外 D3D11 拷贝模式可 batchmode 像素级回归（`AvoxDx11Test`，见 avox-unity `docs/troubleshooting.md`）。

UE（装好编辑器后）：

```powershell
cd <root>\avox-ue\tools
.\deploy_plugin.ps1
.\build_demo.ps1
# demo 工程已开 bRemoteExecution; 编辑器打开后:
python .\run_verify.py [URL] [hard]     # 远程下发 verify_playback.py, 看 [AvoxVerify] SUCCESS, 自动退出编辑器
# 无人值守/CI 用打包游戏而非编辑器 slate(编辑器回调会被节流): tools\run_packagegame.cmd
```

## 3. 判定与归因规则

- **判定**只认 `[AVOX][TEST]` 行 / 脚本退出码 / 明确断言输出（如 `[AvoxVerify] SUCCESS`）。「看起来在播」不算 PASS。
- headless 与 GUI 不一致时（尤其 GPU 路径），先怀疑直通链路：headless 无 RenderingDevice → GPU 直通被跳过，
  headless 绿 ≠ 直通好，反之 headless 崩 ≠ GUI 会崩。

### BUG 归属判定树（决定改哪个仓）

```
现象能被 SDK 原生样例(第1层)复现?
├─ 能   → avox 主仓 (src/ plugins/)：解码/网络/时钟/渲染核心
└─ 不能 → 只在引擎里坏，区分:
   ├─ 桥接层(纹理导入/帧重排/dll加载/生命周期):
   │   Unity(avox_unity.dll) → 改主仓 platform/unity/plugin/src
   │   Godot(avox_godot.dll) → 改主仓 platform/godot/plugin/
   │   UE(AvoxPlayer 模块)   → 改 avox-ue 私仓
   │   ※ Godot 最小复现工具: avox-godot demo/dev/bare_smoke.gd, 专用于区分"桥接层坏"还是"场景用法错"
   ├─ demo/场景/文档/打包脚本 → 对应私仓
   └─ 分不清 → 先在最小复现里关 GPU 直通跑一遍: 关了就好=直通链, 还坏=帧通路/播放器层
```

修复铁律：
1. 涉及主仓 API/帧契约的修复，**主仓与插件仓成对提交**（历史先例：RtcEngine 泄漏 d06a627 ↔ avox-godot 8acbd23）。
2. 桥接层踩的坑优先写进对应私仓 `docs/troubleshooting.md`（那里是踩坑实录的高密度区）。
3. 修完回归原 case + 更新功能测试矩阵，未修的悬案也记在矩阵里（如 W3 的 RTC 9fps 问题）。
