## W5 — macOS (Mac M2 / macOS 26.1, 2026-09-09 实测)

构建: `AVOX_BUILD_TYPE=Release AVOX_CMAKE_ARGS=-DAVOX_ENABLE_SAMPLES=ON python3 build_mac.py`
（Windows 侧 `push_streams.py --lan-ip=192.168.68.245` 供流, Mac 拉 LAN）。
FFmpeg 9.0.1 IO 用 `avox-verify` 无头离屏 app（`AVOX_IO_PLAN=ffmpeg`, 15s 定长），
WebRTC 用仓内样例 `rtcplayheadless`（判定行 case=webrtc-play）。

| case | 结果 | 备注 |
|------|------|------|
| ctest avox_tests | PASS | build/macos/avox |
| ffmpeg9 rtsp-h264 | PASS | playing, fps 24.6, VideoToolbox 硬解 + Metal |
| ffmpeg9 rtsp-h265 | PASS | playing, fps 28.3 |
| ffmpeg9 hls (h265) | PASS | playing, fps 28.3 |
| ffmpeg9 http-ts (h264) | PASS | playing, fps 29.9 |
| ffmpeg9 rtmp (h264) | PASS | 修 rtmp 传 `timeout` 隐式 listen 后通 (fps 28.9), 修前必 `open input failed` |
| webrtc 拉流 h264 (live/avox264) | PASS | conn=connected, 首帧, loss 0, rtt 0-2ms |
| webrtc 拉流 h265 (live/avox) | PASS | 同上 |
| macplaytest 窗口播放 (rtsp-h264) | PASS | 自建 NSWindow + CAMetalLayer, playing/pos 19.8s/fps 31.6, 按 p 存 PNG |
| 退出码 | PASS | 曾经 EXIT=134: `libmk_api.dylib toolkit::Logger::~Logger` → `LogContextCapture::~LogContextCapture` 抛 `recursive_mutex lock failed`; 根因是 Apple 静态链没有 DllMain(DETACH) 去跑 `AvoxManager::clean()`(内含 `mk_env_release`), Logger 单例撑到静态析构期。现 zl io init 泄漏一份 Logger 引用, zlmediakit/ffmpeg 两种 IO 均 EXIT=0 |

macOS 上编样例需显式 `-DAVOX_ENABLE_SAMPLES=ON`（默认仅 Win/Linux 开），且 Apple 静态
libavox.a 必须整档 `WHOLE_ARCHIVE`，否则 `AVOX_REGISTER_MODULE` 的静态注册被 ld 丢弃
（`createWebRtcPlayer()` 返回 null 直接段错误）。

看画面（Mac 无显示器/远程时）：mac 端已开屏幕共享（`kickstart -activate`, launchd 监听 5900），
Windows 用 VNC 客户端连 `192.168.68.219:5900`；窗口程序用样例 `macplaytest`：

```bash
build/macos/avox/install/aarch64/Release/macplaytest.app/Contents/MacOS/macplaytest \
  rtsp://<LAN>:554/live/avox264 [超时秒 0=关窗为止] [ffmpeg|zlmediakit]
# 窗口内按 p 存 /tmp/avox_shot.png, q 退出
```
