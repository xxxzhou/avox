## 1. 仓库地图

相关仓共五个。**没有固定盘符/检出路径**——唯一硬约定是几个插件仓与 avox 主仓**同级并列**（同一个父目录下），
deploy/打包脚本全部按 `../avox/...` 这类相对路径找兄弟仓和构建树；个别入口可用环境变量把构建树指到别处
（UE `AVOX_RELEASE_DIR`、Unity `AVOX_BUILD_DIR`、依赖库 `AVOX_EXTERNAL_LIBRARY_DIR`），但同级是默认约定。
下文用 `<root>` 指这几个仓共同的父目录（本机当前检出在 `Q:\Work\github`，只是示例，换机器/换盘不变更约定）。

| 仓库 | 职责 | 活跃入口 |
|------|------|----------|
| `<root>\avox`（本仓） | SDK 核心 + **三个引擎的桥接层源码**（UE 除外） | `build_*.py`、`platform/`、`script/` |
| `<root>\avox-ue` | UE 插件**全部**源码（AvoxPlayer）+ demo + 打包/验证工具 | `tools/`、`plugin/AvoxPlayer/` |
| `<root>\avox-unity` | Unity UPM 包（`com.avox.player`）+ demo + 部署/回归/合规工具 | `tools/`、`plugin/com.avox.player/` |
| `<root>\avox-godot` | Godot 插件分发仓：demo 工程 + 打包/合规工具（**无 C++ 源码**） | `tools/`、`demo/` |
| `<root>\avc_library` | 大型预编译依赖（WebRTC/ONNX/OpenCV 等） | `3rdparty/library/<平台>/` |

### 代码归属（修 BUG 前必看，详见工作流文档的归属判定）

| 产物 | 源码位置 | 说明 |
|------|----------|------|
| `avox.dll` 及全部核心/插件 | avox 主仓 | `src/`、`plugins/` |
| `avox_unity.dll`（Unity 桥接） | **avox 主仓** `platform/unity/plugin/src` | 由主仓 CMake `AVOX_ENABLE_UNITY` 编出 |
| `avox_godot.dll`（GDExtension） | **avox 主仓** `platform/godot/plugin/` | 由主仓 CMake `AVOX_ENABLE_GODOT` 编出 |
| UE 桥接（AvoxGpuInterop 等） | **avox-ue 私仓** `plugin/AvoxPlayer/Source/` | 主仓 `platform/ue/` 只剩迁移公告（2026-09-05 迁出） |
| UPM 包/demo/部署脚本 | avox-unity 私仓 | 主仓 `platform/unity/` 的 deploy 脚本是**开发流旧版**（见 §4 警告） |
| Godot demo/打包脚本 | avox-godot 私仓 | 主仓 `platform/godot/tools/` 是内部工具箱工程（另有所用） |

## 2. 构建产物流

```
python build_<platform>.py
   └→ build/<平台>/avox/install/<架构>/<类型>/     ← 唯一的产物集散地
        Windows: build\windows\avox\install\AMD64\Release\
                 (avox.dll + avox_godot.dll + FFmpeg dll + plugins\ + assets\glsl + ..\include\avox)
        Android: build\android\avox\install\aarch64\
        macOS:   build\macos\avox\install\aarch64\Release\
   └→ deploy 脚本按需拷贝/挂载到各引擎工程：
        Godot: platform/godot/plugin/deploy_godot.ps1   → addons/avox_godot/bin junction（免拷贝，构建即生效）
        Unity: avox-unity\tools\deploy_unity.ps1        → 拷 9 dll + assets 子集进 UPM 包，/MIR 镜像到 demo
        UE:    avox-ue\tools\deploy_plugin.ps1          → 拷源码+头+lib+dll+glsl spv 进 demo Plugins/AvoxPlayer（双份）
```

| 构建命令 | 平台 | 备注 |
|----------|------|------|
| `python build_windows.py` | Win x64 | `AVOX_BUILD_TYPE` 默认 Release、增量；`--flavor=commercial\|agpl`；`AVOX_CMAKE_ARGS` 透传 |
| `python build_android.py` | arm64-v7a/arm64 | NDK 26.1.10909125；`AVOX_FORCE_REBUILD` 默认 True |
| `python build_mac.py` | macOS | 需 `-DAVOX_ENABLE_SAMPLES=ON` 才编样例；Apple 静态库必须 WHOLE_ARCHIVE |
| `python build_ios.py` | iOS arm64 | 当前链接失败待救活（见矩阵 W5） |
| `python build_linux.py` | Linux x64 | 额外参数用 `AVOX_EXTRA_CMAKE_ARGS`（与其它平台不同名） |

## 3. 平台 × 引擎支持矩阵

| | Windows x64 | Android arm64 | iOS | macOS |
|---|---|---|---|---|
| SDK 原生（samples/ctest） | ✅ 主力 | ✅ MediaCodec | ⚠️ 待救活 | ✅ VideoToolbox+Metal |
| Godot（avox_godot） | ✅ 现役：DX11 硬解 + VK 直通 | ✅ 构建链完备，渲染 CPU 回退（Godot 未开 AHB 导入扩展） | ❌ | ❌ |
| Unity（com.avox.player） | ✅ VK 零拷贝 / D3D11 拷贝 | ✅ AHB 零拷贝（可交付态，未进商店 SKU） | ❌ 未做 | ❌ 未做 |
| UE（AvoxPlayer） | ✅ VK 零拷贝 / D3D11 / D3D12 拷贝 | ❌ 计划中 | ❌ 计划中 | ❌ |

GPU 直通方式对照（排查画面问题时用）：

| 引擎 | Windows 直通 | 失败降级 |
|------|--------------|----------|
| Godot | copy-based：avox VkImage 外部内存(NT 句柄) → 导入 → 每帧 `RD::texture_copy` → `Texture2DRD` | 非 Vulkan 后端自动 CPU 回退（NV12 回读→shader 转 RGB） |
| Unity | Vulkan=零拷贝 NT 句柄导入；D3D11=共享纹理+fence 安全拷贝（`GpuFlavor` 1/2 可查） | D3D12/OpenGL 走 CPU 回退；Android AHB 失败自动回退 |
| UE | Vulkan RHI=零拷贝；D3D11/D3D12 RHI=avox D3D11 出生共享纹理拷贝 | 自动降级 CPU 回读（BGRA8），`bAllowSoftFallback` 4s 无帧回退软解 |

**跨引擎硬约束**：avox Vulkan 导出的 `OPAQUE_WIN32` 句柄**不能**跨 API 给 D3D 导入（E_INVALIDARG / AMD 驱动崩），
D3D 系一律走 avox D3D11 出生共享纹理；Unity 侧曾因在 D3D11 设备上导入 VK 内存导致系统重启 ×2，该分支已删除。
另外 **glsl `.spv` 缺失 = 各引擎硬解静默无帧**（部署脚本都会拷，自搬产物时最容易漏）。

## 4. FFmpeg 代际耦合（当前最大坑）

三套 deploy 清单要求不同 FFmpeg 代际，**直接拿当前构建树喂任何插件都可能不匹配**：

| 消费方 | 要求 | 状态（2026-09-10） |
|--------|------|--------------------|
| avox-ue `deploy_plugin.ps1` | 63 代（avcodec-63…swresample-7，自编 9.0.1 LGPL 白名单）+ zlib1/libwinpthread | ✅ 匹配当前构建树 |
| avox-unity `tools/deploy_unity.ps1`（商店合规流） | 清单已升 **63 代**（2026-09-10，与 UE 同口径自编 9.0.1 LGPL 白名单） | ✅ store 树已验证：11 dll 部署零警告 + strict 许可自检通过 |
| avox 主仓 `platform/unity/deploy_unity.ps1`（开发流） | 63 代 + fdk-aac + WebRTC 可选 | ✅ 匹配，但这是**开发/实测 SKU**，别当商店口径 |

当前构建树实际内容（已核实）：63 代 + `fdk-aac.dll` + `avox_godot.dll` + `plugins/avox_webrtc.dll`/`avox_torrent.dll`，
**无 `avox_unity.dll`**（最近一次构建未开 unity 目标）。

结论——三个引擎要能测，前置各是：
- Godot：现成，`deploy_godot.ps1` junction 指向当前树即可。
- Unity：store 树已就绪（`avox_unity.dll` 已产出且无 fdk-aac，2026-09-10 验证）；换到编辑器机后解包 SDK zip → `deploy_unity.ps1` → `test_unity.ps1` 即可。
- UE：现成，直接 `deploy_plugin.ps1`。

FFmpeg 大版本升级时要同步改三处清单：avox-ue `deploy_plugin.ps1` + `Build.cs` + `sdk_common.py`；Unity 同理在 `sdk_common.py`。

## 6. 版本耦合规则

- **无版本钉死**：三个插件仓对主仓零源码依赖（UE 除外，编进插件），全靠「同级 clone + 构建树」路径耦合，`AVOX_RELEASE_DIR`/`AVOX_BUILD_DIR` 只改路径不校验版本。
- 运行时可查版本：`GetAvoxVersion()` → `AVOX_COMMIT_VERSION (AVOX_COMMIT_HASH)`，来自构建生成的 `AvoxVersion.h`（`cmake/AVOXGit.cmake` 从 git 推导）。
- 主仓 API 换签名（如 `onFrame(IImageBuffer*, YuvType)`）→ 桥接层要跟着改，**主仓与插件仓成对提交**；测试前先确认构建树与各私仓 HEAD 同步。
- 历史教训：主仓 `avplay→avox` 更名一次破坏全部三个插件的路径脚本（avox-ue `8de881b` / avox-unity `6e7a43b` / avox-godot `956e362` 才对齐）——**别再改构建树目录名**。
- 发布包目前**不记录**对应的 avox commit hash（三仓皆缺），上架前必须补（见发布检查清单）。

### 双环境分工（上架执行口径）

本机不是唯一环境：**另一台机器有 Unity/UE 编辑器但无 mac**；mac 只能 ssh（有 iOS 能力）。按「构建自动化 vs 编辑器验证」切分，而不是按平台切：

| 环境 | 承担 | 依赖 |
|------|------|------|
| 本机（Godot+工具链+ZLM+真机） | 全部编码/构建/打包/合规自检；Godot 全链；出「store 口径 SDK 树」zip | — |
| 编辑器机（Unity/UE） | Unity/UE deploy → batchmode 测试 → 交互式 GPU 验证 → 编辑器导出商店包 → 商店提交 | 只需 SDK zip + 插件仓 git，**无需 avox 源码工具链** |
| mac（ssh） | 样例级验证（W5 已通）；**不在上架关键路径**——三个商店 SKU 均为 Windows 优先，无一宣称 mac/iOS | iOS 救活单独排期（avc_library ios 同步 + 链接失败定位） |

仓同步：插件仓走 git push（注意 avox-unity 本地领先 origin 1 提交、avox-ue 领先 2，先推再换机）；SDK 构建树不进 git，用 `script/package/pack_sdk_windows.py --zip --headers` 打包传过去。
