# 播放器重构

## 已完成的重构

### 窗口与渲染分离

原 VideoRender 直接绑定窗口，但是窗口是由用户控制，开关时机并不在播放器控制内，故窗口只在渲染时调用 VideoRender。

VideoRender 原来负责开启线程，并同步音频中的视频及调用 PipeGraph 渲染，但是现在 Tick 改由窗口控制，VideoRender 就不需要管理线程了，故整合 PipeGraph，各个平台的 PipeGraph 都由 VideoRender 实现，相应的原始硬解出来的数据由 VideoRender 对应平台调用底层的 Dx11/OpenGL/Metal 实现 YUV 转 RGBA 并渲染到窗口，如果是 Vk 窗口，则渲染到纹理并由各平台进程间图像共享机制如 DX11 共享句柄/AHardwareBuffer/IOSurface 机制直接给到 Vk 计算管线然后给 Vk 渲染。

经这次调整，VideoRender 实现更有意义，也有必要脱离 VideoTrack，给别的功能实现，如 android/ios 原生相机的渲染，WebRTC 的渲染等。

### 解码器独立化

VideoDecoder 同理，现在也绑定在 VideoTrack，但是实际解码只需要三步，一拿到配置信息初始化解码器，二拿到数据帧解码，三转发解码帧。需要抽离更原始的这三步，可以看到 WebRTC 的解码接口也是这三步，WebRTC 新版本也是提供解码工厂这些，明显是想让你自己实现，只要做到脱离 VideoTrack，VideoDecoder 和 VideoRender 一样，在整合 WebRTC 时就能方便利用已有的解码与渲染能力。

### SourcePlayer 播放器扩展

如果直接取显示解码后数据到窗口，如查看本地摄像头，本来得到就是原始数据，或是拿到 WebRTC 数据，直接显示即可。比传统播放器只是少了解码的过程，但是余下的流程差不多。

现在已实现 `SourcePlayer` 类，专门用于处理原始数据源（设备源、WebRTC）：

```cpp
class SourcePlayer : public ISourcePlayer,
                     public IRawSourceOb,
                     public BasePlayer,
                     public RunTask {
protected:
  std::unique_ptr<RawSource> rawSource;
};
```
