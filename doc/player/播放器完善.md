播放器架构现代化改造规划

## 现状分析与核心问题

当前播放器系统经过长期迭代和人员迭代，主要问题及改进点：

* 当前各个平台的渲染技术，Windows 使用 dx9，android/ios 使用 opengles2.0，现在 Windows 主流使用 dx11/dx12，而 Google 已经要求最新 android 画面渲染统一为 Vulkan，其最新 API 框架里的底层渲染都要基于 Vulkan。而 iOS 目前使用 Metal，相关 OpenGL ES 在 Xcode 已经是废弃状态不维护了。
* 原来PC，android，ios 分别由不同人员开发，其各自平台相应的 IO 线程，解码线程，渲染线程状态管理都是各自的，这导致了各个平台线程状态都维护了一套。新平台统一维护。
* 原平台 Windows 由 VS 管理，android 使用 CMake 管理，ios 使用 Xcode 管理项目，这样不同平台引入库使用不同的方式，易混乱及难维护，新平台统一使用 CMake 管理项目，统一多平台库管理。
* 原 WebRTC 播放器项目单独分开，与老播放器使用了同样的原生窗口渲染以及都接入不同平台的 H265 硬解码，这二个部分功能差不多，并且是播放器主要功能，导致需要维护多份。新平台通用协议与 WebRTC 使用统一的解码与对应平台渲染。
* 原平台封装语言不同平台提供给上层的封装接口不同，由人手动针对接口封装，这样当 C++ 接口及结构改动后，可能有些平台重新改了，有些没改，慢慢不同平台，不同版本与分支差异越大，新平台使用 SWIG 自动把 C++ 封装成 C#/Java/JavaScript 等上层语言，统一接口。
* 原平台里的音频与视频各自的解码，渲染，呈现对象，分散实现，并且不同平台接口不同，很多相同功能各自重复实现，新平台统一相应对象接口，统一注册管理，功能唯一实现并由不同平台共享。
* 原平台图像处理由各自平台开发各自处理，接口不统一，代码维护多份，并且只能选择其中一种处理。新平台在硬解过后，其 GPU 资源直接映射到 Vulkan 图像，由 Vulkan 统一进行图像处理。
* IO 包队列以及解码后的帧队列，其压入与弹出状态管理混乱，其队列里同步锁在各个位置分散，新平台统一与简化进出状态与对象同步。
* 原平台很早前不得已而为之的手段，如不同命令列表使用相同结构，导致结构非常大，在不同命令下有不同含义，难维护并且混合，新平台使用泛型，不同命令匹配不同结构，强类型及字段名有意义。
* 原平台的配置设置功能混乱，播放器下发配置到解码器，渲染对象上功能实现别扭且乱，新平台统一配置设置，播放器下发配置到内部对象统一。

## 现代化改造目标

构建技术统一、架构清晰、维护高效的跨平台播放器体系。

### 技术栈升级

| 平台 | 旧技术栈 | 新技术栈 | 状态 |
|------|----------|----------|------|
| Windows | DirectX 9 | DirectX 11/12/Vulkan | ✅ 已完成 |
| Android | OpenGL ES 2.0 | Vulkan | ✅ 已完成 |
| iOS | OpenGL ES | Metal/Vulkan | ✅ 已完成 |
| Linux | - | Vulkan | ✅ 已完成 |
| WebAssembly | - | WebGL | 🔄 进行中 |

### 架构体系重构

#### 统一线程交互

* 多平台统一线程对象封装，其 IO/解码/渲染由此统一管理
* 标准化 IO/解码/渲染线程状态管理
* 多平台播放器统一线程命令队列

**状态：✅ 已完成**

#### 构建系统整合

* 采用 CMake 作为全平台统一构建工具
* 建立模块化依赖管理机制
* CMake 统一管理多平台资源

**状态：✅ 已完成**

#### 合并 WebRTC 与主播放器核心功能

* 统一硬解码接口适配层
* WebRTC 与主项目同用 AAC 解码器
* 统一多平台原生窗口渲染

**状态：✅ 已完成**

#### 自动化接口封装

* 引入 SWIG 工具链实现多语言自动绑定
* 建立 C++ 接口变更自动同步各语言 API 机制
* 支持 C#/Java/JavaScript 等上层语言

**状态：✅ 已完成**

#### 对象模型标准化

* 设计统一的音视频对象接口，包含解码，渲染，呈现对象
* 实现组件注册与生命周期管理
* 功能复用，多平台统一实现

**状态：✅ 已完成**

#### 图像处理架构

* 多平台硬解可直接快速渲染到原生窗口 dx11/opengles/metal 呈现
* 多平台硬解码后 GPU 资源高效映射至 Vulkan GPU 图像处理管线，统一处理后由 Vulkan 窗口呈现
* 构建 Vulkan 统一图像处理管线，支持多效果链式处理的灵活配置

**状态：✅ 已完成**

#### 队列管理优化

* 重构 IO 包/帧队列数据结构
* 统一同步锁机制与状态管理，锁粒度细化并控制在一个类中
* IO 包/帧队出入状态简化与自动处理

**状态：✅ 已完成**

#### 多流播放支持

* 设计多路视频流单播放器内统一渲染
* 实现多流同步控制机制

**状态：⏳ 计划中**

#### 命令系统重构

* 采用泛型设计实现命令-结构强绑定
* 建立语义化字段命名规范
* 实现命令解析的类型安全校验

**状态：✅ 已完成**

#### 配置体系升级

* 构建统一配置下发通道
* 配置选项类型安全校验

**状态：✅ 已完成**
