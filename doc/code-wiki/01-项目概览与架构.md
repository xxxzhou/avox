# 01 项目概览与架构

## 1. 项目定位

avox（CMake 工程名 `avplay`）是一个**跨平台音视频播放器 SDK**，提供：

- 本地文件 / 直播流（RTSP/RTMP/WebRTC）播放
- 软解 + 各平台硬解（Windows DX11、Android MediaCodec、iOS VideoToolbox）
- Vulkan GPU 图像处理管线（100+ 滤镜/效果：Anime4K 超分、水印去除、LUT、去隔行、FSR 等）
- 设备采集（摄像头/麦克风/屏幕捕获）
- 录制/转码/推流（FFmpeg / ZLMediaKit / ONVIF / WebRTC）
- AI 能力：语音识别（ASR）、语音合成（TTS）、离线翻译、图像修复（inpaint）、YOLO 检测、OCR、虚拟人（avatar blendshape/身体姿态）
- **Agent 客户端**：对接 OpenAI 兼容 VLM，通过原生工具 + skill 做多媒体诊断与自动化
- **CLI 工具**：`avox_cli`（ffmpeg 风格的多功能命令行）

**支持平台**：Windows、Android、iOS、Linux、WebAssembly。
**语言绑定**：C/C++ 原生，SWIG 生成 C# / Java / Node.js / Python 封装。

### 2.2 设计原则

- **接口/实现分离**：根目录 `.h` 定义抽象接口（C 友好、SWIG 可用），子目录 `.hpp/.cpp` 提供实现。
- **观察者模式**：主要接口均配 Observer（`IMediaPlayerOb`、`IAVSourceOb`、`IRecorderOb` 等），用 `addXxxOb/removeXxxOb` 注册。
- **模块/插件化**：核心内部用 `AvoxManager` 工厂表 + `ModuleMgr` 插件管理；可选能力编译为独立 dll，运行期探测加载（懒加载）。
- **配置传播**：`IOption` 基于 JSON 的键值配置在管线中传递（`optionCopy` 初始 / `optionUpdate` 同步变更）。
- **跨 DLL 安全**：全链路 `/MT` 静态 CRT，插件接口只传 `const char*` 与原生类型，STL 容器不跨 DLL 传递。
- **资源生命周期约定**：`create*()` 返回需释放（调用者 delete）；`get*()` 返回托管对象（不释放）。

### 2.3 平台支持矩阵

| 平台 | 架构 | 硬解 | 渲染后端 | 音频 |

## 3. 核心数据流

### 3.1 URL 播放（IMediaPlayer / MediaPlayer）

```
IAVSource (FFmpegSource/ZlmSource …)      ← IO 层：解封装，输出 AvoxPacket(编码帧)
    │  onPacket 回调
    ▼
MediaPlayer ── 命令队列(MPCommand) ── 按轨道分发
    ├── AudioTrack ── ADecoderTask(解码线程) ── AvoxAFrame ── AudioRender/IAudioRender
    └── VideoTrack ── VDecoderTask(解码线程) ── YUVFrame/GpuFrame ── ISurfaceRender
                                                              │
                                                              ▼
                                                   IPipeGraph (Vulkan GPU 效果链)
                                                    IVInputLayer → VLayer[] → IVOutputLayer
```

- 数据包（`AvoxPacket`）由 `AVSource` 产出并做 PTS 对齐、Annexb/AVCC 格式处理、SPS/PPS/VPS 配置帧管理。
- 音视频同步：`Clock` 维护播放时钟，解码/渲染任务按 PTS 驱动，支持倍速。
- 状态机：`none → opening → ready → playing → pause → seek → buffering → stopped → completed`。

### 3.2 设备采集（ISourcePlayer / SourcePlayer）

```
IVideoSource / IAudioSource (设备原始帧 YUV/PCM)
    ▼
SourcePlayer
    ├──→ ISurfaceRender (直接渲染)
    ├──→ IAudioRender
    └──→ IMediaMuxer (可选编码/录制/推流)
```

### 3.3 封装录制（Muxer / Recorder）

```
原始帧 / AvoxPacket
    ▼
IMediaMuxer(编码+封装) / IRecorder(流录制) / StreamRecorder / TranscodeRecorder
    ▼
输出：文件(mp4…) / ZLMediaKit(rtsp/rtmp) / WebRTC / ONVIF
```

### 3.4 WebRTC 推拉流（IRtcPlayer，plugins/avox_webrtc）

- 支持 offer/answer 两种角色，SDP 信令协商（`ISdpAgentOb` 回调，`createZlTestSdpAgent` 提供测试信令通道）。
- 拉流：远端 H264/H265 经 Rtc 解码器解出 → 远端渲染器；推流：本地设备源 → Rtc 编码器 → 网络。
- 核心接口 `IRtcPlayer` 位于 `src/avox/AvoxPlayer.h`，实现位于插件 `plugins/avox_webrtc`（工厂 `rtcPlayerHub` 注册）。

### 3.5 AI / Agent 数据流

```
ASR: 音频流 → AudioStt(工厂 avox_sherpa) → 字幕/文本
TTS: 文本 → AudioTts(工厂 avox_sherpa) → PCM → 播放/落盘
翻译: 文本 → ITranslator(工厂 avox_translation) → 目标语言
去水印: 图像 → IWatermarkRemoval(工厂 avox_cv) → 修复图像
YOLO: 图像 → IYoloDetector(工厂 avox_cv) → 检测框/分类
OCR: 图像 → ITextRecognizer(工厂 avox_ocr) → 文本
Avatar: PCM→ARKit52 blendshape / 视频→人脸478点 / 身体33点
Agent: followup(text) → Session/ReactLoopAgent → LLM tool_calls → 工具执行(skill) → 回灌 → 收敛
```

## 4. 模块注册与插件机制（架构关键点）

### 4.1 AvoxManager（核心工厂中心）

`src/avox/module/AvoxManager.hpp`，全局单例。持有全部解码器/渲染器/IO/源/复用器注册表与插件工厂表：

| 成员 | 类型 | 作用 |
|------|------|------|
| `ioSources` | `RegeditObj<IoPlan, AVSource, IoPlanDesc>` | IO 方案（ffmpeg/zlmediakit/webrtc…）→ AVSource |
| `rawSources` | `RegeditObj<RawSourceType, RawSource, RawSourceDesc>` | 原始源（device/media/WebRTC） |
| `muxers` | `RegeditObj<MuxerType, IOMuxer, MuxerDesc>` | 封装器 |
| `vRender` / `aRender` | `RegeditObj<RenderType,…>` / `RegeditObj<ARenderType,…>` | 视频/音频渲染器 |
| `vDecoders` / `aDecoders` | `RegeditObjList<VCodecId, VideoDecoder,…>` | 视频/音频解码器（多实现） |
| `vEncoders` / `aEncoders` | `RegeditObjList<…>` | 视频/音频编码器 |
| `aDeviceMgr` / `vDeviceMgr` | `RegeditMgr<…>` | 音频/视频设备管理器（懒加载单例） |
| `audioSttHub` `audioTtsHub` `onnxSessionHub` `translatorHub` `watermarkRemovalHub` `yoloDetectorHub` `rtcPlayerHub` `audioFaceHub` `videoFaceHub` `bodyFaceHub` 等 | `RegeditFactory<T>` | **插件工厂表**：插件 `loadModule` 时 `reg("name", factory)`，业务 `create("name")` 查表（查不到返回 nullptr 降级） |

> 注意：插件工厂表使用 **C 函数指针**（非 `std::function`），避免跨 DLL 析构已卸载 manager 崩溃；`RegeditFactory` 的 `create` 会先触发 `ModuleMgr::ensureStarted()`（懒加载扫描 plugins/）。

### 4.2 ModuleMgr（插件加载）

`src/avox/module/ModuleMgr.hpp`：
- 扫描 `avox.dll` 同级的 `plugins/` 目录，发现 `avox_*` 动态插件。
- `loadModule(name)` 支持递归加载依赖（`IModule::addDep`），失败传播。
- `startup()` / `ensureStarted()`（幂等懒触发）。
- `StaticLinkModule<T>` 用于静态链接（iOS/WASM）时的构造期注册。

### 4.3 IModule 与插件 ABI

`src/avox/module/IModule.hpp`：
- `IModule` 基类：`loadModule(IOption*)`（运行期能力探测，false=不可用≠崩溃）、`unloadModule()`、`addDep/depCount/getDep`。
- `AVOX_PLUGIN_ABI_VERSION 1`、`AVOX_PLUGIN_API`（dllexport/dllimport）。
- `AVOX_REGISTER_MODULE(ModuleClass, name)`：动态模式导出 `NewModule()` + `GetModuleABI()`；静态模式实例化 `StaticLinkModule`。
- 注册表基元（`src/avox/module/RegeditObj.hpp`）：`RegeditObj`（一类型一实现）、`RegeditObjList`（一类型多实现）、`RegeditFactory`（字符串键 + C 函数指针）、`RegeditMgr`（懒加载单例）、`RegeditSingleton`。

### 4.4 插件编译（plugins/）

- 总开关 `AVOX_ENABLE_PLUGINS`；各组件 option 定义于 `plugins/options.cmake`。
- `plugins/CMakeLists.txt` 的 `PLUGINS_DYNAMIC` 列表（当前：avox_opencv, avox_sherpa, avox_onnx, avox_translation, avox_cv, avox_ocr, avox_webrtc, avox_openvino, avox_avatar）。
- `cmake/avox_module.cmake` 的 `register_plugin(<name> DYNAMIC DEPS … LIBS … DEP_DLLS …)`：建独立 SHARED target，输出到 `${CMAKE_INSTALL_PREFIX}/plugins/`。
- 铁律：插件编译只定义 `AVOX_PLUGIN_BUILDING`，**绝不定义 `AVOX_EXPORT_DEFINE`**（防止 `IModule` 被 dllexport 导致跨 DLL 虚表错乱）。

## 5. 线程模型

| 线程 | 承担者 | 说明 |
|------|--------|------|
| 主线程 | 调用者 | 创建对象、配置、`open/close/seek` 走命令队列 |
| IO/解封装线程 | `AVSource` 子类内部线程 | 产包（`onPacket` 回调），流初始化在数据流线程内完成 |
| 音频解码线程 | `ADecoderTask` | 消费音频包 → `AvoxAFrame` |
| 视频解码线程 | `VDecoderTask` | 消费视频包 → `YUVFrame/GpuFrame` |
| 音频渲染线程 | `ARenderTask` / `AudioRender` | 按时钟播放 PCM |
| 渲染线程 | `VideoRender` / Vulkan 命令提交 | GPU 提交与呈现 |
| 命令线程 | `MPCommand` | 跨线程命令的排队与状态切换 |

线程安全约定：`open/close/seek` 可跨线程（命令队列）；`getState/getPosition` 可跨线程（原子/锁）；回调在调用者线程、不得阻塞；回调内不调用同步方法。
