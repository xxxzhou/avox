# 渲染车道演进：纹理直通 → 原生窗口（各平台直渲）

> 状态: 有效 · 上次核对: 2026-10-01 · 权威源: panvox 仓 `docs/design/native-video-view.md` ·
> `docs/design/ui-modes-redesign.md` §六130 · `docs/reports/2026-09-12-gpu-passthrough-spike.md` ·
> `docs/reports/2026-09-22-startup-1s-block-corruption-forensics.md`

一句话背景: 视频上屏最初走**纹理直通** —— avox Vulkan 合成 → NT 共享 D3D11 纹理 → shim 镜像 blit
→ Flutter/ANGLE 外部纹理。该链路**本身反复出「乱块/花屏 + 卡顿」**，2026-09-24 全平台改为
**原生窗口直渲**（视频 = 原生窗口节点，播放控件 = 普通 Flutter widget），纹理直通整条退役。

## 1. 原方案：纹理对接（2026-09-12 spike 落地）

- 接口: Flutter `kFlutterDesktopGpuSurfaceTypeDxgiSharedHandle` → ANGLE
  `eglCreatePbufferFromClientBuffer(EGL_D3D_TEXTURE_2D_SHARE_HANDLE_ANGLE)`。
- 可用配方五条（AMD RX 9070 XT / Win11 / Flutter 3.47.3 实测）:
  句柄 = legacy `D3D11_RESOURCE_MISC_SHARED` + `GetSharedHandle()`（**非** NT 句柄，两者互斥）·
  格式 = `DXGI_FORMAT_B8G8R8A8_UNORM`（ANGLE 的通道约定也是 BGRA，不只是格式要求）·
  绑定 = `RENDER_TARGET|SHADER_RESOURCE`、`MipLevels=1`、`ArraySize=1`、`SampleDesc.Count=1` ·
  适配器 = 必须与引擎**同 LUID** · 同步 = 每帧写入后 `Flush()` 再 `MarkExternalTextureFrameAvailable`。
- 同日接入真实播放链路成默认（`PANVOX_GPU_SHARED=0` 可回退）；640x360 下 CPU 开销 −17%。
- **当时就挂着的疑点**: 单缓冲 + `Flush`，`release_callback` 语义只是「句柄已被打开时回调一次」、
  不是逐帧回执 ⇒ **理论上存在撕裂可能**（后来果然成真）。

## 2. 为什么放弃：链路自身的病灶

### 2.1 慢性碎块/乱块（主因，定谳）

- **碎块 = 同进程跨设备共享纹理并发**；对照实验: 跨进程导入干净，**七种消费端同步方案全部证伪**。
- 消费侧两级无同步: **级 C**（ANGLE 合成）与 **级 B**（shim blit vs avox 下帧写，负载型）。
- 受控复现: 8 线程 spin 负载 40s → 同位同形散块破损；无负载 60 帧全净。
- ⇒ **「纹理链本身就是病灶，修不如绕」** —— 这是换车道的直接理由。

### 2.2 起播/seek 后 ~1s 块状花屏（2026-09-22 取证）

- 现场: WebDAV h264 `1072x1920@29.97`，起播 ~1s 后画面**按行/按块错位**花屏并持续；seek 只是
  让管线重启，同一现象再演一遍（不 seek 也花）。
- 排除: 片源/网络/解码（纯 ffmpeg 逐帧干净）· shim/Flutter（avox_cli 不经过它们也花）· 硬解（软硬都花）。
- 形态: **只有视频平面被错误寻址**，OSD/字幕叠加层始终清晰 ⇒ 像 stride/pitch 或输入层格式不符，
  不是「解码出垃圾宏块」。
- 根因指向: **D3D11 共享纹理 fence 竞态 → GPU 读写同步失效 → 帧撕裂/错位**
  （同批修 `Dx11SharedTex` 的 fence 取号单调递增，`bb87c22`）。

### 2.3 跨 API 排序从未建立（机制层，最要命）

- 写给消费者的 fence 是 **D3D11 侧**打的（`Dx11SharedTex::signalInteropFence()`），
  而**写这张共享纹理的是 Vulkan**。
- `VkWinImage::bindD3D` 里把 D3D 共享 fence 导入 Vulkan 的 `initExternalFence(interopFenceHandle)`
  **被注释掉了**（`VkWinImage.cpp:70-73`）。
- ⇒ 消费者等到的 fence **不证明「Vulkan 已写完导出纹理」**，跨 API 排序根本没建立；导出的其实是
  一张「部分写完的图」的快照 ⇒ 表现为**稳定、块状、块内容来自相邻帧**（不是随机噪声）。
- **变量隔离**（三套宿主、同文件同 seek）: 路A 交换链恒干净，**唯一变量 = 是否开启路B 导出纹理**。
- **发生率**（`--shot=1` 同刻背靠背取路A/路B）: 顺序播放 MAE>2 占 **21%**、肉眼可见 **8%**；
  `seek 20000` 后 **32% / 14%** ⇒ 与「seek 后很大概率整屏色块」「大部分 rmvb 正常」吻合。

### 2.4 性能与目标不可持续

- 8K RGBA8 = **132.7 MB/帧**，直通链每帧 **3 跳**（avox 图内 1:1 拷贝 + shim mirror blit + …），
  层层拷贝/镜像不可持续；窗口 swapchain 直渲才是最短路径。
- 卡顿: 直通链有 blit 线程与 fence 等待。

## 3. 新方案：原生窗口直渲

| 平台 | 视频承载 | avox 对接 | 控件叠加 |
|---|---|---|---|
| Windows | **自研**: 顶层视频窗垫底 + `SetWindowCompositionAttribute`(accent=6) 整窗透明合成 | `setSurface(hwnd)` + `setVulkan(true)`（Vulkan 合成 present 进宿主窗内自建 `CustomVkWindowClass` 子窗） | 真 alpha 逐像素 |
| macOS | `AppKitView`（官方 PlatformView） | `setSurface(CAMetalLayer*)` | 官方合成 |
| iOS | `UiKitView` | `setSurface(CAMetalLayer*)` | 官方合成 |
| Android | `AndroidView` / SurfaceView PlatformView | `setSurface(ANativeWindow*)` | 官方合成 |

- avox 侧接口**现成**: `AvoxLayer.h` 的 `ISurfaceRender::setVulkan/setSurface`；Windows 直渲窗口路径
  早有 `dx11windowtest` 验证（无碎块）。
- Windows 自研要点: 视频窗 `SetWindowPos` 插到 Flutter 主窗**正后方**（z 序贴合）· 主窗 accent=6 整窗透明 ·
  `NativeVideoView` 上报自身 rect（视频窗跟随）并在视频区画**透明洞** · 视频窗完全不吃输入（hit-test 免处理）·
  最小化/最大化走 flutter_native_view 三步绕法（关透明→藏窗→延迟 `SW_SHOWNOACTIVATE` 恢复）。
- 关键序: **视频 rect 的 `SetWindowPos` 必须在 player create 之前** —— 子窗/交换链尺寸钉在挂窗瞬间，
  晚了画面只剩一角。

## 5. 验收与实测

- P0 五项全过: 启动段截图无碎块 · 半透明遮罩/控件叠加正确 · 拖动跟随无错位 · 最小化恢复无残影 ·
  8K `7680x4320` HEVC 可播。
- A/B（尖刀环境同机同片）: 纹理对照组碎块复现，直渲组全净；用户实播判读**「不卡、没乱块」**。
- 真机: RV40（乱块惯犯）本地长片满幅无碎块 · resize 重建贴合 · `HUD tex=-1` 确认无纹理参与 ·
  `open→首帧 246ms`。
- 帧率/卡顿: 本链**无 blit 线程、无 fence 等待** ⇒ 卡顿消失。
- 已知非缺陷: RV40(RMVB) 起播头几秒大块糊斑 = `fromStart` 起点撞非关键帧（日志
  `first frame is no keyframe`），下一关键帧自愈（8s 糊 / 15s 净实测），与老纹理车道的持久乱块无关。

## 6. 与 2026-10-01 卡帧修复的关系（同族缺陷）

- 今天修的 `00ce5dd`（**input 方向**: DX11 解码纹理 → Vulkan 直读，写方不 signal / 读方不等待）
  与 §2.3 的 **output 方向**（Vulkan 导出纹理 → D3D11/ANGLE 读）是**同一类缺陷**：
  **跨 API 队列排序没建立**。
- 区别在于可控性: input 那条是**引擎内单点**（`Dx11CSVideoRender` + `VkWinImage` + `Dx11SharedTex`），
  加一对 fence signal/wait 即闭环；output 那条还叠着 **ANGLE 消费侧（级 C）** 与 **shim 镜像环**，
  多主体无法收敛 —— 所以选择**绕开（换车道）**而非修复。

## 7. 可复用判据

1. **跨 API 共享纹理，写方 fence 必须由「真正写纹理的那个 API」打点**；「消费者等到了 fence」≠
   「纹理已写完」。
2. 变量隔离到**「唯一变量 = 某开关」**时，别继续在消费侧堆同步方案，先怀疑**链路本身**。
3. **同进程并发 vs 跨进程导入**是分离「设备/资源并发」与「进程边界」的第一刀。
4. 判画面/观感必须用**上屏仪器或原生分辨率取证**，别靠窗口截图（`PrintWindow` 抓不到透出的视频）。
5. 换车道这类架构决策，**验收要 A/B 同机同片**，且用户实播判读是最终口径。
