# 播放引擎排查案例集 ①：解码映射与像素呈现

> 状态: 有效 · 上次核对: 2026-10-04 · 权威源: 记忆库(memory/)+各仓 git 提交号
> 本文为 2026-09-19~09-30 排查战役的蒸馏汇编, 案例细节以对应提交号与记忆文件为准

一句话背景: 汇总「解码器选轨/映射 → 解码执行 → 像素呈现」链路上的已定谳案例,
每条含根因、修复提交与可复用的判据。供同类症状快速对号入座。

## 1. 编解码映射与老片源

- **DIV3 播不了** (09-21, avox `b8ea53d`): DivX 3.11 Alpha 的 fourcc `DIV3` 实为
  FFmpeg `AV_CODEC_ID_MSMPEG4V3`, `ffVCodec()` 映射表漏 MSMPEG4V1/V2/V3 三族 →
  IO 层 `VCodecId::none` → 不建解码任务 → 10s buffering 超时关停。
  修法: `AVOX_MAP_VCODEC` 尾部「只增不改」追加三族; IO 选轨与解码器注册同表过滤,
  **一处补表全链路通**。教训: 「播放不了+音频正常」先查映射表, 别直奔解码器。
- **MPEG-1 .mpg 全片宏块垃圾** (09-24): 根因在 FFmpeg 侧 mpegvideo 解析
  白名单, 已修 `build_ffmpeg.py` 四平台重编部署; 沉淀三步交叉验证法
  (参考解码器对质 → 抽原始码流独立解码 → 比对 avox 解码输出)。
- **WMV3 开头花 3 秒** (09-23, `48bc3bd`): `copyBuf` 复用槽残留 PacketBuf 踩掉
  flattener 扣住的首簇, 坏包 pts=1000槽×帧长成周期图案。附带两坑: ASF 手撕端序、
  mpegvideo `no-keyframe` 报错= dummy 参考判据(非真丢参考)。

## 2. 崩溃与内存越界

- **h264 PPS scaling matrix 连环两刀**: ① `loopTime` 缺基数 6 的 resize 传负值
  (`937617b`); ② 修后暴露 `UseDefaultScalingMatrix8x8Flag[i]` 越界写——`041ebea`
  埋雷 19 天被①掩护, 显式 8x8 表才踩, 即 **panvox 启动堆损坏根因**(`155d817` 修)。
  沉淀: 无 PDB 的 Release 定位= 修饰名+VEH+dbghelp 手解 minidump;
  遗留: default-flag 未回填默认表(Vulkan 量化矩阵错, 画质类)。
- **AudioFrame::writeBytes 上界校验仅存 assert** (mpv/vlc 千提交审计发现,
  AudioFrame.hpp:41): Release 下 assert 失效即 memcpy 无界; 现调用方均先钳位
  无可达越界, 待一行显式钳位收口。
- **mac 切流闪退 = Metal 纹理缓存先于纹理释放** (10-03 定谳, `a5af7c7`): 一日内两份
  `.ips` 同栈——`EXC_BAD_ACCESS at 0x0`、线程 `com.Metal.CompletionQueueDispatch`,
  栈顶 `avox::MetalRender::renderCVPixelBuffer` 完成 block → `_CFRelease(CVMetalTexture)`
  → `CVMetalTextureCache::bufferBackingNotInUse` → `CFArrayAppendValue(NULL)`。
  根因: `closeTextureCache()` 随 `releaseGraph()`(每次 `hdr pipeline flip`/关流都走)
  直接 `CFRelease(cacheTexture)`, 而帧的 `CVMetalTexture` 要到命令缓冲完成回调才释放
  ⇒ 缓存先死、回调再回写它即空指针。**判据**: `.ips` 见上述栈即定案(别往解码/宿主查);
  修后日志出现 `texture cache retire deferred, inflight:N` = 命中过原崩溃窗口并安全兑现。
  **修**: 缓存与 device 同生命周期(仅首次创建, 图重建只换 IO 面), 退场改「在飞帧计数归零
  才释放」, 计数状态堆上共享(完成回调不持 `this`, 渲染器析构后仍可兑现)。**验收**: 两轮
  拖动压力中该路径命中 17 次、零崩溃; ctest 2/2 + 离线矩阵 126 PASS/0 FAIL。

## 3. 像素呈现与色彩条

- **packed 420P 奇数色度行绿条** (`24c0292`, 09-22): 三缺陷叠加——打包丢末行 /
  shader V 基址差半行 / split 视图错一条 stride; 偶数 uvH 时字节巧合互相抵消
  所以隐匿。统一线性布局后奇数尺寸用例锁定(avox-test)。
- **绿条/色条家族判别**: 某AVI样本底部绿条(打包) 与 某老片顶部 RGB 条(片源) 不同因;
  **片源损坏判据**: ffmpeg 参考解码多位置扫描同现 + 解码 dump 源 U/V 平面即垃圾
  → 非引擎 bug, 直接归档(顶部色条案例)。
- **RMVB RV40 花屏** (`processVideo` 修): 非 h264/h265 码流的「伪起始码」前字节
  被当长度头吃掉 → 帧截断花屏; 修=非 h26x 整包直发, 不做 NALU 拆包。
- **RM INDX Invalid stream index**: RMVB 源文件脏 INDX, FFmpeg 跳过兜底, 良性
  噪音不修; 唯一隐患是 seek 退化。
- **mac 切流彩色马赛克 = 层格式漂移(16F 管线绘进 8bit 层)** (10-03 定谳, `a5af7c7`):
  症状 = 拖入新视频偶发「橙/红/蓝/绿色带 + 边界噪点」马赛克并冻结(正常应为紫黑)。
  复现配方: 显示 HDR→SDR→切回, 再拖文件(**宿主重挂平台视图**的动作触发)。根因: 重挂会把
  `CAMetalLayer` 重置回 `RGBA8Unorm`(SDR), 而引擎直通态(`bF16Pipeline`/16F 管线)不变、
  标志没变故不触发 `hdr pipeline flip` 重建 ⇒ 16F 管线绘进 8bit 目标 = Metal 未定义行为。
  **判据**(帧级转储, env `AVOX_METAL_DUMP=<dir>` 每流头 12 帧落盘「解码输入平面 + 渲染
  目标纹理」): 坏帧目标纹理 4B/px 而管线 f16=1; 输入 pb 干净、输出几何与输入**完全对齐**、
  仅颜色炸开 ⇒ 纯色彩通路崩(非几何/解码)。修后日志
  `layer format drift: target f16:0 pipeline f16:1 -> re-apply layer config`。
  **修**: `renderCVPixelBuffer` 每帧核实际目标格式 vs `bF16Pipeline`, 不符即
  `applyLayerHdrConfig` 回写层配置并弃本帧(新格式对下一个 drawable 生效, 最坏闪一帧)。
  **验收**: 用户按原配方反复跑, 守卫命中 4 次、717 帧转储零花屏帧、无法再复现;
  panvox 侧配套「表面重挂补发堵漏」在 `c2970e8`(app 半边), 引擎守卫与它互补。

## 4. 硬解车道

- **AV1 双平台落地** (09-25, Apple `7cab9f8` / Win `ffc9b7b`): M5 VT 硬解首帧
  100ms 全绿; Windows D3D11VA `file-av1`/`probe-field-av1*` 三用例 PASS(10bit 不折);
  顺带修 VP9 硬解门闸既有 bug。边界: bundled FFmpeg 无 dav1d → M1/M2 无 AV1 软解;
  Windows AV1 硬解需 RTX30+/RX6000 级。
- **Vulkan 设备丢失恢复** (0920 夜): 判空/过闸落地, 播放管线停摆阈值≈1.1s 发现,
  退避回设 1s; avox-test `vk-lost-recover` 用例+注入钩子口径。
- **VR 鱼眼打开卡死** (09-24): 门闸洗清——mp4 有 stss 时 BACKWARD seek 必落
  sync sample, 首包即 KEY; **97% 样本是 12 字节 x264 skip 帧属合成片正常**,
  别当 corruption; SEI 前置于 IDR 的包会让「只认包首 NAL」的闸误丢首个 GOP。

## 5. 复用与生命周期

- **EOS 重开幽灵时间轴** (09-25, `deaf13f`): 轨对象跨 open 复用(AVOX_MAX_TRACK
  固定数组), `close()` 只清队列不清**呈现游标**——`VideoTrack.lastInPts`/
  `AudioTrack.nextPts`/`PtsFlattener.lastOut` 残留旧停片位, 新一轮开头全被重戳
  成幽灵 pts, 视频钟与音频真钟谁先 sync 谁赢=偶发换片跳位。
  修法= 三处 close() 补齐 flush() 同款复位。教训: **复用型对象的 close 审计要
  对照 flush 的复位清单逐项过**。
- **dx11sharedtest 超时** (09-22): enableVkOutputDx11 timeout 根因=测试文件
  路径不存在 → outputLayer null → sample 轮询不感知 onError 傻等 10s。
  教训: 样例程序要对「文件没打开」有显式失败出口。

## 7. 案例补充细节(修复验证口径)

- **DIV3 离线回归口径**: 修复轮矩阵 48 过/4 失败——4 个全是 dav 远程用例,
  b8ea53d 之前就 FAIL 的存量环境问题(本地 WebDAV fixture), 与引擎无关。
  「新旧失败分账」是矩阵解读第一课。
- **panvox mpeg4 黑屏** (09-20/21): 解码层全排除(mpeg4 恒软解/avox_cli 正常/
  dll 含修复), 嫌疑收敛到软解 yuv420p × panvox 离屏 GPU 直通; 早期「硬解缺口
  无回退」结论已推翻。**跨进程对质(avox_cli 正常 + panvox 异常)是壳层问题
  的第一分水岭。**
- **vk-lost-recovery**: 判据口径=播放管线停摆阈值 ≈1.1s 内发现 + 命中后回放
  恢复; 注入钩子在 avox-test 用例里, 回归时人为制造 device lost。
- **wmv3 附加**: 「dummy 参考」判据——mpegvideo 报 no-keyframe 但画面正常推进
  =老容器丢 key 元数据的正常现象; 真丢参考会持续花屏到 GOP 边界。
- **RV40 vs RV30/RMVB 时间戳**: 源层音频垃圾 pts 统一归一 NOPTS 的改造在
  rmvb-audio-nopts(详见案例集②时钟节), 呈现侧只需保证「无 pts 帧沿用
  nextPts 采样推进」。
- **AV1 素材口径**: avox-test `test_av1_opus_640x360.webm` /
  `test_av1_10bit_opus_640x360.webm`; 探针链路 track valid → `ios av1 decoder`
  (mac) / `ff_av1_dx11 hw=1`(win) → VT session status:0 → 首帧毫秒级。

## 8. 呈现链「三段定位法」(蒸馏)

1. **解码前**(码流/包层): dump 原始 NALU/平面, 参考解码器对质 → 定「进来的就是
   坏的」(片源/容器/拆包)。
2. **解码后**(帧层): 关闭渲染直读 YUV/RGBA 落 PNG → 定「解出来的好坏」。
3. **呈现后**(屏幕/截图): 同刻屏幕抓帧 + 逐位 hash → 定「呈现链消费坏」。
   三段各留证, 二分一轮即锁定区段; 跨进程(panvox vs cli)再分一层。
