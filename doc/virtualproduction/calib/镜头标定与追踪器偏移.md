# 镜头标定与追踪器偏移

## 镜头标定

张正友标定法是一种比较简单通用的镜头标定方法,利用一张棋盘格得到各个参数,其opencv已经直接集成.

其中UE4有二个插件都集成相应实现,其插件CameraCalibrationEditor里的UCameraLensDistortionAlgoCheckerboard实现.插件OpenCVLensCalibration里UOpenCVLensCalibrator类实现.

说下UE4里的实现过程.

1. 根据棋盘的角点信息(格子数,物理尺寸)生成opencv坐标系下的三维点信息,主要注意选择原点与轴,在这建议以棋盘的左上角为原点,棋盘从左到右为X轴,棋盘从上到下为Y轴,左手坐标系对应的Z轴,和opencv默认坐标系重合.

2. 拍摄至少四张不同角度下的图片,根据每张图片,查找其角点二维坐标信息与上面三维点信息(cv::findChessboardCorners/cv::cornerSubPix),收集其计算结果.

3. 利用第二步收集的二维UV坐标与棋盘生成的三维点信息得到镜头内参,畸变系数,对应各图片下的镜头外参(cv::calibrateCamera).

相应实现现经简单封装,源码[CameraCalibration](https://git.woa.com/leoxzhou/aoce/blob/master/code/aoce_opencv/CameraCalibration.cpp)

## 追踪器偏移

在UE4插件CameraCalibrationEditor的UCameraNodalOffsetAlgoPoints类有如何求得追踪器偏移的逻辑.

说下UE4里的实现过程.

1. 实现过程首先在UE4虚拟空间中,完成一个追踪器类似的模拟,假设是VIVE Tracker,其在UE4已经集成.

2. 根据上面求得的镜头参数,然后摄像机固定不动,移动Tracker在至少四个不同位置,每个位置标记Tracker生成二维信息与记录Tracker在UE4里的三维坐标,注意把相应UE4坐标数据转到opencv坐标系用于在opencv里计算.

3. 利用第二步收集的每个Track的二维信息与三维信息,使用cv::solvePnP求得在摄像机坐标系下Tracker三维坐标系所在原点(也就是UE4原点)姿态,这姿态求逆得到UE4原点下摄像机姿态,把这姿态从opencv坐标系转到UE4坐标系,然后计算与挂在摄像机上的追踪器的UE4姿态求得偏移.

在虚拟制片中,追踪系统一般使用Redspy,按照如上方式,一是使用二个追踪器,麻烦并且贵,二是先求得到结果,然后再把Redspy绑定到摄像机上,然后算出偏移,但是算完后固定Redspy到摄像机的过程中,只要稍微移动摄像机,就会造成计算结果错误,所以我们放弃UE4中的这种方式.

有没有绑定追踪器到摄像机,然后拍几张图就可以自动算出与追踪器的偏移了,其实是可以的,这本来就是机器人的手眼标定问题.

根据[传感器外参标定总结](https://zhuanlan.zhihu.com/p/458993915)(眼在手上)逻辑.

1. Redspy追踪器在Redspy空间下的姿态.

2. 相机相对Redspy追踪器的姿态,变换是固定,是我们需要求解的结果.

3. 标定板在相机坐标系下的姿态,如上我们可以cv::solvePnP求得标定板在相机下的姿态.

4. 相机在Redspy空间下的姿态,这个变换我们可以不关心.

![avatar](https://pic3.zhimg.com/80/v2-c5ab29593bfaf8e2ad45d8ffb0b2175a_1440w.jpg)

Redspy固定相机在不同位置拍摄几次标定板,构建空间变换回路.$ D = A{1}*B*C{1}^{-1} = A{2}*B*C{2}^{-1} $ 变换如下 $ (A{2}^{-1}*A{1})*B = B*(C{2}^{-1}*C{1}) $,就是一个AX=XB的问题.

找了下,opencv已经集成这个实现(需要版本在4.1及以上),默认参数对应眼在手上.

```C++
CV_EXPORTS_W void calibrateHandEye( InputArrayOfArrays R_gripper2base, InputArrayOfArrays t_gripper2base,
                                    InputArrayOfArrays R_target2cam, InputArrayOfArrays t_target2cam,
                                    OutputArray R_cam2gripper, OutputArray t_cam2gripper,
                                    HandEyeCalibrationMethod method=CALIB_HAND_EYE_TSAI );
```

简单说下对应各个参数的理解.

1. R_gripper2base/t_gripper2base 追踪器对应追踪空间下的旋转/位移.

2. R_target2cam/t_target2cam 标定板在摄像机空间下的旋转/位移.

3. 输出R_cam2gripper/t_cam2gripper 摄像机相对追踪器下的旋转/位移,也就是我们要求解的姿态.

根据现在流程,调整实现过程如下.

1. 固定棋盘,根据棋盘的角点信息生成opencv坐标系下的三维点信息,其主要是选择原点与轴,在这建议以棋盘的左上角为原点,棋盘从左到右为X轴,棋盘从上到下为Y轴,右手坐标系对应的Z轴,和opencv默认坐标系重合.

2. 移动摄像机,拍摄至少四个角度相应图像,识别棋盘二维UV(cv::findChessboardCorners/cv::cornerSubPix),自动识别,不需要手动标注,根据cv::solvePnP求得标定板在摄像机空间的姿态,收集这个姿态以及追踪器对应追踪空间下的姿态.

3. 利用第二步收集的信息调用cv::calibrateHandEype求解得到偏移.

相应实现现经简单封装,源码[CameraOffset](https://git.woa.com/leoxzhou/aoce/blob/master/code/aoce_opencv/CameraOffset.cpp)

## 手眼标定代码解析

在opencv里的calib3d模块,calibration_handeye.cpp文件里.

``` c++
//Reference:
//R. Y. Tsai and R. K. Lenz, "A new technique for fully autonomous and efficient 3D robotics hand/eye calibration."
//In IEEE Transactions on Robotics and Automation, vol. 5, no. 3, pp. 345-358, June 1989.
//C++ code converted from Zoran Lazarevic's Matlab code:
//http://lazax.com/www.cs.columbia.edu/~laza/html/Stewart/matlab/handEye.m
static void calibrateHandEyeTsai(const std::vector<Mat>& Hg, const std::vector<Mat>& Hc,
                                 Mat& R_cam2gripper, Mat& t_cam2gripper)
{
    //Number of unique camera position pairs
    int K = static_cast<int>((Hg.size()*Hg.size() - Hg.size()) / 2.0);
    //Will store: skew(Pgij+Pcij)
    Mat A(3*K, 3, CV_64FC1);
    //Will store: Pcij - Pgij
    Mat B(3*K, 1, CV_64FC1);

    std::vector<Mat> vec_Hgij, vec_Hcij;
    vec_Hgij.reserve(static_cast<size_t>(K));
    vec_Hcij.reserve(static_cast<size_t>(K));

    int idx = 0;
    for (size_t i = 0; i < Hg.size(); i++)
    {
        for (size_t j = i+1; j < Hg.size(); j++, idx++)
        {
            //Defines coordinate transformation from Gi to Gj
            //Hgi is from Gi (gripper) to RW (robot base)
            //Hgj is from Gj (gripper) to RW (robot base)
            Mat Hgij = homogeneousInverse(Hg[j]) * Hg[i]; //eq 6
            vec_Hgij.push_back(Hgij);
            //Rotation axis for Rgij which is the 3D rotation from gripper coordinate frame Gi to Gj
            Mat Pgij = 2*rot2quatMinimal(Hgij);

            //Defines coordinate transformation from Ci to Cj
            //Hci is from CW (calibration target) to Ci (camera)
            //Hcj is from CW (calibration target) to Cj (camera)
            Mat Hcij = Hc[j] * homogeneousInverse(Hc[i]); //eq 7
            vec_Hcij.push_back(Hcij);
            //Rotation axis for Rcij
            Mat Pcij = 2*rot2quatMinimal(Hcij);

            //Left-hand side: skew(Pgij+Pcij)
            skew(Pgij+Pcij).copyTo(A(Rect(0, idx*3, 3, 3)));
            //Right-hand side: Pcij - Pgij
            Mat diff = Pcij - Pgij;
            diff.copyTo(B(Rect(0, idx*3, 1, 3)));
        }
    }

    Mat Pcg_;
    //Rotation from camera to gripper is obtained from the set of equations:
    //    skew(Pgij+Pcij) * Pcg_ = Pcij - Pgij    (eq 12)
    solve(A, B, Pcg_, DECOMP_SVD);

    Mat Pcg_norm = Pcg_.t() * Pcg_;
    //Obtained non-unit quaternion is scaled back to unit value that
    //designates camera-gripper rotation
    Mat Pcg = 2 * Pcg_ / sqrt(1 + Pcg_norm.at<double>(0,0)); //eq 14

    Mat Rcg = quatMinimal2rot(Pcg/2.0);

    idx = 0;
    for (size_t i = 0; i < Hg.size(); i++)
    {
        for (size_t j = i+1; j < Hg.size(); j++, idx++)
        {
            //Defines coordinate transformation from Gi to Gj
            //Hgi is from Gi (gripper) to RW (robot base)
            //Hgj is from Gj (gripper) to RW (robot base)
            Mat Hgij = vec_Hgij[static_cast<size_t>(idx)];
            //Defines coordinate transformation from Ci to Cj
            //Hci is from CW (calibration target) to Ci (camera)
            //Hcj is from CW (calibration target) to Cj (camera)
            Mat Hcij = vec_Hcij[static_cast<size_t>(idx)];

            //Left-hand side: (Rgij - I)
            Mat diff = Hgij(Rect(0,0,3,3)) - Mat::eye(3,3,CV_64FC1);
            diff.copyTo(A(Rect(0, idx*3, 3, 3)));

            //Right-hand side: Rcg*Tcij - Tgij
            diff = Rcg*Hcij(Rect(3, 0, 1, 3)) - Hgij(Rect(3, 0, 1, 3));
            diff.copyTo(B(Rect(0, idx*3, 1, 3)));
        }
    }

    Mat Tcg;
    //Translation from camera to gripper is obtained from the set of equations:
    //    (Rgij - I) * Tcg = Rcg*Tcij - Tgij    (eq 15)
    solve(A, B, Tcg, DECOMP_SVD);

    R_cam2gripper = Rcg;
    t_cam2gripper = Tcg;
}
```

先算旋转,再算偏移.旋转利用每次数据间隔,追踪器与摄像机的旋转矩阵是一样的求解,而位移则是每次数据间隔其摄像机相对追踪的位置是固定的来求解.

求旋转时,skew函数需要研究下,搞清楚半四元数转的对角矩阵是什么意思[机器人手眼标定原理介绍](https://blog.csdn.net/qq_27865227/article/details/114011388).

求位移时,左边表示间隔 追踪器自身旋转*追踪器相对摄像机偏移=摄像机在追踪器下位移 - 追踪器位移.
