# 手眼标定算法改进

## 虚拟制片中的运用

在摄像机与Track绑定在一起,满足钢体关系,分别在N个不同位置下方向下,同时拍摄角点图案与记录追踪器数据,得到N组数据(一组数据包含拍摄画面与追踪器数据),根据其N组数据里的画面先得到摄像机内参,然后根据内参与画面得到摄像机在幕墙坐标系下姿态,根据手眼标定算法,在钢体关系下,N(大于4)组(摄像机在幕墙坐标系下姿态)与(追踪器在追踪器坐标下姿态),可得到(摄像机相对追踪器在追踪器空间下的4x4偏移矩阵).

在虚拟制片中,我们还需要知道(幕墙坐标系到追踪器坐标系)的4x4的转换矩阵,根据其关系有摄像机在幕墙坐标系A(4N,4)x幕墙坐标系到追踪器坐标系X(4,4)=摄像机到追踪器坐标系B(4N,4).其A表示根据N次拍摄图使用PNP得到(摄像机在幕墙坐标系的4x4矩阵).而B对应的是N次(摄像机相对追踪器偏移矩阵[手眼标定求])*(追踪器在追踪器坐标系)而得到的(摄像机到追踪器坐标系的N个4x4矩阵).这样A与B都算已知的.根据关系AxX=B,A/B都是(4N,4)的矩阵,N表示拍摄图片/记录追踪器姿态的次数,根据SVD算法求得X(幕墙坐标系到追踪器坐标系),依据SVD算法性质,其X满足N组A与B关系的最优解.

根据(摄像机相对追踪器偏移矩阵)x(追踪器在追踪器坐标系)x(追踪器坐标系到幕墙坐标系)=(摄像机在幕墙坐标系姿态).这样屏幕不需要打印角点图,也能根据(追踪器在追踪器坐标系姿态)得到(摄像机在幕墙坐标系姿态)了.

如何确定求得二个(摄像机相对追踪器偏移)(追踪器坐标系到幕墙坐标系)矩阵结果好坏?首先根据拍摄图使用PNP得到摄像机在幕墙坐标系姿态,这个我们当做真实的值,而根据(摄像机相对追踪器偏移)x(追踪器在追踪器坐标系)x(追踪器坐标系到幕墙坐标系)=(摄像机在幕墙坐标系姿态)我们得到是计算值,直接比较姿态的误差,不太好评价,故我们会把角点三维坐标通过方法cv::projectPoints映射到画面中,比较与真实角点UV在像素上的误差,这样对于人眼更直观,评价也更科学.

## 当追踪器的尺寸与现实世界不匹配

一般使用手眼标定算法,用来求解机器人上机器手臂上绑定的摄像机的相对偏移,在我们虚拟制片当中,可以用来求解绑定在追踪器上摄像机的相对偏移,如HTC Vive Tracker,他给的数据与现实的长度是匹配的,我们直接使用手眼标定算法就完成了,但是使用如Redspy红外相机跟踪系统,它给出的数据并不与现实长度匹配,比如它移动一段位移,它给出的数据是1m,但是在现实中可能对应10cm,10m,3m这些位移,手眼标定算法能否在不知道这个缩放值的情况下,求出原手眼标定的位移以及这个缩放.

## 手眼标定算法解析

我们使用opencv源码解析,可以看到默认选择使用Tsai方法,余下几种大部分和Tasi类似,使用二步法,先求得旋转,再求得位移,可以看到求旋转的过程没有用到位移数据,所以可以保证旋转不会因摄像机与追踪器位移尺寸不匹配出现问题.

我们改进的主要就是求得位移的过程,先来看下opencv手眼标定里求位移相关逻辑.

``` c++
    // 解决追踪器与摄像机使用不同尺寸问题.
    Mat A(3 * K, 3, CV_64FC1);
    // Will store: Pcij - Pgij
    Mat B(3 * K, 1, CV_64FC1);
    idx = 0;
    for (size_t i = 0; i < Hg.size(); i++)
    {
        for (size_t j = i+1; j < Hg.size(); j++, idx++)
        {
            //Defines coordinate transformation from Gi to Gj
            //Hgi is from Gi (gripper) to RW (robot base)
            //Hgj is from Gj (gripper) to RW (robot base)
            Mat Hgij = vec_Hgij[static_cast<size_t>(idx)];
            //Defines coordinate transformation from Ci to Cj
            //Hci is from CW (calibration target) to Ci (camera)
            //Hcj is from CW (calibration target) to Cj (camera)
            Mat Hcij = vec_Hcij[static_cast<size_t>(idx)];

            //Left-hand side: (Rgij - I)
            Mat diff = Hgij(Rect(0,0,3,3)) - Mat::eye(3,3,CV_64FC1);
            diff.copyTo(A(Rect(0, idx*3, 3, 3)));

            //Right-hand side: Rcg*Tcij - Tgij
            diff = Rcg*Hcij(Rect(3, 0, 1, 3)) - Hgij(Rect(3, 0, 1, 3));
            diff.copyTo(B(Rect(0, idx*3, 1, 3)));
        }
    }

    Mat Tcg;
    //Translation from camera to gripper is obtained from the set of equations:
    //    (Rgij - I) * Tcg = Rcg*Tcij - Tgij    (eq 15)
    solve(A, B, Tcg, DECOMP_SVD);
```

利用等式

$$ (Rgij - I) * Tcg = Rcg*Tcij - Tgij $$

其中Rgij表示标定记录中二次记录之间追踪器空间下追踪器之间的旋转,根据记录是已知量.I表示3x3的单位矩阵,是固定量.Tcg表示追踪器空间下,摄像机相对追踪器的位移偏移,也就是我们要求解的值.Rcg表示追踪器空间下,摄像机相对追踪器的旋转偏移.Tcij 表示标定记录中二次记录之间摄像机空间下标定板之间的旋转,根据记录是已知量.Tgij 表示标定记录中二次记录之间追踪器空间下追踪器之间的位移,根据记录是已知量.

$$ (Rgij - I) * Tcg - Rcg*Tcij*Scale = -Tgij $$

原来矩阵算式如下.

$$\begin{bmatrix}
A_{00}&A_{01}&A_{02}\\
A_{10}&A_{11}&A_{12}\\
A_{20}&A_{21}&A_{22}\\
\end{bmatrix} * \begin{bmatrix}
T_{0}\\
T_{1}\\
T_{2}\\
\end{bmatrix} = \begin{bmatrix}
B_{0}\\
B_{1}\\
B_{2}\\
\end{bmatrix}
$$

现在变换后,矩阵算式如下.

$$\begin{bmatrix}
A_{00}&A_{01}&A_{02}&C_{03}\\
A_{10}&A_{11}&A_{12}&C_{13}\\
A_{20}&A_{21}&A_{22}&C_{23}\\
\end{bmatrix} * \begin{bmatrix}
T_{0}\\
T_{1}\\
T_{2}\\
S_{3}\\
\end{bmatrix} = \begin{bmatrix}
B_{0}\\
B_{1}\\
B_{2}\\
\end{bmatrix}
$$

其中新变换里的C表示- Rcg*Tcij,这样就把缩放参数带入要求解的[T0,T1,T2,S3]中的S3里面,新的代码如下.

```c++
    // 解决追踪器与摄像机使用不同尺寸问题.
    Mat TA(3 * K, 4, CV_64FC1);
    // Will store: Pcij - Pgij
    Mat TB(3 * K, 1, CV_64FC1);
    idx = 0;
    for (size_t i = 0; i < Hg.size(); i++) {
        for (size_t j = i + 1; j < Hg.size(); j++, idx++) {
            // Defines coordinate transformation from Gi to Gj
            // Hgi is from Gi (gripper) to RW (robot base)
            // Hgj is from Gj (gripper) to RW (robot base)
            Mat Hgij = vec_Hgij[static_cast<size_t>(idx)];
            // Defines coordinate transformation from Ci to Cj
            // Hci is from CW (calibration target) to Ci (camera)
            // Hcj is from CW (calibration target) to Cj (camera)
            Mat Hcij = vec_Hcij[static_cast<size_t>(idx)];

            // Left-hand side:3x3_(Rgij - I) 3x1_(Rcg*Tcij)
            Mat ldiff1 = Hgij(Rect(0, 0, 3, 3)) - Mat::eye(3, 3, CV_64FC1);
            ldiff1.copyTo(TA(Rect(0, idx * 3, 3, 3)));
            Mat ldiff2 = -(Rcg * Hcij(Rect(3, 0, 1, 3)));
            ldiff2.copyTo(TA(Rect(3, idx * 3, 1, 3)));

            // Right-hand side: -Tgij
            Mat diff = -Hgij(Rect(3, 0, 1, 3));
            diff.copyTo(TB(Rect(0, idx * 3, 1, 3)));
        }
    }
    Mat Tcg;
    solve(TA, TB, Tcg, DECOMP_SVD);
```

## 变换详细说明

因为(Rgij-I) * Tcg与Tgij是追踪器系下位移,而Rcg*Tcij是摄像机(现实世界)位移,假定现实世界相对追踪器坐标系下缩放是scale,那么满足如下关系.

$$ (Rgij-I)*Tcg=Rcg*Tcij*Scale-Tgij $$

要求解Tcg(3x1)与Scale,满足如下求解方程 Ax=b,求解x,把如上方程变形为:

$$ (Rgij-I)*Tcg-Rcg*Tcij*Scale=-Tgij $$

Rcg在前面已求得,I表示(3x3)单位矩阵,故简化如下:

$$  Rxij*Tcg-Txij*Scale=-Tgij $$

其Rxij[3x3],Tcg[3x1],Txij[3x1],Scale[1x1],Tgij[3x1].组合Rxji与Txij,Tcg与Scale.

$$\begin{bmatrix}
A_{00}&A_{01}&A_{02}&C_{03}\\
A_{10}&A_{11}&A_{12}&C_{13}\\
A_{20}&A_{21}&A_{22}&C_{23}\\
\end{bmatrix} * \begin{bmatrix}
T_{0}\\
T_{1}\\
T_{2}\\
S_{3}\\
\end{bmatrix} = \begin{bmatrix}
B_{0}\\
B_{1}\\
B_{2}\\
\end{bmatrix}
$$

其A00-A22表示Rxji,其C03-C23 表示Txij,其T0-T2 表示Tcg,S3表示scale.矩阵展开所表示就是原来Rxij * Tcg - Txij * Scale=-Tgij.并满足Ax=b的等式.求解得到x.这个x表示是K条记录中,Ax=b的最优解,类似([A1x-b1]+[A2x-b2]+...+[Akx-bk])/k的最少值,应该是平方根的最少值.

其求得的4*1前面三个表示Tcg(摄像机相对追踪器的位移),最后数据表示现实世界相对追踪器坐标系下缩放是scale.
