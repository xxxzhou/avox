# 推拉流验证测试界面设计文档

## 1. 界面概述

设计一个适配移动端布局的推拉流验证测试界面，用于测试播放器的拉流和推流功能。界面采用垂直长布局，默认分为上下两部分，分别对应拉流和推流功能区域。

## 2. 布局设计

### 2.1 整体布局

- **布局方向**：垂直布局
- **默认状态**：拉流界面和推流界面各占50%高度
- **展开状态**：点击展开按钮后，对应界面占据全屏高度
- **适配设备**：主要针对移动端设备，支持触摸操作
- **响应式设计**：适配不同屏幕尺寸

### 2.2 拉流界面

| 组件 | 位置 | 功能描述 |
|------|------|----------|
| AvRenderView | 顶部 | 显示拉流视频画面 |
| 文本输入框 | 中间 | 输入拉流地址（支持RTSP、RTMP、HTTP等协议） |
| 功能按钮组 | 底部 | 包含以下按钮：<br>- 软/硬解切换<br>- IO模式切换（FFmpeg/ZLMediaKit）<br>- 截图<br>- 展开/收起 |

### 2.3 推流界面

| 组件 | 位置 | 功能描述 |
|------|------|----------|
| AvRenderView | 顶部 | 显示推流预览画面 |
| 文本输入框 | 中间 | 输入推流地址（支持RTMP等协议） |
| 功能按钮组 | 底部 | 包含以下按钮：<br>- 软/硬编切换<br>- IO模式切换（FFmpeg/ZLMediaKit）<br>- 开始/停止推流<br>- 展开/收起 |

## 3. 核心功能

### 3.1 拉流功能

- **地址输入**：支持手动输入拉流地址
- **播放控制**：开始/停止拉流
- **解码模式**：支持软解码和硬解码切换
- **IO模式**：支持FFmpeg和ZLMediaKit两种IO模式
- **截图功能**：捕获当前视频画面并保存
- **画面显示**：通过AvRenderView显示视频画面
- **状态显示**：显示当前拉流状态、码率、延迟等信息

### 3.2 推流功能

- **地址输入**：支持手动输入推流地址
- **推流控制**：开始/停止推流
- **编码模式**：支持软编码和硬编码切换
- **IO模式**：支持FFmpeg和ZLMediaKit两种IO模式
- **画面预览**：通过AvRenderView显示推流预览画面
- **状态显示**：显示当前推流状态、码率、延迟等信息

### 3.3 界面控制

- **展开/收起**：点击展开按钮后，对应界面占据全屏
- **布局切换**：支持默认分屏和全屏模式切换
- **状态保存**：保存用户的设置和偏好

## 4. 技术实现

### 4.1 界面组件

- **主界面**：`StreamTestView.axaml` - 主容器，管理拉流和推流界面的布局
- **拉流界面**：`PullStreamView.axaml` - 拉流功能界面
- **推流界面**：`PushStreamView.axaml` - 推流功能界面
- **控制按钮**：使用Avalonia的Button控件
- **输入框**：使用Avalonia的TextBox控件
- **视频渲染**：使用AvRenderView控件

### 4.2 核心类设计

#### StreamTestView
- **职责**：管理整体布局和界面状态
- **属性**：
  - `IsPullStreamExpanded`：拉流界面是否展开
  - `IsPushStreamExpanded`：推流界面是否展开
- **方法**：
  - `TogglePullStreamExpand()`：切换拉流界面展开状态
  - `TogglePushStreamExpand()`：切换推流界面展开状态

#### PullStreamView
- **职责**：实现拉流功能
- **属性**：
  - `PullStreamUrl`：拉流地址
  - `IsHardwareDecoding`：是否启用硬解码
  - `CurrentIOMode`：当前IO模式
- **方法**：
  - `StartPullStream()`：开始拉流
  - `StopPullStream()`：停止拉流
  - `ToggleDecodingMode()`：切换解码模式
  - `ToggleIOMode()`：切换IO模式
  - `TakeScreenshot()`：截图

#### PushStreamView
- **职责**：实现推流功能
- **属性**：
  - `PushStreamUrl`：推流地址
  - `IsHardwareEncoding`：是否启用硬编码
  - `CurrentIOMode`：当前IO模式
- **方法**：
  - `StartPushStream()`：开始推流
  - `StopPushStream()`：停止推流
  - `ToggleEncodingMode()`：切换编码模式
  - `ToggleIOMode()`：切换IO模式

### 4.3 布局实现

```xml
<!-- StreamTestView.axaml -->
<UserControl xmlns="https://github.com/avaloniaui"
             xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
             xmlns:controls="clr-namespace:AvoxControls"
             x:Class="AvoxControls.StreamTestView">
    <Grid RowDefinitions="{Binding RowDefinitions}" Background="#F0F0F0">
        <!-- 拉流界面 -->
        <controls:PullStreamView x:Name="PullStreamView"
                                Grid.Row="0"
                                Margin="10"
                                OnExpandRequested="{Binding TogglePullStreamExpand}" />
        
        <!-- 推流界面 -->
        <controls:PushStreamView x:Name="PushStreamView"
                                Grid.Row="1"
                                Margin="10"
                                OnExpandRequested="{Binding TogglePushStreamExpand}" />
    </Grid>
</UserControl>
```

## 5. 功能实现

### 5.1 拉流功能

1. **拉流地址输入**：
   - 支持手动输入RTSP、RTMP、HTTP等协议的拉流地址
   - 支持从历史记录中选择常用地址

2. **解码模式切换**：
   - 软解码：使用CPU进行解码，兼容性好
   - 硬解码：使用GPU进行解码，性能更好
   - 通过ConfigManager实现模式切换

3. **IO模式切换**：
   - FFmpeg IO：使用FFmpeg作为IO层
   - ZLMediaKit IO：使用ZLMediaKit作为IO层
   - 通过ConfigManager实现模式切换

4. **截图功能**：
   - 捕获当前视频画面
   - 保存为图片文件
   - 显示截图成功提示

5. **状态管理**：
   - 显示拉流状态（准备中、播放中、暂停、错误）
   - 显示当前码率、延迟等信息
   - 错误处理和提示

### 5.2 推流功能

1. **推流地址输入**：
   - 支持手动输入RTMP等协议的推流地址
   - 支持从历史记录中选择常用地址

2. **编码模式切换**：
   - 软编码：使用CPU进行编码，兼容性好
   - 硬编码：使用GPU进行编码，性能更好
   - 通过ConfigManager实现模式切换

3. **IO模式切换**：
   - FFmpeg IO：使用FFmpeg作为IO层
   - ZLMediaKit IO：使用ZLMediaKit作为IO层
   - 通过ConfigManager实现模式切换

4. **推流控制**：
   - 开始推流：启动推流功能
   - 停止推流：停止推流功能
   - 推流状态显示和错误处理

5. **预览功能**：
   - 推流前显示摄像头预览
   - 调整摄像头参数（如分辨率、帧率）

### 5.3 界面控制

1. **展开/收起功能**：
   - 点击展开按钮，对应界面占据全屏
   - 点击收起按钮，恢复默认分屏状态
   - 通过RowDefinitions动态调整布局

2. **状态保存**：
   - 保存用户设置的推流/拉流地址
   - 保存解码/编码模式设置
   - 保存IO模式设置
   - 通过ConfigManager实现设置持久化

## 9. 性能优化

1. **内存管理**：
   - 合理管理AvRenderView的生命周期
   - 避免内存泄漏

2. **UI响应**：
   - 使用异步操作处理耗时任务
   - 避免UI线程阻塞

3. **电池优化**：
   - 在推流时合理控制编码参数
   - 避免不必要的后台操作

## 10. 总结

本设计文档提供了一个完整的推拉流验证测试界面方案，适用于移动端设备，支持拉流和推流功能的测试。界面采用垂直布局，默认分为上下两部分，可展开为全屏模式，操作便捷直观。通过此界面，用户可以方便地测试不同编码解码模式、IO模式下的推拉流性能，为播放器的功能验证提供有力支持。
